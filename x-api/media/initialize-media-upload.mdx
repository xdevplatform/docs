openapi: post /2/media/upload/initialize

Start a chunked upload session. Send a JSON body with `media_type`, `total_bytes`, and `media_category`. Do not send `command=INIT` to `POST /2/media/upload`.

## Size and duration limits

`total_bytes` may be at most 16 GB in the request schema. The session is then capped by the **authenticated user's** X Premium / verified status and by `media_category`:

| Account | Category | Max duration | Max file size |
| :--- | :--- | :--- | :--- |
| Default | `tweet_video`, `amplify_video` | 20 minutes | 8 GB |
| X Premium / verified | `tweet_video`, `amplify_video` | 125 minutes | 16 GB |
| Default | `dm_video` | 140 seconds | 512 MB |
| X Premium / verified | `dm_video` | 10 minutes | 1 GB |
| Any | `tweet_image`, `dm_image` | — | 5 MB |
| Any | `tweet_gif`, `dm_gif` | — | 15 MB |

Minimum video duration is 0.5 seconds. Use `tweet_video` for a regular Post and `amplify_video` for Ads creatives. Post-video caps are the same for both categories.

A successful initialize does not mean the file can be attached to a Post. [`POST /2/tweets`](/x-api/posts/create-post) re-checks duration and returns **403** if the video is longer than that user is allowed to post.

See [size and duration limits](/x-api/media/introduction#size-and-duration-limits) and the [chunked upload quickstart](/x-api/media/quickstart/media-upload-chunked).
