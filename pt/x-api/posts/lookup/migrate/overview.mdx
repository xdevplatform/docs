## Comparando os endpoints de Posts lookup da X API

Os endpoints de Posts lookup da v2 substituem os endpoints standard v1.1 [GET statuses/lookup](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-lookup) e [GET statuses/show](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-show-id). Este guia é para desenvolvedores que estão migrando dessas versões mais antigas para a X API v2.

## Tabela de comparação de endpoints

| Descrição | Standard v1.1 | X API v2 |
|:-------------|:---------------|:----------|
| **Métodos HTTP suportados** | `GET` | `GET` |
| **Domínio do host** | `https://api.x.com` | `https://api.x.com` |
| **Caminho do endpoint** | `/1.1/statuses/show.json`, `/1.1/statuses/lookup.json` | `/2/tweets` |
| **[Autenticação](resources/fundamentals/authentication)** | OAuth 1.0a User Context | OAuth 1.0a User Context, OAuth 2.0 App-Only, OAuth 2.0 Authorization Code com PKCE |
| **[Formato JSON](/x-api/fundamentals/data-dictionary) do Post** | Formato Standard v1.1 | [Formato X API v2](/x-api/fundamentals/data-dictionary), determinado pelos parâmetros `fields` e `expansions` (não compatível com versões anteriores do v1.1) |
| **Suporta seleção de [fields](/x-api/fundamentals/data-dictionary) específicos** |  | ✔ |
| **Suporta os fields de [annotations](/x-api/fundamentals/post-annotations)** |  | ✔ |
| **Suporta novos fields de [metrics](/x-api/fundamentals/metrics)** |  | ✔ |
| **Suporta o field `conversation_id`** |  | ✔ |
| **Fornece histórico de edições de Post** | ✔ | ✔ |
| **Requer credenciais de um [App de desenvolvedor](/fundamentals/developer-apps) associado a um Project** |  | ✔ |

## Standard v1.1 em comparação com a X API v2

Se você tem trabalhado com o standard v1.1 GET statuses/show e GET statuses/lookup, este guia ajudará você a entender as similaridades e diferenças entre os endpoints de Posts lookup do standard e da X API v2.

Você também pode se interessar pela nossa [ferramenta visual de migração de formato de dados](/x-api/migrate/data-format-migration) para ajudar a ver rapidamente as diferenças entre o [formato de dados da X API v1.1](/x-api/fundamentals/data-dictionary) e o [formato da X API v2](/x-api/fundamentals/data-dictionary).

- **Similaridades**
  - OAuth 1.0a User Context
  - Limites de Posts por requisição
  - Suporte para histórico de edições e metadados de Post

- **Diferenças**
  - URLs dos endpoints
  - Requisitos de App e Project
  - Formato dos dados de resposta
  - Parâmetros de requisição

### Similaridades

#### Método de autenticação OAuth 1.0a User Context

O endpoint standard suporta [OAuth 1.0a User Context](/resources/fundamentals/authentication), enquanto o novo endpoint de Post lookup da X API v2 suporta tanto OAuth 1.0a User Context quanto [OAuth 2.0 App-Only](/resources/fundamentals/authentication). Portanto, se você estava anteriormente usando um dos endpoints standard v1.1 de Post lookup, você pode continuar usando o mesmo método de autenticação se migrar para a versão X API v2.

A autenticação App-Only provavelmente é a maneira mais fácil de começar. Para saber como gerar um App Access Token, consulte [este guia de OAuth 2.0 App-only](/resources/fundamentals/authentication).

#### Limites de Posts por requisição

O endpoint v1.1 [GET statuses/lookup](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-lookup) permite especificar até 100 Posts por requisição. Isso também se aplica ao endpoint GET /tweets. Para especificar 100 Posts completos, use o parâmetro `ids` como um query parameter com uma lista separada por vírgulas de [IDs de Post](/resources/fundamentals/x-ids).

**Suporte para histórico de edições e metadados de Post**

Ambas as versões fornecem metadados que descrevem qualquer histórico de edições. Confira as Referências da API de Post lookup e a [página de fundamentos de edição de Posts](/x-api/fundamentals/edit-posts) para mais detalhes.

### Diferenças

#### URLs dos endpoints

- **Endpoints standard v1.1:**
  - `https://api.x.com/1.1/statuses/show`
  - `https://api.x.com/1.1/statuses/lookup`
  
- **Endpoint da X API v2:**
  - `https://api.x.com/2/tweets`
  - `https://api.x.com/2/tweets/:id`

#### Requisitos de App e Project

Os endpoints da X API v2 exigem credenciais de um [App de desenvolvedor](/resources/fundamentals/developer-apps) associado a um [Project](/resources/fundamentals/developer-apps) para autenticação. Os endpoints da X API v1.1 podem usar credenciais de Apps ou Apps associados a um App.

#### Formato dos dados de resposta

Uma diferença significativa entre as versões dos endpoints standard v1.1 e X API v2 é como os fields são selecionados no payload.

Para endpoints standard, muitos fields de resposta são incluídos por padrão, com opções de usar parâmetros para especificar fields adicionais.

A X API v2, no entanto, entrega apenas os fields `id` e `text` do Post por padrão. Fields e objetos adicionais exigem o uso dos parâmetros [fields](/x-api/fundamentals/fields) e [expansions](/x-api/fundamentals/expansions). Os fields expandidos retornam em um objeto `includes` dentro da resposta, que pode ser associado ao objeto Post primário fazendo a correspondência dos IDs.

Para mais informações sobre como usar fields e expansions, consulte o [guia sobre como usar fields e expansions](/x-api/fundamentals/data-dictionary). Um [guia de migração de formato de dados](/x-api/fundamentals/fields) também mapeia os fields do standard v1.1 para os fields mais novos da v2.

Além disso, a X API v2 introduz novos designs JSON para objetos, incluindo os objetos Post e [user](/x-api/fundamentals/fields):

- Endpoints standard retornam objetos Post em um array `statuses`, enquanto a X API v2 usa um array `data`.
- Retweeted e Quoted Tweets na X API v2 substituem a terminologia "statuses".
- Nova terminologia como `like` substitui termos como `favorites` e `favourites`.
- Atributos sem valores (ex.: `null`) não são incluídos nos payloads da X API v2.

O objeto Post na X API v2 inclui novos fields como:
- `conversation_id`
- Dois novos fields de [annotations](/x-api/fundamentals/post-annotations) (`context` e `entities`)
- Novos fields de [metrics](/x-api/fundamentals/metrics)
- Field `reply_setting` mostrando quem pode responder a um determinado Post

#### Parâmetros de requisição

Os seguintes parâmetros de requisição do standard v1.1 têm equivalentes na X API v2:

| Standard | X API v2 |
|:----------|:----------|
| `id`     | `ids`    |

Certos parâmetros do standard v1.1 **não** são suportados na X API v2:

| Standard            | Comentário                                                                                                                      |
|:---------------------|:------------------------------------------------------------------------------------------------------------------------------|
| `tweet_mode`        | Substituído pela funcionalidade de fields e expansions.                                                                             |
| `trim_user`         | Substituído por fields e expansions. Use a expansion `author_id` e `user.fields` para dados de usuário.                               |
| `include_my_retweet`| Fornece o ID do Post de origem para Posts Retweetados pelo usuário autenticador.                                          |
| `include_entities`  | Use fields e expansions para controlar entities no payload.                                                               |
| `include_ext_alt_text` | Adiciona o field `ext_alt_text` na entity de mídia se o texto alternativo estiver presente.                                                         |
| `include_card_uri`  | Adiciona `card_uri` quando um ads card estiver anexado.                                                                               |
| `map`               | Retorna o Post ID e a mensagem de erro para Posts indisponíveis na X API v2, ao contrário dos fields anulados na v1.1.            |

### Requisições cURL

As requisições cURL a seguir mostram endpoints do standard v1.1 e seus equivalentes na v2. Substitua `ACCESS_TOKEN` no header pelo access token do seu app. Para endpoints v2, o token deve pertencer a um [App de desenvolvedor](/fundamentals/developer-apps) dentro de um Project.

Os payloads de resposta da v1.1 diferem dos da v2. Com a v2, você pode solicitar fields diferentes com os parâmetros [fields](/x-api/fundamentals/fields) e [expansions](/x-api/fundamentals/expansions).

**Endpoints standard v1.1 `GET statuses/lookup` e v2 `GET /tweets`**

```bash
curl --request GET \
  --url 'https://api.x.com/1.1/statuses/lookup.json?id=1460323737035677698%2C1460323743339741184' \
  --header 'Authorization: Bearer $ACCESS_TOKEN'
```

```bash
curl --request GET \
  --url 'https://api.x.com/2/tweets?ids=1460323737035677698%2C1460323743339741184&tweet.fields=created_at&expansions=author_id&user.fields=created_at' \
  --header 'Authorization: Bearer $ACCESS_TOKEN'
```


**Endpoints standard v1.1 `GET statuses/show/:id` e v2 `GET /tweets/:id`**
```bash
curl --request GET \
  --url 'https://api.x.com/1.1/statuses/show.json?id=1460323737035677698' \
  --header 'Authorization: Bearer $ACCESS_TOKEN'
```

```bash
curl --request GET \
  --url 'https://api.x.com/2/tweets/1460323737035677698?tweet.fields=created_at&expansions=author_id&user.fields=created_at' \
  --header 'Authorization: Bearer $ACCESS_TOKEN'
```
