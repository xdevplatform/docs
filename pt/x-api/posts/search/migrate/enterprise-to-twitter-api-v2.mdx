### Enterprise em comparação com a X API v2


**Similaridades**

* Paginação
* Fuso horário
* Suporte para histórico de edições e metadados de Post. 

**Diferenças**

* URLs dos endpoints
* Requisito de App e Project
* Períodos de tempo disponíveis
* Formato dos dados de resposta
* Métodos HTTP
* Formatos de tempo da requisição
* Parâmetros de requisição
* Operadores de filtragem


#### Similaridades

**Paginação**

Embora a v2 tenha recursos adicionais de paginação (novos parâmetros de paginação que permitem navegar usando IDs de Post com `since_id` e `until_id`), tanto a enterprise quanto a v2 permitem paginar usando tempo (`fromDate` e `toDate` na enterprise, e `start_time` e `end_time` na v2).


**Fuso horário**

Como observado na seção de paginação, você pode navegar por diferentes páginas de dados usando tempo tanto na enterprise quanto na v2. Em ambos os casos, você usará UTC como fuso horário ao utilizar esses parâmetros.

**Suporte para histórico de edições e metadados de Post**

Ambas as versões fornecem metadados que descrevem qualquer histórico de edições. Confira as [Referências da Search API](/x-api/posts/recent-search) e a [página de fundamentos de edições de Post](/x-api/fundamentals/edit-posts) para mais detalhes.

#### Diferenças

**URLs dos endpoints**

* Endpoints enterprise:
    * 30 dias - `http://gnip-api.x.com/search/30day/accounts/:account_name/:label.json`
    * Full-archive - `http://gnip-api.x.com/search/fullarchive/accounts/:account_name/:label.json`
* Endpoints da X API v2
    * Recent (7 dias) - `https://api.x.com/2/tweets/search/recent`
    * Full-archive - `https://api.x.com/2/tweets/search/all`

**Requisito de App e Project**

Os endpoints da X API v2 exigem que você use credenciais de um Project ao autenticar suas requisições. Todos os endpoints da X API v1.1 podem usar credenciais de Apps ou Apps associados a um App.
