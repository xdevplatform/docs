### Standard v1.1 em comparação com a X API v2

Se você tem trabalhado com o v1.1 [search/posts](/x-api/posts/search/introduction), o objetivo deste guia é ajudar você a entender as similaridades e diferenças entre o endpoint de search Posts do standard e da X API v2.

* **Similaridades**
    * OAuth 1.0a User Context e OAuth 2.0 App-Only
    * Suporte para histórico de edições e metadados de Post. 
* **Diferenças**
    * URLs dos endpoints
    * Requisitos de App e Project
    * Formato dos dados de resposta
    * Parâmetros de requisição
    * Novos operadores de query

    * Precedência dos operadores AND / OR 

#### Similaridades

**Autenticação OAuth 1.0a User Context e OAuth 2.0 App-Only**

O v1.1 search/posts e o endpoint recent search da X API v2 suportam tanto [OAuth 1.0a User Context](/resources/fundamentals/authentication) quanto [OAuth 2.0 App-Only](/resources/fundamentals/authentication#oauth-2-0).

Portanto, se você estava anteriormente usando o endpoint standard v1.1 search, pode continuar usando o mesmo método de autenticação se migrar para a versão X API v2.

Dependendo da sua biblioteca/pacote de autenticação de escolha, a autenticação App-Only provavelmente é a maneira mais fácil de começar e pode ser definida com um simples header de requisição. Para saber como gerar um App Access Token, consulte este [guia de OAuth 2.0 App-Only](/resources/fundamentals/authentication#bearer-token-also-known-as-app-only).

Se você quiser aproveitar a capacidade de obter métricas privadas ou de publicidade com o endpoint da X API v2, precisará usar OAuth 1.0a User Context e passar os user access tokens relacionados ao usuário que publicou o Post cujas métricas você deseja obter.


**Suporte para histórico de edições e metadados de Post**

Ambas as versões fornecem metadados que descrevem qualquer histórico de edições. Confira as [Referências da Search API](/x-api/posts/recent-search) e a [página de fundamentos de edições de Post](/x-api/fundamentals/edit-posts) para mais detalhes.
