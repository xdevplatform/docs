### Migração da PowerTrack API para o filtered stream da X API v2

Use este guia de migração para entender as similaridades e diferenças entre a [PowerTrack API](/x-api/enterprise-gnip-2.0/powertrack-api) e o [filtered stream](/x-api/posts/filtered-stream) da X API v2 e para ajudar a migrar uma integração atual da PowerTrack API para o filtered stream v2.

* **Similaridades**
    * Método de entrega por streaming
    * Processo de integração
    * Conexão de stream persistente com endpoints de gerenciamento de regras separados
    * Sintaxe de regra
    * Operadores de regra (com exceções)
    * Lógica de correspondência de regras
    * Suporte para histórico de edições e metadados de Post
* **Diferenças**
    * Tamanho da regra
    * Volume de regras
    * URLs dos endpoints
    * Requisito de App e Project para acesso
    * Método de autenticação
    * Parâmetros de requisição
    * Rastreamento de uso
    * Múltiplos streams, conexões redundantes, backfill e recuperação com Replay
    * Parâmetros de requisição e formato de resposta
    * Estrutura de dados JSON da resposta

#### Similaridades

**Método de entrega por streaming**

Tanto o PowerTrack quanto o filtered stream da X API v2 usam entrega de dados por streaming, que requer que o cliente estabeleça uma conexão aberta com um endpoint e mantenha uma requisição HTTP de longa duração, analisando a resposta incrementalmente vinda do servidor em tempo real. Tanto o PowerTrack quanto o filtered stream da X API v2 filtram Posts publicamente disponíveis que correspondem às regras que existem no stream em tempo real, e usam sinais keep-alive como caracteres de nova linha (\\r\\n) para sinalizar que a conexão ainda está ativa. Tanto o PowerTrack quanto as conexões do endpoint de filtered stream da X API v2 entregam dados em tempo real e devem ser lidas rapidamente pelo cliente conectado.
