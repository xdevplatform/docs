### Correspondendo Posts retornados à sua regra associada

O endpoint do filtered stream permite ter múltiplas regras ativas por meio de uma única conexão. Antes de começar a receber Posts em seu stream, você precisará criar uma regra que especifica os tipos de Posts que lhe interessam.

Ao especificar suas regras para corresponder a Posts com base em uma ampla variedade de atributos, incluindo atributos do usuário, geolocalização, idioma e muitos outros, você pode anexar uma tag para distinguir essa regra em um nível mais alto. Tags são uma boa maneira de contextualizar sua regra, especialmente se você tiver muitas regras ativas. As regras de filtragem determinam quais atividades de Post serão enviadas por meio da conexão.

Se você precisar adicionar uma nova regra de filtragem para capturar um tipo diferente de Post, ou remover uma regra existente, seu app pode enviar uma requisição ao endpoint [POST tweets/search/stream/rules](/x-api/stream/update-stream-rules) para fazer isso. Quando essa requisição é enviada, as regras de filtragem são automaticamente modificadas e as mudanças simplesmente entram em vigor no stream de dados sem necessidade de reconexão. A maioria das adições de regra entra em vigor em cerca de 20 segundos ou menos. É improvável, mas dependendo de fatores externos (por exemplo, conectividade de rede), pode demorar mais até você começar a receber Posts correspondentes. Se você não encontrar uma regra no endpoint de listagem de regras, verifique se a requisição de criação foi bem-sucedida; isso pode ser feito checando seus logs em busca de mensagens de erro.


#### Regras correspondentes

Quando uma atividade é entregue por meio da sua conexão do filtered stream, em um array matching_rules, ela contém a lista de filtros que corresponderam ao Post entregue.

No payload do Post há metadados de string adicionais que incluem o rule id e a tag que fizeram um Post específico ser entregue. Se múltiplas regras correspondem a um único Post, a atividade é entregue uma única vez com cada uma das regras correspondentes incluída nesses metadados. As regras correspondentes fornecem uma maneira fácil de associar um Post específico a regras específicas, o que é especialmente útil se você tiver muitas regras distintas. Como os dados são entregues por meio de um único stream dessa forma, garantir que você tenha id e tag únicos é essencial para a correspondência.

**Aqui está um exemplo de como o array "matching_rules" aparece no payload do Post:**


```json
"matching_rules": [
    {
      "id": "1166916266197536768",
      "tag": "test-rule-tag-00000"
    },
    {
      "id": "1166916266197536769",
      "tag": "test-rule-tag-12345"
    }
  ]
```

#### Correspondências de regras de embedding

Quando um Post corresponde a uma regra que contém o operador `embedding:`, a entrada `matching_rules` para essa regra inclui dois campos adicionais (presentes apenas para correspondências baseadas em embedding):

| Campo | Descrição |
|:------|:------------|
| `embedding_similarity` | A pontuação de similaridade de cosseno (0.0–1.0) entre a query da regra e o Post correspondente. |
| `embedding_threshold` | O threshold aplicado (seu valor ou o padrão `0.3`). |

Exemplo de trecho de payload para uma correspondência de embedding:

```json title="Exemplo de resposta" lines wrap icon="/icons/xds/icon-brackets.svg"
{
  "data": {
    "id": "1784600000000000001",
    "text": "The new carbon tax proposal could reshape how industries approach emissions..."
  },
  "matching_rules": [
    {
      "id": "1784567890123456789",
      "tag": "climate-semantic",
      "embedding_similarity": 0.4523,
      "embedding_threshold": 0.4
    }
  ]
}
```

Para regras de keyword, `from:`, `has:` e outras regras que não sejam de embedding, as entradas `matching_rules` contêm apenas `id` e `tag`.

#### Tags de regra

No momento em que são criadas, cada regra de filtragem pode ser criada com uma tag. Tags de regra não têm significado especial, pois são simplesmente tratadas como strings opacas acompanhando a regra. Elas serão incluídas nos metadados matching_rules nas atividades retornadas e visam facilitar a distinção das suas regras em um nível mais alto.

Tags fornecem uma maneira fácil de criar agrupamentos lógicos de regras de filtragem. Por exemplo, você pode gerar um ID único para uma regra específica como sua tag e permitir que seu app faça referência a esse ID dentro das atividades que processa para associar um resultado a clientes, campanhas, categorias ou outros grupos relacionados específicos.

Observe que tags não podem ser atualizadas em uma regra existente e só podem ser incluídas quando uma regra é criada. Para "atualizar" ou "renomear" uma tag, você precisa primeiro excluir a regra e então adicioná-la novamente com a tag desejada. A melhor solução é simplesmente usar um identificador único como sua tag, que seu sistema pode associar a vários outros pontos de dados dentro do seu próprio app, tudo sem precisar alterar nada no conjunto de regras.
