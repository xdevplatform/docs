### Gerenciar replies por tópico

Por meio do endpoint hide replies, você pode criar integrações para ajudar pessoas e marcas a manter a conversa no tópico. Esta página mostra como gerenciar uma conversa usando os endpoints hide replies e [recent search](/x-api/posts/recent-search).

O recent search tem funcionalidade para uma conversa e suas replies, e o payload do Post retorna [Post annotations](/x-api/fundamentals/post-annotations) para ajudar você a entender o contexto e o tópico de cada Post, independentemente do idioma.

O fluxo do app terá controles para exibir e gerenciar uma conversa:

1.  Ele pede permissão ao usuário para ler seus Posts e gerenciar suas replies.
2.  Ele obtém uma conversa recente a partir de uma URL de Post e verifica se a conversa é do usuário autenticado.
3.  Ele chamará o endpoint recent search para exibir cada Post na conversa. A requisição incluirá uma query de busca por conversation ID e a expansion de annotation para determinar se o Post é relacionado a esportes ou não, de acordo com a interpretação do X sobre o Post.
4.  Ele chama o Hide replies para ocultar uma reply quando o usuário escolher fazê-lo. Ele também fornecerá uma maneira de desfazer essa ação para que o usuário sempre esteja no controle.

5.  Para conversas mais longas, ele fornecerá controles para [paginar os resultados de busca](/x-api/posts/search/integrate/paginate).
     

#### Otimize para o usuário (e para o uso)

Você pode projetar um fluxo de forma que coloque o usuário no controle de qualquer ação que ele pretenda realizar. Manter este princípio em mente também ajuda você a construir uma integração que pode otimizar o consumo de Posts.

1.  Como o usuário autenticado só pode gerenciar conversas que ele iniciou, seu fluxo deve terminar cedo quando esse não for o caso.
    * Faça uma requisição inicial de Post lookup. Encerre o fluxo cedo se a URL do Post não for válida ou se a conversa não foi iniciada pelo usuário autenticado.
    * Dessa forma, seu app não precisa fazer uma requisição de recent search se a conversa não puder ser moderada pelo usuário autenticado.
2.  Solicite [fields de usuário e de Post](/x-api/fundamentals/fields) na mesma requisição para evitar fazer requisições separadas. Esta abordagem também pode melhorar o desempenho do seu app.
3.  Evite fazer requisições quando necessário. Este app armazena em cache no navegador do usuário o status oculto de uma reply. Isso é útil para conversas maiores, onde o usuário pode querer retomar seus esforços de moderação em um estágio posterior, e ajuda seu app a otimizar as requisições para ocultar ou reexibir replies.
