## Standard v1.1 em comparação com a X API v2

Se você tem trabalhado com os endpoints standard v1.1 [POST statuses/update](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/post-statuses-update) e [POST statuses/destroy/:id](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/post-statuses-destroy-id), o objetivo deste guia é ajudar você a entender as similaridades e diferenças entre os endpoints de gerenciar Posts do standard e da X API v2.

* **Similaridades**
    * Autenticação
* **Diferenças**
    * URLs dos endpoints
    * Requisitos de App e Project

    * Parâmetros de requisição


### Similaridades

**Autenticação**

Tanto os endpoints standard v1.1 quanto os endpoints de gerenciar Posts da X API v2 ([POST statuses/update](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/post-statuses-update) e [POST statuses/destroy/:id](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/post-statuses-destroy-id)) usam [OAuth 1.0a User Context](https://developer.x.com/content/developer-twitter/resources/fundamentals/authentication). Portanto, se você estava anteriormente usando um dos endpoints standard v1.1, pode continuar usando o mesmo método de autenticação se migrar para a versão X API v2.

### Diferenças

**URLs dos endpoints**

* Endpoints standard v1.1:
    * https://api.x.com/1.1/statuses/update.json
        (Cria um Post)
    * `https://api.x.com/1.1/statuses/destroy/:id.json`
        (Exclui um Post)
* Endpoint da X API v2:
    * https://api.x.com/2/tweets
        (Cria um Post)
    * https://api.x.com/2/tweets/:id
        (Exclui um Post especificado)

### Requisitos de App e Project

Os endpoints da X API v2 exigem que você use credenciais de um [App de desenvolvedor](/resources/fundamentals/developer-apps) associado a um [Project](/resources/fundamentals/developer-apps) ao autenticar suas requisições.
