### Gerenciar Likes: Standard v1.1 em comparação com a X API v2

Se você tem trabalhado com os endpoints standard v1.1 [POST favorites/create](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/post-favorites-create) e [POST favorites/destroy](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/post-favorites-destroy), o objetivo deste guia é ajudar você a entender as similaridades e diferenças entre os endpoints de gerenciamento de Likes do standard v1.1 e da X API v2.

* **Similaridades**
    * OAuth 1.0a User Context
* **Diferenças**
    * URLs dos endpoints e métodos HTTP
    * Requisitos de App e Project
    * Parâmetros de requisição

#### Similaridades

**Método de autenticação OAuth 1.0a User Context**

Ambas as versões dos endpoints suportam [OAuth 1.0a User Context](/resources/fundamentals/authentication#oauth-1-0a-2). Portanto, se você estava anteriormente usando um dos endpoints standard v1.1 manage favorites, você pode continuar usando o mesmo método de autenticação se migrar para a versão X API v2.

#### Diferenças

**URLs dos endpoints e métodos HTTP**

* Endpoints standard v1.1:
    * POST https://api.x.com/1.1/favorites/create.json
        (curtir um Post)
    * POST https://api.x.com/1.1/favorites/destroy.json
        (descurtir um Post)
* Endpoint da X API v2:
    * POST https://api.x.com/2/tweets/:id/likes
        (curtir um Post)
    * DELETE https://api.x.com/2/tweets/:id/likes/:tweet_id
        (descurtir um Post) 

**Requisitos de App e Project**

Os endpoints da X API v2 exigem que você use credenciais de um [App de desenvolvedor](/resources/fundamentals/developer-apps) associado a um [Project](/resources/fundamentals/developer-apps) ao autenticar suas requisições. Todos os endpoints da X API v1.1 podem usar credenciais de Apps ou Apps associados
