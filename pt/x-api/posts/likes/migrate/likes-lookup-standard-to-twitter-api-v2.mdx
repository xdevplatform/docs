### Consulta de likes: Standard v1.1 em comparação com a X API v2

Se você tem trabalhado com o endpoint standard v1.1 [GET favorites/list](https://developer.x.com/en/docs/x-api/v1/tweets/post-and-engage/api-reference/get-favorites-list), o objetivo deste guia é ajudar você a entender as similaridades e diferenças entre os endpoints de consulta de likes do standard v1.1 e da X API v2.

Com a v2, também introduzimos um novo endpoint de liked users que permite obter informações sobre os usuários que curtiram um Post.

* **Similaridades**
    * Autenticação
    * Rate limits
* **Diferenças**
    * URLs dos endpoints

    * Limitações de requisição
    * Requisitos de App e Project

    * Parâmetros de requisição
    * Novo formato JSON

#### Similaridades

**Autenticação**

Tanto o endpoint standard v1.1 quanto o endpoint de consulta de likes da X API v2 usam [OAuth 1.0a User Context](/resources/fundamentals/authentication#oauth-1-0a-2) ou [OAuth 2.0 Bearer Token](/resources/fundamentals/authentication#bearer-token-also-known-as-app-only). Portanto, se você estava anteriormente usando os endpoints standard v1.1 [GET favorites/list](https://developer.x.com/en/docs/x-api/v1/tweets/post-and-engage/api-reference/get-favorites-list), você pode continuar usando o mesmo método de autenticação se migrar para a versão X API v2, se quiser.

Dependendo da sua biblioteca/pacote de autenticação de escolha, a autenticação com Bearer Token provavelmente é a maneira mais fácil de começar e pode ser definida com um simples header de requisição. Para saber como gerar um Bearer Token, consulte [este guia de OAuth 2.0 Bearer Token](/resources/fundamentals/authentication#bearer-token-also-known-as-app-only).


**Rate limits**

O endpoint standard v1.1 GET favorites/list tem um rate limit de 75 requisições por 15 minutos por usuário. O endpoint correspondente de Posts curtidos na v2 também tem esse mesmo
