### Enterprise em comparação com a X API v2

**Similaridades**

* Granularidade
* Paginação
* Fuso horário

**Diferenças**

* URLs dos endpoints
* Requisito de App e Project
* Períodos de tempo disponíveis
* Formato dos dados de resposta
* Métodos HTTP
* Formatos de tempo da requisição
* Parâmetros da requisição
* Operadores de filtragem

#### Similaridades

**Granularidade**

Embora o parâmetro para selecionar a granularidade dos dados retornados seja diferente (`bucket` na versão enterprise, `granularity` na v2), os valores que você pode passar com esse parâmetro são os mesmos, assim como o comportamento padrão:

* `day`
* `hour` (padrão)
* `minute`

**Paginação**

Embora a v2 tenha recursos adicionais de paginação (novos parâmetros de paginação que permitem navegar usando IDs de Post com `since_id` e `until_id`), tanto a enterprise quanto a v2 permitem paginar usando tempo (`fromDate` e `toDate` na enterprise, e `start_time` e `end_time` na v2).

Se você estiver usando a versão enterprise, usará o parâmetro `next` para paginar, o campo do próximo token será chamado de `next` e estará localizado na raiz da resposta.

Se você estiver usando a v2, pode usar tanto o parâmetro `next_token` quanto `pagination_token` para paginar, e seu próximo token estará em `meta.next_token` na resposta.


**Fuso horário**

Como observado na seção de paginação, você pode navegar por diferentes páginas de dados usando tempo tanto na enterprise quanto na v2. Em ambos os casos, você usará UTC como fuso horário ao utilizar esses parâmetros.
