## Comparando os endpoints de Post counts da X API

O endpoint de Post counts da v2 acabará por substituir o [endpoint de counts da enterprise Search API](/x-api/enterprise-gnip-2.0/fundamentals/search-api#counts-requests-post-count). Se você tem código, apps ou ferramentas que usam uma versão mais antiga de um endpoint de Post counts e está considerando migrar para os endpoints mais recentes da X API v2, este guia é para você.

## Comparação de Post counts recentes

A versão enterprise dos endpoints de Post counts permite obter contagens para 30 dias ou para o arquivo completo. Portanto, o endpoint de recent Post counts da v2, que analisa um período de 7 dias, não é uma substituição direta para nenhum dos endpoints mencionados.

No entanto, para ajudar nas comparações, veremos como o endpoint de recent Post counts da v2 se compara ao endpoint enterprise de 30 dias.

A tabela a seguir compara os diversos tipos de endpoints de recent Post counts:

| **Descrição** | **Enterprise** | **X API v2** |
| :--- | :--- | :--- |
| Domínio do host | https://gnip-api.x.com | https://api.x.com |
| Caminho do endpoint | /search/30day/accounts/:account_name/:label/counts.json | /2/tweets/counts/recent |
| [Autenticação](/resources/fundamentals/authentication) | Basic authentication | OAuth 2.0 Bearer Token |
| Formato de timestamp | YYYYMMDDhhmm | YYYY-MM-DDTHH:mm:ssZ  <br/>[ISO 8601 / RFC 3339](https://tools.ietf.org/html/rfc3339#section-5.6) |
| Retorna contagens de Posts com no máximo | 31 dias | 7 dias |
| Métodos HTTP suportados | GET | GET |
| Rate limits padrão de requisição | 20 requisições por 1 seg, agregadas entre requisições de dados de busca e counts  <br/>O rate limit por minuto varia por parceiro conforme especificado no seu contrato. | 180 requisições por 15 min por usuário  <br/>450 requisições por 15 min por App |
| Suporta filtragem usando [annotations](/x-api/fundamentals/post-annotations) |     | ✔   |
| Suporta filtragem usando [conversation_id](/x-api/fundamentals/conversation-id) |     | ✔   |
| Nome da chave JSON para o array de dados de Post | results | data |
| Granularidade de tempo | Dia, hora ou minuto | Dia, hora ou minuto |
| Fuso horário | UTC | UTC |
| Parâmetros de requisição para selecionar o período de tempo | fromDate  <br/>toDate | start_time  <br/>end_time |
| Parâmetros de requisição para navegar por ID de Post |     | since_id  <br/>until_id |
| Requer o uso de credenciais de um [App de desenvolvedor](/resources/fundamentals/developer-apps) associado a um [project](/resources/fundamentals/developer-apps) |     | ✔   |

### Comparação de operadores de filtragem

As duas versões diferentes (enterprise e v2) de Post counts diferem em quais operadores estão disponíveis e também têm níveis variados de disponibilidade de operadores dentro de cada versão, que são explicados abaixo.

Enterprise

* Não há subníveis de operadores enterprise. Todos os operadores enterprise estão disponíveis para todos os usuários enterprise.



X API v2

* **Core:** Estes operadores estão disponíveis para qualquer usuário v2.
* **Advanced:** Estes operadores estão disponíveis apenas para usuários aprovados para acesso Academic Research.



Você pode aprender mais sobre cada um destes conjuntos de operadores em seus respectivos guias:

* [Operadores Enterprise](/x-api/enterprise-gnip-2.0/fundamentals/search-api#building-search-queries)
* [Operadores da X API v2](/x-api/posts/search/integrate/build-a-query)
