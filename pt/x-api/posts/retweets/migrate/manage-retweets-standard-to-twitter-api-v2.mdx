### Gerenciar Retweets: Standard v1.1 em comparação com a X API v2

Se você tem trabalhado com os endpoints standard v1.1 [POST statuses/retweet/:id](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/post-statuses-retweet-id) e [POST statuses/unretweet/:id](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/post-statuses-unretweet-id), o objetivo deste guia é ajudar você a entender as similaridades e diferenças entre os endpoints de Retweets do standard e da X API v2.

* **Similaridades**
    * Autenticação
* **Diferenças**
    * URLs dos endpoints e métodos HTTP
    * Limitações de requisição
    * Requisitos de App e Project
    * Parâmetros de requisição

#### Similaridades

**Autenticação**

Tanto os endpoints standard v1.1 quanto os endpoints de gerenciar Retweets da X API v2 ([POST statuses/retweet/:id](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/post-statuses-retweet-id) e [POST statuses/unretweet/:id](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/post-statuses-unretweet-id)) usam [OAuth 1.0a User Context](https://developer.x.com/content/developer-twitter/resources/fundamentals/authentication). Portanto, se você estava anteriormente usando um dos endpoints standard v1.1 de consulta de Retweets, você pode continuar usando o mesmo método de autenticação se migrar para a versão X API v2.

#### Diferenças

**URLs dos endpoints e métodos HTTP**

    * https://api.x.com/1.1/statuses/retweet/:id.json

    * https://api.x.com/1.1/statuses/unretweet/:id.json
        (Desfaz um Retweet. Retorna o Post original com os detalhes do Retweet incorporados)
