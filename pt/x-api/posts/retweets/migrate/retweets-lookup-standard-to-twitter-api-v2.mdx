### Consulta de Retweets: Standard v1.1 em comparação com a X API v2

Se você tem trabalhado com o standard v1.1 [v1.1 GET statuses/retweets/:id](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-retweets-id), [v1.1 GET statuses/retweets/:ids](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-retweeters-ids), o objetivo deste guia é ajudar você a entender as similaridades e diferenças entre os endpoints de consulta de Retweets do standard v1.1 e da X API v2.

* **Similaridades**
    * Autenticação
    * Limites de usuários por requisição
* **Diferenças**
    * URLs dos endpoints

    * Limitações de requisição
    * Requisitos de App e Project

    * Formato dos dados de resposta
    * Parâmetros de requisição

#### Similaridades

**Autenticação**

Tanto os endpoints de consulta de Retweets do standard v1.1 quanto da X API v2 ([v1.1 GET statuses/retweets/:id](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-retweets-id) e [v1.1 GET statuses/retweeters/:ids](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-retweeters-ids)) usam [OAuth 1.0a User Context](https://developer.x.com/content/developer-twitter/resources/fundamentals/authentication) ou OAuth 2.0 Bearer Token.

**Limites de usuários por requisição**

Para os endpoints GET v1.1 e v2, o número máximo de usuários que será retornado pelo endpoint de consulta de Retweets é 100 usuários. Para o endpoint v2 de consulta de Retweets, não há um pagination token sendo passado; por padrão, entregamos 100 usuários e esse é o máximo retornado.
