Os eventos entregues pela X Activity API (via [stream HTTP persistente](/x-api/activity/activity-stream) ou [webhooks](/x-api/webhooks/introduction)) compartilham um envelope comum:

| Campo | Descrição |
| --- | --- |
| `event_uuid` | Identificador único para esta entrega de evento |
| `filter` | O filtro que correspondeu (por exemplo, `user_id` ou `keyword`) |
| `event_type` | O tipo de evento assinado |
| `tag` | Tag opcional da sua assinatura (quando definida) |
| `payload` | Dados específicos do evento |
| `includes` | Objetos expandidos opcionais (usuários, tweets, etc.) quando disponíveis |

```json title="post.create" lines wrap icon="/icons/xds/icon-brackets.svg"
{
  "data": {
    "event_uuid": "2080761390344937796",
    "filter": {
      "user_id": "1716450569358098432"
    },
    "event_type": "post.create",
    "tag": "my post create",
    "payload": {},
    "includes": {}
  }
}
```

Os exemplos abaixo são payloads representativos do mundo real. A disponibilidade dos campos pode variar conforme as configurações da conta, as expansões e o estado do objeto no momento da entrega. Consulte a [introdução](/x-api/activity/introduction) para ver a lista completa dos tipos de evento suportados e os requisitos de autenticação.

## Eventos de curtida

### `like.create`

Disparado quando o usuário filtrado curte um Post ou quando um dos seus Posts é curtido. Evento privado — requer autenticação no contexto do usuário. Suporta um filtro `direction` opcional (`inbound` ou `outbound`).

O `payload` é um objeto de curtida com os seguintes campos:

| Campo | Descrição |
| --- | --- |
| `id` | ID do evento de curtida |
| `liked_tweet_id` | ID do Post que foi curtido |
| `liked_tweet_author_id` | Autor do Post curtido |
| `created_at` | Horário de criação do Post curtido (quando disponível) |
| `timestamp_ms` | Timestamp do evento em milissegundos (quando disponível) |

`includes` pode conter o Post curtido e os usuários relacionados.

## Eventos de perfil

Todos os eventos `profile.update.*` compartilham a mesma estrutura de payload com `before` / `after`.

Tipos suportados: `profile.update.bio`, `profile.update.profile_picture`, `profile.update.banner_picture`, `profile.update.screenname`, `profile.update.handle`, `profile.update.geo`, `profile.update.url`, `profile.update.verified_badge`, `profile.update.affiliate_badge`.

### `profile.update.bio`

Disparado quando o usuário filtrado atualiza a bio do perfil.

```json title="profile.update.bio" lines wrap icon="/icons/xds/icon-brackets.svg"
{
  "data": {
    "event_uuid": "-8917909039855612786",
    "filter": {
      "user_id": "1716450569358098432"
    },
    "event_type": "profile.update.bio",
    "tag": "my bio updates",
    "payload": {
      "before": "X Developer Platform • prev. @google, @coinbase\n\n@X @XDevelopers",
      "after": "X Developer Platform • prev @google, @coinbase\n\n@X @XDevelopers"
    }
  }
}
```

| --- | --- |

| `name` | Manchete / nome do tópico |

| `hook` | Chamada curta / teaser |
| `summary` | Resumo mais longo |
| `contexts` | Contextos de tópicos / entidades relacionadas |
| `cluster_posts_results` | Posts relacionados, quando disponíveis |
| `updated_at` | Timestamp da última atualização |

## Eventos de silenciamento

Os eventos de silenciamento usam um par de usuários `source` / `target` semelhante aos eventos de seguir. Eventos privados — requerem autenticação no contexto do usuário com o escopo `mute.read`. O filtro `user_id` corresponde ao usuário que **executa** o silenciamento ou o dessilenciamento (não à conta que está sendo silenciada).

### `mute.mute`

Disparado quando o usuário filtrado silencia outro usuário.

### `mute.unmute`

Disparado quando o usuário filtrado dessilencia outro usuário.

---

## Eventos de bloqueio

Os eventos de bloqueio usam um par de usuários `source` / `target` semelhante aos eventos de seguir. Eventos privados — requerem autenticação no contexto do usuário com o escopo `block.read`. O filtro `user_id` corresponde ao usuário que **executa** o bloqueio ou o desbloqueio (não à conta que está sendo bloqueada).

### `block.block`

Disparado quando o usuário filtrado bloqueia outro usuário.

### `block.unblock`

Disparado quando o usuário filtrado desbloqueia outro usuário.

## Eventos de OAuth

### `oauth.revoke`

Disparado quando um usuário revoga o acesso da sua aplicação. O `filter` pode estar vazio. Use este evento para limpar o estado local do usuário revogado.
