### Gerenciar mutes: Standard v1.1 comparado com X API v2

Se você tem usado os endpoints standard v1.1 [POST mutes/users/create](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/mute-block-report-users/api-reference/post-mutes-users-create) e [POST mutes/users/destroy](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/mute-block-report-users/api-reference/post-mutes-users-destroy), o objetivo deste guia é ajudar você a entender as semelhanças e diferenças entre os endpoints de gerenciamento de mutes do standard v1.1 e da X API v2.

* **Semelhanças**
    * OAuth 1.0a User Context
* **Diferenças**
    * URLs dos endpoints
    * Requisitos de App e Project
    * Métodos HTTP
    * Parâmetros da requisição
         

#### Semelhanças

**Método de autenticação OAuth 1.0a User Context**

Ambas as versões de endpoint suportam [OAuth 1.0a User Context](https://developer.x.com/content/developer-twitter/resources/fundamentals/authentication). Portanto, se você estava usando um dos endpoints de gerenciamento de mutes do standard v1.1, pode continuar usando o mesmo método de autenticação ao migrar para a versão X API v2.

#### Diferenças

**URLs dos endpoints**

* Endpoints do standard v1.1:
    * POST https://api.x.com/1.1/mutes/users/create.json
        (silenciar um usuário)
    * POST https://api.x.com/1.1/mutes/users/destroy.json
        (reativar um usuário silenciado)
* Endpoint da X API v2:
    * POST https://api.x.com/2/users/:id/muting
        (silenciar um usuário)
    * DELETE https://api.x.com/2/users/:source\_user\_id/muting/:target\_user\_id
        (reativar um usuário silenciado)
