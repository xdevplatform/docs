## Comparando os endpoints de mutes da X API

#### Consulta de mutes

O endpoint v2 de consulta de mutes substituirá os endpoints standard [v1.1 GET mutes/users/ids](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/mute-block-report-users/api-reference/get-mutes-users-ids) e [GET mutes/users/list](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/mute-block-report-users/api-reference/get-mutes-users-list).

As tabelas a seguir comparam os endpoints de mute do standard v1.1 e da X API v2:
 

| Descrição | Standard v1.1 | X API v2 |
| :--- | :--- | :--- |
| Métodos HTTP suportados | **GET** | **GET** |
| Domínio do host | **https://api.x.com** | **https://api.x.com** |
| Caminho do endpoint | **/1.1/mutes/users/ids.json**<br/><br/>/1.1/mutes/users/list.json | **/2/users/:id/muting** |
| [Autenticação](/resources/fundamentals/authentication) | OAuth 1.0a User Context | OAuth 1.0a User Context<br/><br/>OAuth 2.0 Authorization Code with PKCE |
| [Limites de requisição](/resources/fundamentals/rate-limits) padrão | 15 requisições por 15 min (por usuário) | 15 requisições por 15 min (por usuário) |
| Formatos de dados | Formato Standard v1.1 | [Formato X API v2](/x-api/fundamentals/data-dictionary) (determinado pelos parâmetros fields e expansions da requisição, não é retrocompatível com os formatos v1.1)<br/><br/>Para saber mais sobre como migrar do formato Standard v1.1 para o formato X API v2, consulte nosso [guia de migração de formatos de dados](/x-api/migrate/data-format-migration). |
| Exige o uso de credenciais de um [App de desenvolvedor](/resources/fundamentals/developer-apps) associado a um [Project](/resources/fundamentals/developer-apps) |     | ✔️  |

#### Gerenciar mutes

Os endpoints v2 de gerenciamento de mutes substituirão os endpoints standard v1.1 [POST mutes/users/create](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/mute-block-report-users/api-reference/post-mutes-users-create) e [POST mutes/users/destroy](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/mute-block-report-users/api-reference/post-mutes-users-destroy).

As tabelas a seguir comparam os endpoints de mute do standard v1.1 e da X API v2:

**Silenciar um usuário**

| Descrição | Standard v1.1 | X API v2 |
| :--- | :--- | :--- |
| Métodos HTTP suportados | POST | POST |
| Domínio do host | https://api.x.com | https://api.x.com |
| Caminho do endpoint | /1.1/mutes/users/create.json | /2/users/:id/muting |
| [Autenticação](/resources/fundamentals/authentication) | OAuth 1.0a User Context | OAuth 1.0a User Context<br/><br/>OAuth 2.0 Authorization Code with PKCE |
| [Limites de requisição](/resources/fundamentals/rate-limits) padrão | 50 requisições por 15 min | 50 requisições por 15 min |
| Exige o uso de credenciais de um [App de desenvolvedor](/resources/fundamentals/developer-apps) associado a um [Project](/resources/fundamentals/developer-apps) |     | ✔️  |

**Reativar um usuário silenciado**
