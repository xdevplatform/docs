## Comparando os endpoints de follows da X API

### Consulta de follows

Os endpoints de consulta de follows da v2 substituirão os endpoints standard v1.1 [followers/ids](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/follow-search-get-users/api-reference/get-followers-ids), v1.1 [followers/list](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/follow-search-get-users/api-reference/get-followers-list), v1.1 [friends/ids](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/follow-search-get-users/api-reference/get-friends-ids) e v1.1 [friends/list](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/follow-search-get-users/api-reference/get-friends-list).

As tabelas a seguir comparam os diversos tipos de endpoints de consulta de follows:

|     |     |     |
| :--- | :--- | :--- |
| **Descrição** | **Standard v1.1** | **X API v2** |
| Métodos HTTP suportados | `GET` | `GET` |
| Domínio do host | `https://api.x.com` | `https://api.x.com` |
| Caminho do endpoint | /1.1/friends/ids.json<br/><br/>/1.1/friends/list.json<br/><br/>/1.1/followers/ids.json<br/><br/>/1.1/followers/list.json | /2/users/:id/following<br/><br/>/2/users/:id/followers |
| [Autenticação](/resources/fundamentals/authentication) | OAuth 1.0a User Context<br/><br/>App only | OAuth 1.0a User Context<br/><br/>OAuth 2.0 Authorization Code with PKCE<br/><br/>App only |
| [Limites de requisição](/resources/fundamentals/rate-limits) padrão | 15 requisições por 15 min (por usuário)<br/><br/>15 requisições por 15 min (por app) | 15 requisições por 15 min (por usuário)<br/><br/>15 requisições por 15 min (por app) |
| Máximo de usuários por resposta | GET friends/id & GET followers/id retornam no máximo 5000 IDs de usuários por página.<br/><br/>  <br/><br/>GET friends/list & GET followers/list retornam no máximo 200 objetos de usuário por página. | 1000 objetos de usuário por página |
| Paginação | O token é retornado em um campo next_cursor, que pode então ser passado como valor para o parâmetro cursor a fim de retornar a próxima página de resultados. | O token é retornado em um campo next_token, que pode ser passado como valor para o parâmetro token a fim de retornar a próxima página de resultados.<br/><br/>O payload v2 também entrega um campo previous_token, que pode ser passado com o parâmetro pagination_token para retornar a página anterior de resultados. |
| Formato JSON | Formato Standard v1.1 | [Formato X API v2](/x-api/fundamentals/data-dictionary) (determinado pelos parâmetros fields e expansions da requisição, não é retrocompatível com os formatos v1.1)<br/><br/>Para saber mais sobre como migrar do formato Standard v1.1 para o formato X API v2, consulte nosso [guia de migração de formatos de dados](/x-api/migrate/data-format-migration). |
| Suporta selecionar quais [fields](/x-api/fundamentals/data-dictionary) retornam no payload |     | ✔   |
| Suporta os fields de [annotations](/x-api/fundamentals/post-annotations) de Post |     | ✔   |
| Suporta solicitar novos fields de [metrics](/x-api/fundamentals/metrics) |     | ✔   |
| Suporta o field [conversation_id](/x-api/fundamentals/conversation-id) |     | ✔   |
| Exige o uso de credenciais de um [App de desenvolvedor](/resources/fundamentals/developer-apps) associado a um [Project](/resources/fundamentals/developer-apps) |     | ✔   |

#### Gerenciar follows

Os endpoints v2 de gerenciamento de follows substituirão os endpoints standard v1.1 [POST friendships/create](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/follow-search-get-users/api-reference/post-friendships-create) e [POST friendships/destroy](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/follow-search-get-users/api-reference/post-friendships-destroy).

As tabelas a seguir comparam os endpoints standard v1.1 e X API v2 para criar follows:

#### Seguir um usuário

| Descrição | Standard v1.1 | X API v2 |
| :--- | :--- | :--- |
| Métodos HTTP suportados | POST | POST |
| Domínio do host | https://api.x.com | https://api.x.com |
| Caminho do endpoint | /1.1/friendships/create.json | /2/users/:id/following |
| [Autenticação](/resources/fundamentals/authentication) | OAuth 1.0a User Context | OAuth 1.0a User Context<br/><br/>OAuth 2.0 Authorization Code with PKCE |
| [Limites de requisição](/resources/fundamentals/rate-limits) padrão | 50 requisições por 15 min | 50 requisições por 15 min |
| Máximo de operações diárias por usuário | 400 | 400 |
| Máximo de operações diárias por app | 1000 | 1000 |
| Exige o uso de credenciais de um [App de desenvolvedor](/resources/fundamentals/developer-apps) associado a um [Project](/resources/fundamentals/developer-apps) |     | ✔️  |

#### Deixar de seguir um usuário

As tabelas a seguir comparam os endpoints standard v1.1 e X API v2 para excluir follows:

| Descrição | Standard v1.1 | X API v2 |
| :--- | :--- | :--- |
| Métodos HTTP suportados | POST | DELETE |
| Domínio do host | https://api.x.com | https://api.x.com |
| Caminho do endpoint | /1.1/friendships/destroy.json | /2/users/:source\_user\_id/following/:target\_user\_id |
| [Autenticação](/resources/fundamentals/authentication) | OAuth 1.0a User Context | OAuth 1.0a User Context<br/><br/>OAuth 2.0 Authorization Code with PKCE |
| [Limites de requisição](/resources/fundamentals/rate-limits) padrão | 15 requisições por 15 min (por usuário) | 50 requisições por 15 min (por usuário) |
| Máximo de operações diárias por app | Nenhum | 500 |
| Exige o uso de credenciais de um [App de desenvolvedor](/resources/fundamentals/developer-apps) associado a um [Project](/resources/fundamentals/developer-apps) |     | ✔️  |
