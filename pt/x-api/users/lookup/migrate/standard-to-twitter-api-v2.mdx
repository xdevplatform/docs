### Standard v1.1 comparado com X API v2

Se você tem usado os endpoints standard v1.1 GET users/show e GET users/lookup, o objetivo deste guia é ajudar você a entender as semelhanças e diferenças entre os endpoints de consulta de usuários do standard e da X API v2.

* **Semelhanças**
    * OAuth 1.0a User Context
    * Limites de usuários por requisição
* **Diferenças**
    * URLs dos endpoints
    * Requisitos de App e Project
    * Formato dos dados de resposta
    * Parâmetros da requisição

#### Semelhanças

**Método de autenticação OAuth 1.0a User Context**

O endpoint standard suporta [OAuth 1.0a User Context](/resources/fundamentals/authentication#oauth-1-0a-2), enquanto os novos endpoints de consulta de usuários da X API v2 suportam tanto OAuth 1.0a User Context quanto [App only](/resources/fundamentals/authentication#oauth-2-0). Portanto, se você estava usando um dos endpoints de consulta de usuários do standard v1.1, pode continuar usando o mesmo método de autenticação ao migrar para a versão X API v2.

Dependendo da sua biblioteca/pacote de autenticação, a autenticação App only provavelmente é a maneira mais fácil de começar e pode ser configurada com um simples cabeçalho de requisição. Para saber como gerar um Access Token App only, consulte [este guia sobre App only](/resources/fundamentals/authentication#bearer-token-also-known-as-app-only).

**Limites de usuários por requisição**

O endpoint standard v1.1 GET users/lookup permite especificar 100 usuários por requisição. O mesmo se aplica aos endpoints GET /users e GET /users/by. Para especificar até 100 usuários, você precisará passar o parâmetro ids (GET /users) ou o parâmetro username (GET /users/by) como parâmetro de consulta e incluir a lista de user IDs/usernames separada por vírgulas.
