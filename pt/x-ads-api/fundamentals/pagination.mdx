Para suportar um número máximo maior de campanhas e a recuperação eficiente de todas as entidades associadas a uma conta, a Advertiser API agora suporta paginação em muitos endpoints GET. O mecanismo de paginação é fácil de usar e muito semelhante à paginação baseada em cursor da REST API, como descrito em [Usando cursors para navegar em coleções](https://developer.x.com/en/docs/x-api/v1/pagination).

## Começando

Para requisições GET designadas, agora aceitamos os parâmetros de query `cursor` e `count`, que são ambos opcionais. Se uma resposta tiver mais de `count` entidades, esses endpoints agora retornarão as primeiras `count` entidades e uma chave `next_cursor` no JSON de resposta.

`GET https://ads-api.x.com/5/accounts/abc1/campaigns?count=50`

```json
{
  "data": \[...\],
  "next_cursor": "c-3yvu1pzhd3i7",
  "request": {...}
}
```

Para obter a próxima série de respostas, você adicionaria `cursor` aos seus query params:

`GET https://ads-api.x.com/5/accounts/abc1/campaigns?cursor=c-3yvu1pzhd3i7&count=50`

```json
{
  "data": \[...\],
  "next_cursor": "c-3w3zdyg8ywan",
  "request": {...}
}
```
## Indo mais fundo

Para a maioria dos endpoints, o valor máximo de `count` é **1.000**, o mínimo é **1** e o padrão é **200**.

O valor fornecido por `next_cursor` é sempre uma string e deve ser considerado opaco; a implementação está sujeita a mudanças. Se menos de `count` entidades forem retornadas na página atual do conjunto de resultados, o valor de `next_cursor` será `null`.

**Nota:** os endpoints de analytics não suportam este estilo de paginação. A paginação nos endpoints de stats é suportada especificando períodos de tempo. Consulte a documentação desses endpoints individuais para mais informações.
