O fluxo de sign in no navegador é apropriado para sites e aplicações capazes de abrir ou incorporar um navegador web. Em alto nível:

- A aplicação renderiza um link ou botão "Sign in with X".
- O usuário clica no botão de sign in.
- O navegador web atual é redirecionado para o X (ou um novo navegador é aberto e direcionado para o X).
- O usuário conclui um passo de login e autorização no X, se necessário.
- O X redireciona de volta para uma URL controlada pela aplicação, passando informações de autorização para o usuário.
 

O X mantém o controle das autorizações, portanto, para usuários já conectados ao x.com que autorizaram a aplicação, nenhuma UI é exibida — em vez disso, eles são automaticamente redirecionados de volta à aplicação.

## Fluxo desktop

Para demonstrar os fluxos, imagine que o site retratado à direita ("The greatest website ever created") implementou esta API, como mostrado pelo botão Sign in with X na página inicial.

Quando o usuário clica no botão Sign in, a página que ele vê depende de estar ou não conectado e se ele já permitiu que a aplicação acesse sua conta.

Quando **o usuário está conectado ao x.com mas não concedeu acesso**, uma lista das permissões solicitadas, junto com botões Sign In e Cancel, são exibidos.

Quando **o usuário não está conectado ao x.com**, campos de entrada para username e senha serão exibidos. Observe que mesmo se o usuário já concedeu acesso à aplicação, a lista de permissões ainda será exibida.

Depois que o usuário insere credenciais válidas (se necessário) e clica em "Sign In", o X redireciona o usuário para o site que iniciou o fluxo de sign in.

No caso em que **o usuário já está conectado ao x.com e concedeu acesso ao site**, esse redirecionamento acontece imediatamente.

Para aprender a implementar este fluxo de sign in, leia [Implementando Sign in with X](/x-for-websites/log-in-with-x/guides/implementing-sign-in-with-x).
