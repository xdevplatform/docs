## Introdução

Os [endpoints de Search Posts](/x-api/posts/search/introduction)
no mundo v2 permitem receber Posts relacionados a tópicos de interesse,
com base em uma consulta de busca que você elabora. Temos dois endpoints diferentes
disponíveis com o v2 Search Posts: recent search, que está disponível para todos os
desenvolvedores com uma conta aprovada e pode buscar Posts de até sete dias
de idade, e full-archive search, que está disponível apenas para
pesquisadores aprovados para a
[trilha de produto Academic Research](https://developer.x.com/en/products/x-api/early-access/guide#na_2),
e pode pesquisar em todo o arquivo de Posts desde março de 2006.

Você pode ver toda a nossa oferta de busca em nossa
[página de visão geral de busca](/x-api/posts/search/introduction).

Esses endpoints de Search Posts atendem a um dos casos de uso mais comuns para
pesquisadores acadêmicos, que podem usá-los para estudos longitudinais ou análise
de um tópico ou evento passado.

Este tutorial fornece um guia passo a passo para pesquisadores que desejam usar o
endpoint full-archive search para pesquisar todo o histórico de dados públicos do X.
Também demonstrará as diferentes maneiras de construir um conjunto de dados, como
obter Posts com geotag, e como paginar pelos Posts disponíveis para
uma consulta.

### Pré-requisitos

Atualmente, este endpoint está disponível apenas como parte da
[trilha de produto Academic Research](https://developer.x.com/en/solutions/academic-research/products-for-researchers).

[solicitar acesso](https://developer.x.com/en/portal/petition/academic/is-it-right-for-you).

[inscrição e os requisitos para esta trilha](https://developer.x.com/en/solutions/academic-research/application-info).

### Conectando-se ao endpoint full-archive search

O comando cURL abaixo mostra como você pode obter Posts históricos do handle @XDevelopers.
Substitua $BEARER_TOKEN pelo seu próprio Bearer Token, cole a requisição
completa no seu terminal e pressione "return".

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=from:xdevelopers' --header 'Authorization: Bearer $BEARER_TOKEN'
```

Você verá o JSON de resposta.

Por padrão, apenas os 10 Posts mais recentes serão retornados. Se você quiser mais
de 10 Posts por requisição, pode usar o parâmetro max_results e defini-lo para
um máximo de 500 Posts por requisição, como mostrado abaixo:

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=from:xdevelopers&max_results=500' --header 'Authorization: Bearer $BEARER_TOKEN'
```

### Construindo queries

Como você pode ver nos exemplos de chamadas acima, usando o parâmetro query, é possível
especificar os dados que deseja pesquisar. Por exemplo, se quiser obter todos os Posts
que contêm a palavra _covid_ ou a palavra _coronavirus_, você pode usar o operador
OR entre parênteses, e sua consulta pode ser
`(covid OR coronavirus)`, e assim sua chamada de API ficará assim:

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=(covid%20OR%20coronavirus)&max_results=500' --header 'Authorization: Bearer $BEARER_TOKEN'
```

Da mesma forma, se você quiser todos os Posts que contêm a palavra _covid19_ que não
são reposts, pode usar o operador is:retweet com o NOT lógico (representado
por \-), então sua consulta pode ser covid19 -is:retweet e sua chamada de API será:

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=covid19%20-is:retweet&max_results=500' --header 'Authorization: Bearer $BEARER_TOKEN'
```

Confira
[este guia para uma lista completa de operadores](/x-api/posts/search/integrate/build-a-query)
suportados no endpoint full-archive search.

### Usando os parâmetros start_time e end_time para obter Posts históricos

Ao usar o endpoint full-archive search, por padrão os Posts dos últimos 30
dias serão retornados. Se você quiser obter Posts com mais de 30 dias,
pode usar os parâmetros start_time e end_time em sua chamada de API. Esses
parâmetros devem estar em um formato de data e hora RFC3339 válido, por exemplo
2020-12-21T13:00:00.00Z. Assim, se você quiser obter todos os Posts da conta XDevelopers
no mês de dezembro de 2020, sua chamada de API será:

```bash
curl --request GET 'https://api.x.com/2/tweets/search/all?query=from:XDevelopers&start_time=2020-12-01T00:00:00.00Z&end_time=2021-01-01T00:00:00.00Z' --header 'Authorization: Bearer $BEARER_TOKEN'
```

### Obtendo Posts históricos com geotag

Posts com geotag são Posts que possuem informações geográficas associadas a
eles, como cidade, estado, país etc.

#### Usando o operador has:geo

Se você quiser obter Posts que têm dados de geolocalização, pode usar o operador has:geo.
Por exemplo, a seguinte requisição cURL obterá apenas os Posts do
handle @XDevelopers que têm dados de geolocalização:

```bash
curl --request GET
'https://api.x.com/2/tweets/search/all?query=from:xdevelopers%20has:geo' --header
'Aubashthorization: Bearer $BEARER_TOKEN'
```

#### Usando o operador place_country

Da mesma forma, você pode limitar os Posts que têm dados de geolocalização a um país específico, usando
o operador place_country. O comando cURL abaixo obterá todos os Posts do
handle @XDevelopers dos Estados Unidos:

```bash
curl --request GET
'https://api.x.com/2/tweets/search/all?query=from:xdevelopers%20place_country:US'
--hbasheader 'Authorization: Bearer XXXXX'
```

O país é especificado acima usando o código de dois caracteres ISO alpha-2. Códigos ISO
válidos podem ser encontrados [aqui](http://en.wikipedia.org/wiki/ISO_3166-1_alpha-2).

### Obtendo mais de 500 Posts históricos usando o next_token

Como mencionado acima, por padrão você só pode obter até 500 Posts por requisição para
uma consulta ao endpoint full-archive search. Se houver mais de 500 Posts
disponíveis para sua consulta, sua resposta json incluirá um next_token que você
pode adicionar à sua chamada de API para obter os próximos Posts disponíveis para essa
consulta. Este next_token está disponível no objeto meta da sua resposta JSON,
que se parece com algo assim:

```json
{ "newest_id": "12345678...", "oldest_id": "12345678...", "result_count": 500,
"nebashxt_token": "XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX" }
```

Assim, para obter os próximos Posts disponíveis, use o valor de next_token deste objeto
meta e use o valor como valor do next_token em sua chamada de API para o endpoint
full-archive search, como mostrado abaixo (Você usará seu próprio Bearer Token
e o valor que você obtém para o Next Token da sua chamada de API anterior).

```bash
curl --request GET
'https://api.x.com/2/tweets/search/all?max_results=500&query=covid&next_token=XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX'
--header 'Authorization: Bearer $BEARER_TOKEN'
```

Dessa forma, você pode continuar verificando se há um next_token disponível e, se você não
tiver atingido o número desejado de Posts a serem coletados, pode continuar chamando o
endpoint full-archive com o novo next_token para cada requisição.
