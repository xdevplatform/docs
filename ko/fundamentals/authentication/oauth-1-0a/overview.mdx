## OAuth 1.0a

X 개발자 플랫폼의 많은 엔드포인트는 X 계정을 대신해 작업하거나 API 요청을 보내기 위해 OAuth 1.0a 방식을 사용합니다. 예를 들어, X 개발자 App이 있다면 해당 사용자가 App을 인증하는 한 어떤 X 계정을 대신해서도 API 요청을 보낼 수 있습니다.

참고: HMAC-SHA1 및 퍼센트 인코딩과 같은 개념에 익숙하지 않다면, 인증 과정을 크게 단순화해 주는 API 클라이언트를 소개하는 아래 "유용한 도구" 섹션을 확인하시길 권장합니다.

### 핵심 개념

#### 키와 토큰으로 요청 서명하기

authorization 헤더에 생성된 여러 키와 토큰을 전달하여 각 API 요청에 서명해야 합니다. 시작하려면 [X 개발자 App](/resources/fundamentals/developer-apps)의 세부정보 페이지에서 다음을 포함한 여러 키와 토큰을 생성할 수 있습니다:

|     |     |
| :--- | :--- |
| API 키와 시크릿:<br/><br/>`oauth_consumer_key`<br/><br/>`oauth_consumer_secret` | API 요청을 보낼 때 X 개발자 App을 대표하는 사용자 이름과 비밀번호라고 생각하세요. |
| 액세스 토큰과 시크릿:<br/><br/>`oauth_token`<br/><br/>`oauth_token_secret` | 액세스 토큰과 액세스 토큰 시크릿은 OAuth 1.0a API 요청을 인증하는 데 사용되는 사용자별 자격 증명입니다. 요청이 어떤 X 계정을 대신하여 이루어지는지를 지정합니다.<br/><br/>[X 개발자 App](/resources/fundamentals/developer-apps)의 세부정보 페이지에서, App이 개발자 계정과 연결된 동일한 X 계정을 대신해 요청하도록 하려면 직접 액세스 토큰과 토큰 시크릿을 생성할 수 있습니다.<br/><br/>다른 사용자를 위한 액세스 토큰을 생성하려면 아래 "사용자를 대신하여 요청하기"를 참고하세요. |

#### 사용자를 대신하여 요청하기

서명을 생성할 때, 요청을 대신하려는 사용자를 나타내는 액세스 토큰 세트가 필요합니다.

X 개발자 App을 소유한 X 계정을 나타내는 액세스 토큰 세트는 [App의 세부정보 페이지](https://developer.x.com/content/developer-twitter/en/apps)에서 생성할 수 있습니다. 다른 X 계정을 대신하여 요청하려는 경우, 해당 계정 소유자가 [3-legged OAuth 흐름](/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow)의 일부로 자신의 계정에 로그인하여 액세스를 부여해야 합니다. 이 과정의 결과로 OAuth 1.0a 요청에 사용할 수 있는 액세스 토큰 세트(oauth\_token 및 oauth\_token_secret)가 생성됩니다.

이러한 키와 토큰이 준비되면 처음부터 [서명을 만들 수 있습니다](/resources/fundamentals/authentication#creating-a-signature). 자신이 무엇을 하고 있는지 정확히 알고 있는 경우가 아니라면 이 방법은 권장하지 않으며, OAuth 1.0a가 필요한 엔드포인트에 요청을 보내려면 아래에 소개된 도구 중 하나를 사용하는 편을 권장합니다.

참고로, authorization 헤더에 생성된 모든 토큰이 전달된 서명된 cURL 요청의 예시는 다음과 같습니다:

```bash
curl --request POST \
  --url 'https://api.x.com/1.1/statuses/update.json?status=Hello%20world' \
  --header 'authorization: OAuth oauth_consumer_key="CONSUMER_API_KEY", oauth_nonce="OAUTH_NONCE", oauth_signature="OAUTH_SIGNATURE", oauth_signature_method="HMAC-SHA1", oauth_timestamp="OAUTH_TIMESTAMP", oauth_token="ACCESS_TOKEN", oauth_version="1.0"' \
```

<Note>
**참고:** 사용자 액세스 토큰은 민감하므로 매우 신중하게 보호해야 합니다. 액세스 토큰이 생성될 때, 해당 토큰이 대표하는 사용자는 애플리케이션이 이를 안전하게 관리할 것을 신뢰합니다. API 키와 사용자 액세스 토큰의 보안이 모두 손상되면 애플리케이션이 개인 정보 및 계정 기능에 대한 액세스를 노출할 수 있습니다. [키와 액세스 토큰 보호](/resources/fundamentals/developer-apps)에 대해 자세히 알아보시기 바랍니다.
</Note>

### 유용한 도구

[요청에 서명하는](/resources/fundamentals/authentication#creating-a-signature) 과정은 복잡합니다. 인증 토큰의 상당 부분을 자동으로 생성해 주는 API 클라이언트 라이브러리를 사용할 것을 권장합니다:

|     |     |
| :--- | :--- |
| [Postman](https://www.getpostman.com/) | REST API 요청을 만들고 보낼 수 있는 API 클라이언트입니다. 이 도구에 대해 자세히 알아보려면 "[Postman 시작하기](/tutorials/postman-getting-started)" 튜토리얼을 참고하세요. |
| [Insomnia](https://insomnia.rest/) | Insomnia는 쿠키 관리, 환경 변수, 코드 생성, 인증 기능을 갖춘 Mac, Windows, Linux용 REST API 클라이언트입니다. |
