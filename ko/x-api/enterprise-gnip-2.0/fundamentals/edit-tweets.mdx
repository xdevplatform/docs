엔터프라이즈 endpoint가 편집된 Post 메타데이터를 제공하도록 업데이트되었습니다. _Edit Posts_ 기능은 2022년 9월 1일에 X 직원들 사이에서 테스트를 위해 처음 도입되었습니다. 그 날짜부터, 자격이 있는 Post는 30분 동안 최대 5회까지 편집 가능합니다. _2022년 9월 29일 이후 생성된 Post의 모든 객체_ 에는 Post가 편집되지 않았더라도 Post 편집 메타데이터가 포함됩니다. Post가 편집될 때마다 새로운 Post ID가 생성됩니다. Post의 편집 이력은 원본 ID로 시작하여 이러한 ID를 연결하여 설명할 수 있습니다. 또한 편집 체인의 Post 중 하나라도 삭제되면 해당 체인의 모든 Post가 삭제됩니다.

이러한 메타데이터 세부 정보는 자동으로 포함됩니다. 사용 가능한 편집 이력을 Post 객체의 일부로 포함하기 위한 요청 파라미터는 필요하지 않습니다.

이러한 새 메타데이터를 통해 개발자는 다음을 확인할 수 있습니다:

* 생성 시점에 Post가 편집 가능했는지 여부. 투표가 있거나 예약된 Post와 같은 일부 Post는 편집할 수 없습니다.
* Post는 30분 동안 편집 가능하며 최대 5회까지 편집할 수 있습니다. 편집 가능한 Post의 경우 편집을 위한 시간이 남아 있는지, 몇 번의 편집이 더 가능한지 확인할 수 있습니다.
* 편집된 버전의 Post를 보고 있는지 여부. 대부분의 경우 Post ID로 특정 이전 버전이 요청되지 않는 한 API는 가장 최근 버전의 Post를 반환합니다.

루트 수준에 세 개의 새 Post 속성이 추가되었습니다:

* **edit_history** \- Post의 편집 이력과 연관된 모든 Post ID를 제공합니다. "initial\_tweet\_id" 속성은 원본 Post를 나타내며 "edit\_tweet\_ids" 속성은 편집 이력과 관련된 모든 ID를 제공하는 배열입니다. Post가 편집되지 않은 경우 이 배열에는 단일 ID가 포함됩니다.
```
"edit_history": {
    "initial\_tweet\_id": "1283764123"
    "edit\_tweet\_ids": \["1283764123"\]
  }
```
* **edit_controls** \- 30분 편집 창이 언제 종료되는지와 잠재적 편집이 몇 번 남았는지를 나타내는 속성을 제공합니다.
```
"edit_controls": {  
     "editable\_until\_ms": 1660155761384
     "edits_remaining": 3   
  }
```
* **editable** \- 생성 시 Post가 편집 대상이었는지 여부를 나타냅니다.

"editable": true

대부분의 Post는 자격이 있습니다. 그러나 다음 유형의 Post는 그렇지 않습니다:

* Post가 프로모션된 경우
* Post에 투표가 있는 경우
* Post가 non-self-thread 답글인 경우
* Post가 Retweet인 경우(Quote Tweet은 편집 가능함에 주의)
* Post가 nullcast인 경우
* Community Post
* Superfollow Post
* 협업 Post

**편집되지 않은 Post의 속성 예시**


아래 JSON은 Post 편집 기능이 추가된 후 게시된 Post에 포함되는 편집 메타데이터를 강조합니다. 이 예시는 편집 이력이 없는 Post에 대한 것입니다.

`"edit_tweet_ids"` 배열에 단일 ID가 있음에 주의하세요.

```json title="Example response" lines wrap icon="/icons/xds/icon-brackets.svg"
{
  "created_at": "Wed Aug 16 18:29:02 +0000 2022",
  "id": 1557433858676740098,
  "id_str": "1557433858676740098",
  "text": "I wonder if I will every use teh edit button",
  "edit_history": {
    "initial_tweet_id": "1557433858676740098",
    "edit_tweet_ids": ["1557433858676740098"]
  },
  "edit_controls": {
    "editable_until_ms": 1660155761384,
    "edits_remaining": 5
  },
  "editable": true
}
```

**편집된 Post의 속성 예시**

아래 JSON은 Post 편집 기능이 추가된 후 게시된 게시물에 포함되는 편집 메타데이터를 강조합니다. 이 예시는 단일 편집이 있었던 Post에 대한 것입니다.

`"edit_tweet_ids"` 배열에 원본 Post용 하나와 편집된 업데이트용 하나, 두 개의 ID가 있음에 주의하세요.

```json title="Example response" lines wrap icon="/icons/xds/icon-brackets.svg"
{
  "created_at": "Wed Aug 16 18:35:42 +0000 2022",
  "id": 1557445923210514432,
  "id_str": "1557445923210514432",
  "text": "I wonder if I will ever use the edit button",
  "edit_history": {
    "initial_tweet_id": "1557433858676740098",
    "edit_tweet_ids": ["1557433858676740098", "1557445923210514432"]
  },
  "edit_controls": {
    "editable_until_ms": 1660155761384,
    "edits_remaining": 4
  },
  "editable": true
}
```

**컴플라이언스 지원**

[Compliance Firehose](/x-api/enterprise-gnip-2.0/fundamentals/firehouse)와 v2 [배치 컴플라이언스 endpoint](/x-api/compliance/batch-compliance/introduction) 모두 Post 편집 지원을 제공하도록 업데이트되었습니다:

Compliance Firehose에 새로운 "tweet_edit" 이벤트 유형이 추가되었습니다.

```json
{
  "tweet_edit": {
    "id": <tweetId>,
    "initial_tweet_id": <tweetId>,
    "edit_tweet_ids": [<tweetId1>, <tweetId2>, <tweetId3> ...],
    "timestamp_ms": "<timestampMsStr>"
  }
}
```
