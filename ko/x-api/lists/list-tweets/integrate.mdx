이 페이지는 List Posts lookup 엔드포인트를 통합하기 위한 도구와 핵심 개념을 다룹니다.

## 유용한 도구

이 엔드포인트를 통합하는 데 도움이 되는 몇 가지 핵심 개념을 다루기 전에 다음 항목에 익숙해지실 것을 권장합니다:

### Postman

Postman은 엔드포인트를 테스트하는 데 사용할 수 있는 훌륭한 도구입니다. 각 Postman 요청에는 사용 가능한 모든 항목을 빠르게 이해할 수 있도록 모든 경로와 본문 매개변수가 포함되어 있습니다. Postman 컬렉션에 대해 자세히 알아보려면 ["Postman 사용"](/tutorials/postman-getting-started) 페이지를 참조하세요.

### 코드 샘플

원하는 코딩 언어로 이 엔드포인트를 사용하기 시작하는 데 관심이 있으신가요? [Github 페이지](https://github.com/xdevplatform/Twitter-API-v2-sample-code)에서 시작점으로 활용할 수 있는 다양한 코드 샘플을 제공합니다.

### 서드파티 라이브러리

시작하는 데 도움이 되는 커뮤니티의 [서드파티 라이브러리](/tools-and-libraries) 중 하나를 활용하세요. 올바른 버전 태그를 찾아 v2 엔드포인트에서 동작하는 라이브러리를 찾을 수 있습니다.

## 핵심 개념

### 인증

모든 X API v2 엔드포인트는 자격 증명(key와 token이라고도 함) 세트로 요청을 인증해야 합니다. 이 엔드포인트에서는 요청 인증에 OAuth 1.0a User Context, App only 또는 OAuth 2.0 Authorization Code with PKCE 중 하나를 사용할 수 있습니다.

[OAuth 1.0a User Context](/resources/fundamentals/authentication#oauth-1-0a-2)는 API Key 세트와 사용자 Access Token을 사용하여 성공적으로 요청해야 함을 의미합니다. access token은 대신 요청하려는 사용자와 연결되어 있어야 합니다. 다른 사용자를 위해 Access Token 세트를 생성하려면 해당 사용자가 [3-legged OAuth 흐름](/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow)을 사용하여 App을 인가해야 합니다.

OAuth 1.0a는 사용하기 어려울 수 있습니다. 이 인증 방식에 익숙하지 않은 경우 [라이브러리](/tools-and-libraries)를 사용하거나 Postman과 같은 도구를 사용하거나, OAuth 2.0 또는 App only 중 하나로 요청을 인증하시길 권장합니다.

[OAuth 2.0 Authorization Code with PKCE](/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2)를 사용하면 애플리케이션의 scope와 여러 기기에 걸친 인가 흐름을 더 세밀하게 제어할 수 있습니다. OAuth 2.0에서는 사용자를 대신하여 특정 권한을 부여하는 세분화된 scope를 선택할 수 있습니다.

App에서 OAuth 2.0을 활성화하려면 Developer Console의 App 설정 섹션에서 App의 인증 설정에서 활성화해야 합니다.

[App only](/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token)는 요청과 함께 [App only Access Token](/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token)을 전달하기만 하면 됩니다. developer App 내에서 직접 App only Access Token을 생성하거나 [POST oauth2/token](/resources/fundamentals/authentication#post-oauth2-token) 엔드포인트를 사용하여 생성할 수 있습니다.

### Developer Console, Project 및 developer App

X API v2 엔드포인트에서 동작하는 인증 자격 증명 세트를 검색하려면 [developer account에 가입](https://developer.x.com/en/portal/petition/essential/basic-info)하고, 해당 계정 내에 [Project](/resources/fundamentals/developer-apps)를 설정한 후, 해당 Project 내에 [developer App](/resources/fundamentals/developer-apps)을 만들어야 합니다. 그런 다음 developer App 내에서 key와 token을 찾을 수 있습니다.

### Rate limit

매일 수천 명의 개발자가 X API에 요청을 보냅니다. 이러한 요청의 방대한 양을 관리하는 데 도움이 되도록, 각 엔드포인트에는 App 또는 인증된 사용자를 대신하여 요청할 수 있는 횟수를 제한하는 [rate limit](https://developer.x.com/x-api/fundamentals/rate-limits)이 설정되어 있습니다.

이 엔드포인트는 App 수준과 사용자 수준 모두에서 rate limit이 적용됩니다. app rate limit이란 개발자가 특정 App(API Key 및 API Secret Key 또는 Bearer Token 사용을 기준으로 함)에서 지정된 기간 동안 이 엔드포인트에 특정 횟수만큼만 요청할 수 있음을 의미합니다. 사용자 rate limit이란 요청을 대신 보내는 인증된 사용자가 어떤 developer App에서도 특정 횟수만큼만 List Post lookup을 수행할 수 있음을 의미합니다.

아래 표는 각 엔드포인트의 rate limit을 보여줍니다.

| Endpoint | HTTP method | Rate limit |
| :--- | :--- | :--- |
| /2/lists/:id/tweets | GET | 15분당 900회 요청 |

### 필드 및 확장

X API v2 GET 엔드포인트에서는 `fields` 및 `expansions`라는 도구 세트를 사용하여 API에서 반환할 데이터를 정확히 선택할 수 있습니다. `expansions` 매개변수를 사용하면 페이로드에서 참조되는 객체를 확장할 수 있습니다. 예를 들어, List Posts를 조회할 때 다음 [expansion](/x-api/fundamentals/expansions)을 가져올 수 있습니다:

* `author_id`

`fields` 매개변수를 사용하면 다양한 데이터 객체 내에서 수신할 [fields](/x-api/fundamentals/fields)를 정확히 선택할 수 있습니다. 이 엔드포인트는 주로 Post 객체를 제공합니다. 기본적으로 Post 객체는 `id`와 `text` 필드를 반환합니다. `tweet.created_at` 또는 `tweet.lang`과 같은 추가 필드를 수신하려면 fields 매개변수를 사용하여 명시적으로 요청해야 합니다.

[X API v2 데이터 사전](/x-api/fundamentals/data-dictionary)에 [fields 및 expansions](/x-api/fundamentals/data-dictionary/reference#how-to-use-fields-and-expansions)를 함께 사용하는 방법에 대한 가이드를 추가했습니다.

아래 표는 lookup 엔드포인트에 대해 사용 가능한 필드 및 expansion을 보여줍니다:

| Endpoint | Fields | Expansions |
| :--- | :--- | :--- |
| /2/lists/:id/tweets | `tweet.fields`, `user.fields` | `author_id` |

### 페이지네이션

List Posts 조회는 많은 데이터를 반환할 수 있습니다. 언제든지 일관되고 성능이 좋은 결과를 반환하기 위해 페이지네이션을 사용합니다. 페이지네이션은 X API v2 엔드포인트의 기능으로, 단일 응답에서 반환할 수 있는 것보다 더 많은 결과를 반환합니다. 이 경우 데이터가 일련의 '페이지'로 반환됩니다. [결과 페이지네이션 방법](/x-api/fundamentals/pagination)에 대해 자세히 알아보세요.
