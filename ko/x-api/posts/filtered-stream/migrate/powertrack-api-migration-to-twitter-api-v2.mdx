### PowerTrack API에서 X API v2 filtered stream으로 마이그레이션

이 마이그레이션 가이드를 사용해 [PowerTrack API](/x-api/enterprise-gnip-2.0/powertrack-api)와 X API v2 [filtered stream](/x-api/posts/filtered-stream)의 공통점과 차이점을 이해하고, 현재의 PowerTrack API 통합을 v2 filtered stream으로 마이그레이션하는 데 활용하세요.

* **공통점**
    * 스트리밍 전달 방식
    * 통합 프로세스
    * 별도의 규칙 관리 엔드포인트를 갖춘 지속적인 스트림 연결
    * 규칙 구문
    * 규칙 연산자 (일부 예외 있음)
    * 규칙 매칭 로직
    * Post 편집 히스토리 및 메타데이터 지원
* **차이점**
    * 규칙 길이
    * 규칙 볼륨
    * 엔드포인트 URL
    * 접근을 위한 App 및 Project 요구사항
    * 인증 방식
    * 요청 파라미터
    * 사용량 추적
    * 다중 스트림, 이중 연결, backfill 및 Replay 복구
    * 요청 파라미터 및 응답 형식
    * 응답 JSON 데이터 구조

#### 공통점

**스트리밍 전달 방식**

PowerTrack과 X API v2 filtered stream 모두 스트리밍 데이터 전달을 사용합니다. 클라이언트는 엔드포인트에 대한 오픈 연결을 수립하고 매우 오래 지속되는 HTTP 요청을 유지한 뒤, 서버에서 오는 응답을 실시간으로 점진적으로 파싱해야 합니다. PowerTrack과 X API v2 filtered stream은 모두 실시간으로 스트림 상의 규칙과 매칭되는 공개 게시물을 필터링하고, 연결이 여전히 활성 상태임을 알리기 위해 개행 문자(\\r\\n)를 keep-alive 신호로 사용합니다. PowerTrack과 X API v2 filtered stream 엔드포인트 연결 모두 데이터를 실시간으로 전달하며, 연결된 클라이언트가 이를 신속하게 읽어야 합니다.
