### 반환된 게시물을 연결된 규칙과 매칭하기

Filtered stream 엔드포인트는 단일 연결로 여러 규칙을 적용할 수 있는 기능을 제공합니다. 스트림에서 게시물을 수신하기 전에, 관심 있는 게시물 유형을 지정하는 규칙을 만들어야 합니다.

사용자 속성, 지리적 위치, 언어 등 다양한 속성을 기반으로 게시물을 매칭하는 규칙을 지정할 때, 이 규칙을 상위 수준에서 구분하기 위한 tag를 부착할 수 있습니다. tag는 특히 규칙이 많을 때 규칙에 맥락을 부여하는 좋은 방법입니다. 필터링 규칙에 따라 어떤 게시물 액티비티가 연결을 통해 전달될지 결정됩니다.

다른 유형의 게시물을 캡처하기 위해 새 필터링 규칙을 추가하거나 기존 규칙을 제거해야 할 경우, 앱에서 [POST tweets/search/stream/rules](/x-api/stream/update-stream-rules) 엔드포인트로 요청을 보내면 됩니다. 이 요청이 전송되면 필터링 규칙이 자동으로 수정되고, 재연결 없이 데이터 스트림에 변경 사항이 그대로 적용됩니다. 대부분의 규칙 추가는 약 20초 이내에 적용됩니다. 드물지만 외부 요인(예: 네트워크 연결 상태)에 따라 매칭 게시물을 수신하기까지 더 오래 걸릴 수 있습니다. list rule 엔드포인트에서 규칙을 찾지 못한다면, 규칙 생성 요청이 성공했는지 확인하세요. 로그에서 오류 메시지가 없는지 검토하면 됩니다.


#### 매칭 규칙

액티비티가 filtered stream 연결을 통해 전달될 때, matching_rules 배열에 해당 게시물에 매칭된 필터 목록이 포함됩니다.

게시물 페이로드에는 특정 게시물이 전달되도록 만든 규칙의 id와 tag를 포함하는 추가 문자열 메타데이터가 있습니다. 여러 규칙이 하나의 게시물에 매칭될 경우, 액티비티는 한 번만 전달되며 이 메타데이터에 매칭된 각 규칙이 포함됩니다. 매칭 규칙은 특정 게시물과 특정 규칙을 손쉽게 연결하는 방법을 제공하며, 서로 다른 규칙이 많은 경우 특히 유용합니다. 이 방식에서는 데이터가 단일 스트림으로 전달되므로, 고유한 id와 tag를 확보하는 것이 매칭에 필수적입니다.

**게시물 페이로드에서 "matching_rules" 배열이 어떻게 나타나는지에 대한 예시:**
 

```json
"matching_rules": [
    {
      "id": "1166916266197536768",
      "tag": "test-rule-tag-00000"
    },
    {
      "id": "1166916266197536769",
      "tag": "test-rule-tag-12345"
    }
  ]
```

#### 임베딩 규칙 매칭

게시물이 `embedding:` 연산자를 포함하는 규칙에 매칭되면, 해당 규칙의 `matching_rules` 항목에는 두 개의 추가 필드가 포함됩니다(임베딩 기반 매칭에만 존재):

| Field | Description |
|:------|:------------|
| `embedding_similarity` | 규칙의 쿼리와 매칭된 게시물 사이의 코사인 유사도 점수(0.0–1.0). |
| `embedding_threshold` | 적용된 임계값(사용자가 설정한 값 또는 기본값 `0.3`). |

임베딩 매칭에 대한 페이로드 예시:

```json title="예시 응답" lines wrap icon="/icons/xds/icon-brackets.svg"
{
  "data": {
    "id": "1784600000000000001",
    "text": "The new carbon tax proposal could reshape how industries approach emissions..."
  },
  "matching_rules": [
    {
      "id": "1784567890123456789",
      "tag": "climate-semantic",
      "embedding_similarity": 0.4523,
      "embedding_threshold": 0.4
    }
  ]
}
```

keyword, `from:`, `has:` 및 기타 임베딩이 아닌 규칙의 경우 `matching_rules` 항목에는 `id`와 `tag`만 포함됩니다.

#### 규칙 tag

각 필터링 규칙은 생성 시 tag와 함께 만들어질 수 있습니다. 규칙 tag는 특별한 의미를 지니지 않으며, 규칙과 함께 전달되는 불투명 문자열로 취급됩니다. 반환되는 액티비티의 matching_rules 메타데이터에 포함되며, 상위 수준에서 규칙을 구분하기 쉽게 하는 것을 목적으로 합니다.

Tag는 필터링 규칙의 논리적 그룹화를 손쉽게 만드는 방법을 제공합니다. 예를 들어 특정 규칙에 고유 ID를 tag로 생성하고, 앱이 처리하는 액티비티 내에서 해당 ID를 참조하여 결과를 특정 고객, 캠페인, 카테고리 또는 기타 관련 그룹과 연관 지을 수 있습니다.

기존 규칙의 tag는 업데이트할 수 없으며, 규칙 생성 시에만 포함할 수 있습니다. tag를 "업데이트"하거나 "이름 변경"하려면 먼저 규칙을 삭제한 뒤 원하는 tag로 다시 추가해야 합니다. 가장 좋은 해결책은 tag로 고유 식별자를 사용하는 것입니다. 이렇게 하면 규칙 세트를 변경하지 않고도 시스템에서 자체 앱 내의 다양한 데이터 포인트와 연관 지을 수 있습니다.
