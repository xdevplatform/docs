### 주제별로 답글 관리하기

Hide replies 엔드포인트를 통해 사용자와 브랜드가 대화 주제를 유지하도록 돕는 통합을 구축할 수 있습니다. 이 페이지에서는 hide replies와 [recent search](/x-api/posts/recent-search) 엔드포인트로 대화를 관리하는 방법을 보여줍니다.

Recent search에는 대화와 그 답글을 다루는 기능이 있으며, Post 페이로드는 언어에 관계없이 각 게시물의 컨텍스트와 주제를 이해하는 데 도움이 되는 [Post annotations](/x-api/fundamentals/post-annotations)를 반환합니다.

앱의 흐름에는 대화를 표시하고 관리하기 위한 제어가 포함됩니다:

1.  사용자에게 게시물을 읽고 답글을 관리할 권한을 요청합니다.
2.  Post URL에서 최근 대화를 가져오고, 대화가 인증 사용자로부터 시작되었는지 확인합니다.
3.  recent search 엔드포인트를 호출해 대화의 각 게시물을 표시합니다. 요청에는 conversation ID 검색 쿼리와 annotation expansion이 포함되어, X의 게시물 해석에 따라 게시물이 스포츠 관련인지 여부를 판단합니다.
4.  사용자가 선택하면 Hide replies를 호출해 답글을 숨깁니다. 사용자가 언제든지 제어할 수 있도록 이 동작을 취소하는 방법도 제공합니다.

5.  더 긴 대화의 경우 [검색 결과 페이지네이션](/x-api/posts/search/integrate/paginate) 컨트롤을 제공합니다.
     

#### 사용자(및 사용량)에 맞게 최적화

사용자가 취하려는 모든 동작을 사용자가 통제할 수 있는 방식으로 흐름을 설계할 수 있습니다. 이 원칙을 유지하면 게시물 소비를 위한 최적화된 통합을 구축하는 데도 도움이 됩니다.

1.  인증된 사용자는 자신이 시작한 대화만 관리할 수 있으므로, 그렇지 않은 경우 흐름을 조기에 종료해야 합니다.
    * 초기 Post lookup 요청을 수행합니다. Post URL이 유효하지 않거나 대화가 인증 사용자에 의해 시작되지 않은 경우 흐름을 조기에 종료합니다.
    * 이렇게 하면 인증된 사용자가 대화를 모더레이션할 수 없는 경우 앱이 recent search 요청을 만들 필요가 없습니다.
2.  별도의 요청을 만들지 않도록 동일한 요청에서 [user 및 Post 필드](/x-api/fundamentals/fields)를 요청합니다. 이 방식은 앱 성능도 향상시킬 수 있습니다.
3.  필요할 때만 요청을 만듭니다. 이 앱은 답글의 숨김 상태를 사용자의 브라우저에 캐시합니다. 이는 사용자가 나중에 모더레이션 작업을 이어가고자 할 수 있는 더 큰 대화에서 유용하며, 답글 숨기기/해제 요청을 최적화하는 데 도움이 됩니다.
