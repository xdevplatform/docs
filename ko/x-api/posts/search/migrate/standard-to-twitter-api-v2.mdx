### Standard v1.1과 X API v2 비교

v1.1 [search/posts](/x-api/posts/search/introduction)를 사용해 왔다면, 이 가이드의 목표는 standard와 X API v2 search Posts 엔드포인트의 공통점과 차이점을 이해하도록 돕는 것입니다.

* **공통점**
    * OAuth 1.0a User Context 및 OAuth 2.0 App-Only
    * Post 편집 히스토리 및 메타데이터 지원
* **차이점**
    * 엔드포인트 URL
    * App 및 Project 요구사항
    * 응답 데이터 형식
    * 요청 파라미터
    * 새로운 쿼리 연산자

    * AND / OR 연산자 우선순위

#### 공통점

**OAuth 1.0a User Context 및 OAuth 2.0 App-Only 인증**

v1.1 search/posts와 X API v2 recent search 엔드포인트는 [OAuth 1.0a User Context](/resources/fundamentals/authentication)와 [OAuth 2.0 App-Only](/resources/fundamentals/authentication#oauth-2-0)를 모두 지원합니다.

따라서 이전에 standard v1.1 search 엔드포인트를 사용하고 있었다면, X API v2 버전으로 마이그레이션하더라도 동일한 인증 방식을 계속 사용할 수 있습니다.

선택한 인증 라이브러리/패키지에 따라 다르지만, App-Only 인증이 시작하기 가장 쉬운 방법이며 간단한 요청 헤더로 설정할 수 있습니다. App Access Token 생성 방법은 [이 OAuth 2.0 App-Only 가이드](/resources/fundamentals/authentication#bearer-token-also-known-as-app-only)를 참고하세요.

X API v2 엔드포인트에서 비공개 또는 광고 지표를 가져오는 기능을 활용하려면, OAuth 1.0a User Context를 사용하고 지표를 가져오려는 게시물을 작성한 사용자와 관련된 user access token을 전달해야 합니다.


**Post 편집 히스토리 및 메타데이터 지원**

두 버전 모두 편집 히스토리를 설명하는 메타데이터를 제공합니다. 자세한 내용은 [search API 레퍼런스](/x-api/posts/recent-search)와 [Post 편집 기본 페이지](/x-api/fundamentals/edit-posts)를 참고하세요.
