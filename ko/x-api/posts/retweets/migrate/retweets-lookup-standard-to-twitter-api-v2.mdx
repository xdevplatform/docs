### Retweets lookup: Standard v1.1과 X API v2 비교

standard v1.1 [v1.1 GET statuses/retweets/:id](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-retweets-id), [v1.1 GET statuses/retweets/:ids](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-retweeters-ids)를 사용해 왔다면, 이 가이드의 목표는 standard v1.1과 X API v2 Retweets lookup 엔드포인트의 공통점과 차이점을 이해하도록 돕는 것입니다.

* **공통점**
    * 인증
    * 요청당 사용자 수 제한
* **차이점**
    * 엔드포인트 URL

    * 요청 제한
    * App 및 Project 요구사항

    * 응답 데이터 형식
    * 요청 파라미터

#### 공통점

**인증**

standard v1.1과 X API v2 Retweets lookup 엔드포인트([v1.1 GET statuses/retweets/:id](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-retweets-id) 및 [v1.1 GET statuses/retweeters/:ids](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-retweeters-ids))는 모두 [OAuth 1.0a User Context](https://developer.x.com/content/developer-twitter/resources/fundamentals/authentication) 또는 OAuth 2.0 Bearer Token을 사용합니다.

**요청당 사용자 수 제한**

v1.1과 v2 GET 엔드포인트 모두 Retweets lookup 엔드포인트에서 반환되는 최대 사용자 수는 100명입니다. v2 Retweets lookup 엔드포인트에는 pagination token이 전달되지 않으며, 기본적으로 100명의 사용자를 제공하고 이것이 반환되는 최대치입니다.

#### 차이점
**엔드포인트 URL**

* Standard v1.1 엔드포인트:
    * https://api.x.com/1.1/statuses/retweets/:id.json
        (가장 최근 100개의 컬렉션을 반환합니다
