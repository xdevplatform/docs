### Manage mutes: standard v1.1과 X API v2 비교

standard v1.1의 [POST mutes/users/create](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/mute-block-report-users/api-reference/post-mutes-users-create) 및 [POST mutes/users/destroy](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/mute-block-report-users/api-reference/post-mutes-users-destroy) 엔드포인트를 사용해 왔다면, 이 가이드는 standard v1.1과 X API v2의 manage mutes 엔드포인트 사이의 유사점과 차이점을 이해하는 데 도움이 될 것입니다.

* **유사점**
    * OAuth 1.0a User Context
* **차이점**
    * 엔드포인트 URL
    * App 및 Project 요구사항
    * HTTP 메서드
    * 요청 매개변수


#### 유사점

**OAuth 1.0a User Context 인증 방식**

두 엔드포인트 버전 모두 [OAuth 1.0a User Context](https://developer.x.com/content/developer-twitter/resources/fundamentals/authentication)를 지원합니다. 따라서 이전에 standard v1.1 manage mutes 엔드포인트 중 하나를 사용했다면 X API v2 버전으로 마이그레이션할 때도 동일한 인증 방식을 계속 사용할 수 있습니다.

#### 차이점

**엔드포인트 URL**

* Standard v1.1 엔드포인트:
    * POST https://api.x.com/1.1/mutes/users/create.json
        (사용자 뮤트)
    * POST https://api.x.com/1.1/mutes/users/destroy.json
        (사용자 뮤트 해제)
* X API v2 엔드포인트:
    * POST https://api.x.com/2/users/:id/muting
        (사용자 뮤트)
    * DELETE https://api.x.com/2/users/:source\_user\_id/muting/:target\_user\_id
        (사용자 뮤트 해제)

**App 및 Project 요구사항**

X API v2 엔드포인트는 요청을 인증할 때 [Project와 연결된 [developer App](/resources/fundamentals/developer-apps)의 자격 증명을 사용해야 합니다.
