## 개요

filtered stream 엔드포인트 그룹은 개발자가 공개 Post 스트림을 필터링할 수 있게 합니다. 이 엔드포인트 그룹의 기능에는 규칙을 만들고 관리하며, 이러한 규칙을 적용하여 일치하는 공개 Post를 반환하는 Post 스트림을 필터링할 수 있는 여러 엔드포인트가 포함됩니다. 이 엔드포인트 그룹을 사용하면 사용자가 특정 주제와 이벤트를 청취하고, 대회 관련 대화를 모니터링하며, 트렌드가 어떻게 발전하는지 이해하는 등 많은 것을 할 수 있습니다.

개발자는 REST [rules 엔드포인트](/x-api/stream/get-stream-rules)를 사용하여 정의된 조건과 일치하는 Post를 필터링하기 위한 규칙을 추가하고 제거할 수 있습니다. 이러한 [규칙](/x-api/posts/filtered-stream/integrate/build-a-rule)은 메시지 키워드, 해시태그, URL과 같은 Post 속성에 매칭되는 연산자로 생성할 수 있습니다. 연산자와 규칙 절은 부울 논리 및 괄호와 결합하여 필터의 매칭 동작을 개선할 수 있습니다.

규칙 집합을 추가한 후에는 웹훅을 등록하면 X가 [Post 객체](/x-api/fundamentals/data-dictionary/reference#tweet)를 JSON 형식으로 전달하기 시작합니다. 규칙과 일치하는 콘텐츠만 웹훅으로 수신됩니다.

이 엔드포인트는 편집된 Post를 지원합니다. 여러분의 웹훅은 하나 이상의 필터와 일치하는 편집된 Post와 함께 Post ID 배열을 포함한 편집 기록을 수신합니다. 편집 기록이 없는 Post의 경우 이 배열은 단일 ID를 갖습니다. 편집된 Post의 경우 이 배열에는 편집 순서를 반영하여 오름차순으로 배열된 여러 ID가 포함되며, 가장 최근 버전이 배열의 마지막 위치에 있습니다. Post 편집이 작동하는 방식에 대해 자세히 알아보려면 [Posts edits 기본](/x-api/fundamentals/edit-posts) 페이지를 참조하세요.

**참고:** 이 엔드포인트 그룹은 규칙 설정 측면에서 [v2 filtered stream 엔드포인트](/x-api/posts/filtered-stream/introduction)와 유사합니다. 유일한 차이점은 규칙과 일치하는 Post의 전달 메커니즘입니다.
* v2 filtered stream 엔드포인트의 경우 지속적인 연결을 설정하고 규칙과 일치하는 Post를 청취해야 합니다.
* 이 filtered stream webhook 엔드포인트의 경우 웹훅을 등록하면 X가 규칙과 일치하는 Post를 웹훅으로 전달합니다.

이렇게 하면 클라이언트 드롭이나 일반적인 재시작으로 인한 서버 측 드롭에서 발생하는 연결 해제를 처리할 필요가 없어집니다. 초당 수백 건의 이벤트를 전달할 가능성이 높으므로, 웹훅 서버는 이러한 동시 연결 시도를 처리할 수 있어야 합니다.

이 엔드포인트는 현재 Enterprise 개발자에게 제공되며 다음 구성을 지원합니다:

* 프로젝트당 25,000개 이상의 규칙
* 규칙을 만들 때 모든 연산자 사용 가능
* 최대 2048자 길이의 규칙 작성 가능
* Enterprise 액세스는 [여기](/forms/enterprise-api-interest)에서 신청

filtered stream에서 반환된 Post는 월별 [Post cap](/x-api/fundamentals/post-cap)에 포함됩니다.
