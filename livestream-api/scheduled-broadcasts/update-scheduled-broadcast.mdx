Updates a scheduled broadcast that hasn't started yet. `:id` is the alphanumeric `broadcast_id`, while the body's required `scheduled_broadcast_id` is the numeric scheduler ID (from create, list, or get).

## Required fields

`scheduled_broadcast_id`, `scheduled_start_ms` and `scheduled_end_ms` are required in every request. To keep the current times, resend them unchanged. Send `scheduled_end_ms` as `"0"` for an open-ended broadcast.

Every other field is optional. Fields you don't send keep their current values.

## Schedule rules

The [create rules](/livestream-api/scheduled-broadcasts/create-scheduled-broadcast#schedule-rules) apply: the start must be in the future, a broadcast with an end lasts 1 minute to 24 hours, and broadcasts on the same source can't overlap. Updating a broadcast that has already started returns `400`.

## Source

`source_id` is the source id of one of your [stream sources](/livestream-api/sources/overview), from [Get Sources](/livestream-api/sources/get-sources). Passing a stream key as `source_id` is deprecated and stops working on **January 1, 2027**; see the [migration guide](/livestream-api/migration-guide). The response returns `source_id` as the source id.

<Note>
Recurring schedules are retired. A request with `roll_forward` set to `true` returns `400`.
</Note>
