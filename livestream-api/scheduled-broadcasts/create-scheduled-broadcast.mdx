Schedules a broadcast on one of the authenticated user's sources. The response returns `201 Created` with the new scheduled broadcast.

## Required fields

`source_id` and `scheduled_start_ms` are required.

- `source_id` is the source id of one of your [stream sources](/livestream-api/sources/overview): its `id` from [Get Sources](/livestream-api/sources/get-sources). The response returns `source_id` as the source id.
- `scheduled_start_ms` is the scheduled start time, Unix epoch milliseconds as a decimal string. It must be in the future.

<Warning>
Passing a stream key as `source_id` is deprecated and stops working on **January 1, 2027**. Pass the source id instead. See the [migration guide](/livestream-api/migration-guide).
</Warning>

## Schedule rules

- The start time must be in the future.
- With `scheduled_end_ms`, the broadcast must last between 1 minute and 24 hours. Omit `scheduled_end_ms` for an open-ended broadcast.
- Scheduled broadcasts on the same source can't overlap. For this check, an open-ended broadcast occupies the minute after its start, so open-ended broadcasts on one source must start at least 1 minute apart.

A request that breaks one of these rules returns `400`. The error message starts with the reason, such as `start_in_past`, `invalid_period` or `schedule_conflict`.

## Publishing behavior

Set `manual_publish` to `true` when you want to publish explicitly with [`POST /2/broadcasts/scheduled/:id/live`](/livestream-api/scheduled-broadcasts/go-live). Otherwise, the scheduler publishes automatically at `scheduled_start_ms`.

## Optional fields

- `scheduled_end_ms` sets the scheduled end time as Unix epoch milliseconds. If omitted, the broadcast has no scheduled end and runs until it is stopped or ends manually.
- `title` and `description` set the broadcast's status text and description.
- `thumbnail_media_id` is a numeric media ID used as the pre-live slate image.
- `chat_option` controls chat permissions and is a numeric string.
- `available_for_replay` enables replay after the broadcast ends.
- `is_locked` locks the broadcast.
- `locale` sets the broadcast's locale.

<Note>
Recurring schedules are retired. A request that includes `recurrence` returns `400`; create each occurrence as its own scheduled broadcast. `telecast_id` is ignored.
</Note>

## Example

```json
{
  "source_id": "9123456789012345678",
  "scheduled_start_ms": "1784000000000",
  "scheduled_end_ms": "1784003600000",
  "title": "Product launch",
  "description": "Live from our launch event",
  "available_for_replay": true,
  "manual_publish": true
}
```

<Tip>
Save both `broadcast_id` (alphanumeric, used in endpoint paths) and `scheduled_broadcast_id` (numeric, required in the body of [update requests](/livestream-api/scheduled-broadcasts/update-scheduled-broadcast)).
</Tip>
