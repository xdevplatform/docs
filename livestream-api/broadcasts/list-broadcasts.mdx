**Endpoint:** `GET /2/users/:user_id/broadcasts`

<Warning>
**This route is deprecated.** Use [`GET /2/broadcasts`](/livestream-api/broadcasts/get-broadcasts) instead, which omits the user ID from the path, supports OAuth 2.0 user context, and adds bulk lookup by `ids`. Ownership is still enforced through the authenticated user context.
</Warning>

Supports cursor pagination.

## Query parameters

| Name | Type | Required | Description |
|:-----|:-----|:---------|:------------|
| `pagination_token` | string | No | `next_token.offset` from a prior response. Omit it, or send it empty, for the first page. |

Other query parameters are ignored.

## Response (example)

```json
{
  "broadcasts": [
    { ...broadcast object... }
  ],
  "next_token": { "offset": "..." }
}
```

Returns up to **100 broadcasts per page** (the page size is fixed and not client-configurable). `next_token` is present only when there is another page; pass its `offset` as `pagination_token` to fetch it. Pagination is forward-only: there is no previous-page token.

Broadcasts that were created but never published aren't listed. See the [broadcast object](/livestream-api/broadcasts/overview#broadcast-object) for the fields of each item.

Accounts that aren't eligible to broadcast get `412` with `error_type: "preconditionFailed"`.
