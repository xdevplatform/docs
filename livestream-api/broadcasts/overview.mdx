Broadcasts are ephemeral sessions tied to a source. A broadcast starts in `NOT_STARTED`, moves to `RUNNING` when published, and ends in `ENDED` (or another terminal state).

## Broadcast states

| State | Meaning |
|:------|:--------|
| `NOT_STARTED` | Created but not yet live. Initial state returned by Create Broadcast. |
| `PRE_PUBLISHED` | Transitional state while the broadcast is being prepared to go live. |
| `RUNNING` | Live and publicly visible. Set after a successful `PUBLISH`. |
| `ENDED` | Finished normally after `END`. Terminal — a broadcast cannot be restarted. |
| `TIMED_OUT` | Terminal. The broadcast was not published in time, or ingest stopped before it went live. |
| `CANCELED` | Terminal. The broadcast was canceled before or during its lifecycle. |

The only transitions you trigger directly are `NOT_STARTED` → `RUNNING` (via `PUBLISH`) and `RUNNING` → `ENDED` (via `END`). The remaining states are set by the platform.

<Note>
A source doesn't need to be receiving video to create or publish a broadcast. Publishing makes the broadcast `RUNNING` right away, and video appears once your encoder is sending to the source. Start your encoder before or right after publishing.
</Note>

A broadcast that is created but never published isn't listed by List Broadcasts and is deleted after 7 days.

## Eligibility

The broadcasting account must be allowed to go live on X. For accounts that aren't, List Broadcasts returns `412` ("Listing broadcasts requires X Premium or more than 1,000 followers.") and Create Broadcast returns `412` ("This account can't create broadcasts."), both with `error_type: "preconditionFailed"`.

## Broadcast object

| Field | Description |
|:------|:------------|
| `id`, `broadcast_id` | Broadcast ID (the same value). |
| `media_key`, `media_id` | Media identifiers, used for [chat access](/livestream-api/chat/accessing-live-chat). |
| `state` | See [Broadcast states](#broadcast-states). |
| `status` | Broadcast title. |
| `twitter_user_id` | Numeric X user ID of the broadcaster, as a string. |
| `created_at_ms`, `updated_at_ms`, `start_ms`, `end_ms` | Timestamps in milliseconds since the Unix epoch, as strings. `start_ms` and `end_ms` appear once the broadcast has gone live or ended. |
| `chat_option` | Who can chat; see [chat option values](/livestream-api/broadcasts/publish-or-end-broadcast#chat-option-values). |
| `language` | Broadcast language, when a `locale` was sent at publish. |
| `height`, `width` | Video dimensions in pixels. |
| `available_for_replay` | Whether a replay is available. |
| `is_high_latency` | Informational latency flag. |
| `image_url`, `image_url_medium`, `image_url_small` | Thumbnails. A placeholder image until video arrives. |
| `total_watching`, `total_watched` | Live and cumulative viewer counts, as strings. |
| `tweet_id` | The announcement post, once it exists. |

<Note>
Broadcast objects no longer include `user_id`, `username`, `twitter_username`, `user_display_name`, `profile_image_url`, `has_location`, `lat`, `lng`, `friend_chat`, `private_chat`, `is_locked`, `has_moderation`, `no_hearts`, `camera_rotation`, `ping_ms`, `version`, `broadcast_source` or `unavailable_in_periscope`. Use [`GET /2/users/me`](/x-api/users/get-my-user) for the broadcaster's profile.
</Note>

## Errors

Invalid parameters return `400` in the standard X API problem format. Other errors return a `{ "error_type", "message" }` body:

| Status | `error_type` | Example |
|:-------|:-------------|:--------|
| 400 | `badRequest` | The request can't be applied to the broadcast in its current state. |
| 403 | `forbidden` | The account isn't permitted to perform the action. |
| 404 | `notFound` | The broadcast or source doesn't exist or belongs to another user. |
| 412 | `preconditionFailed` | The account isn't eligible to broadcast. |
| 503 | `serviceUnavailable` | Temporary failure; retry with backoff. |

## Endpoints

| Endpoint | Method & Path | New Method & Path |
|:---------|:--------------|:------------------|
| Create Broadcast | [`POST /2/users/:user_id/broadcasts`](/livestream-api/broadcasts/create-broadcast) | — |
| List Broadcasts | [`GET /2/users/:user_id/broadcasts`](/livestream-api/broadcasts/list-broadcasts) | [`GET /2/broadcasts`](/livestream-api/broadcasts/get-broadcasts) |
| Get Broadcast | [`GET /2/users/:user_id/broadcasts/:broadcast_id`](/livestream-api/broadcasts/get-broadcast) | [`GET /2/broadcasts/:id`](/livestream-api/broadcasts/get-broadcast-by-id) |
| Publish or End a Broadcast | [`PUT /2/users/:user_id/broadcasts/:broadcast_id/state`](/livestream-api/broadcasts/publish-or-end-broadcast) | — |
| Delete Broadcast | [`DELETE /2/users/:user_id/broadcasts/:broadcast_id`](/livestream-api/broadcasts/delete-broadcast) | — |

All routes accept both OAuth 2.0 and OAuth 1.0a [user context authentication](/livestream-api/authentication). The new routes (those without `user_id` in the path) are the recommended routes and return additional fields (for example, field selection with `broadcast.fields`).

<Note>
The original routes are being replaced over time. Where a new route is listed, use it in place of the original; the original route is deprecated and may be removed in a future release. Additional replacement routes will be added to the table above as they become available.
</Note>

<Note>
To schedule a broadcast in advance — one-time or recurring, with automatic or manual publishing — see the [Livestream Scheduling API](/livestream-api/scheduled-broadcasts/overview).
</Note>
