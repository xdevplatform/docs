Para admitir un mayor número de campañas y una recuperación eficiente de todas las entidades asociadas a una cuenta, la Advertiser API ahora admite paginación en muchos endpoints GET. El mecanismo de paginación es fácil de usar y muy similar a la paginación basada en cursor de la REST API descrita en [Using cursors to navigate collections](https://developer.x.com/en/docs/x-api/v1/pagination).

## Empezando

Para las solicitudes GET designadas, ahora aceptamos los parámetros de consulta `cursor` y `count`, ambos opcionales. Si una respuesta tiene más de `count` entidades, estos endpoints ahora devolverán las primeras `count` entidades y una clave `next_cursor` en el JSON de respuesta.

`GET https://ads-api.x.com/5/accounts/abc1/campaigns?count=50`

```json
{
  "data": \[...\],
  "next_cursor": "c-3yvu1pzhd3i7",
  "request": {...}
}
```

Para obtener la siguiente serie de respuestas, añadirías `cursor` a tus parámetros de consulta:

`GET https://ads-api.x.com/5/accounts/abc1/campaigns?cursor=c-3yvu1pzhd3i7&count=50`

```json
{
  "data": \[...\],
  "next_cursor": "c-3w3zdyg8ywan",
  "request": {...}
}
```
## Yendo más profundo

Para la mayoría de los endpoints, el valor máximo de `count` es **1000**, el mínimo es **1** y el predeterminado es **200**.

El valor proporcionado por `next_cursor` es siempre un string y debe considerarse opaco; la implementación está sujeta a cambios. Si se devuelven menos de `count` entidades en la página actual del conjunto de resultados, el valor de `next_cursor` será `null`.

**Nota:** los endpoints de analytics no admiten este estilo de paginación. La paginación en los endpoints de estadísticas se admite especificando periodos de tiempo. Consulta la documentación de esos endpoints individuales para más información.
