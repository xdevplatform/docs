Los endpoints enterprise se han actualizado para proporcionar metadatos de Posts editados. La funcionalidad de _Editar Posts_ se introdujo por primera vez para pruebas entre empleados de X el 1 de septiembre de 2022. A partir de esa fecha, los Posts elegibles podían editarse durante 30 minutos y hasta 5 veces. _Todos los objetos para Posts creados desde el 29 de septiembre de 2022_ incluyen metadatos de edición de Posts, incluso si el Post nunca fue editado. Cada vez que se edita un Post, se crea un nuevo ID de Post. El historial de edición de un Post se puede describir encadenando estos IDs, comenzando con el ID original. Además, si se elimina cualquier Post en la cadena de edición, todos los Posts de esa cadena también se eliminan.

Estos detalles de metadatos se incluyen automáticamente. No se necesitan parámetros de solicitud para incluir el historial de edición disponible como parte del objeto Post.

Con estos nuevos metadatos, un desarrollador puede averiguar:

* Si un Post era elegible para edición en el momento de su creación. Algunos Posts, como los que tienen encuestas o los Posts programados, no pueden editarse.
* Los Posts pueden editarse durante 30 minutos y se pueden editar hasta 5 veces. Para los Posts editables, puedes ver si queda tiempo para editar y cuántas ediciones más son posibles.
* Si estás viendo una versión editada de un Post. En la mayoría de los casos, la API devolverá la versión más reciente de un Post, a menos que se solicite una versión pasada específica por ID de Post.

Se han agregado tres nuevos atributos de Post en el nivel raíz:

* **edit_history**  \- Proporciona todos los IDs de Post asociados con el historial de edición del Post. El atributo "initial\_tweet\_id" indica el Post original y el atributo "edit\_tweet\_ids" es un array que proporciona todos los IDs asociados con su historial de edición. Si el Post no ha sido editado, este array contendrá un único ID.
```
"edit_history": {
    "initial\_tweet\_id": "1283764123"
    "edit\_tweet\_ids": \["1283764123"\]
  }
```
* **edit_controls** \- Proporciona atributos que indican cuándo termina la ventana de edición de 30 minutos y cuántas ediciones potenciales quedan.
```
"edit_controls": {  
     "editable\_until\_ms": 1660155761384
     "edits_remaining": 3   
  }
```
* **editable** \- Indica si un Post era elegible para edición cuando se creó.

"editable": true

La mayoría de los Posts son elegibles. Sin embargo, los siguientes tipos de Posts no lo son:

* Post promocionado
* Post con encuesta
* Post que es una respuesta que no es un self-thread
* Post que es un Retweet (ten en cuenta que los Quote Tweets son elegibles para edición)
* Post que es nullcast
* Post de Comunidad
* Post de Superfollow
* Post colaborativo

**Ejemplo de atributos para un Post no editado**


El JSON siguiente resalta los metadatos de edición que se incluyen para un Post publicado después de que se añadió la función de editar Post. Este ejemplo es para un Post que no tiene historial de edición.

Ten en cuenta que el array `"edit_tweet_ids"` tiene un único ID.

```json title="Ejemplo de respuesta" lines wrap icon="/icons/xds/icon-brackets.svg"
{
  "created_at": "Wed Aug 16 18:29:02 +0000 2022",

  },
  "edit_controls": {
    "editable_until_ms": 1660155761384,
    "edits_remaining": 5
  },
  "editable": true
}
```

**Ejemplo de atributos para un Post editado**

El JSON siguiente resalta los metadatos de edición que se incluyen para un post publicado después de que se añadió la función de editar Post. Este ejemplo es para un Post que ha tenido una única edición.

Ten en cuenta que el array `"edit_tweet_ids"` tiene dos IDs, uno para el Post original y otro para la actualización editada.

```json title="Ejemplo de respuesta" lines wrap icon="/icons/xds/icon-brackets.svg"
    "editable_until_ms": 1660155761384,

  },
  "editable": true

```

**Soporte de cumplimiento**

Tanto el [Compliance Firehose](/x-api/enterprise-gnip-2.0/fundamentals/firehouse) como el [endpoint batch compliance](/x-api/compliance/batch-compliance/introduction) de v2 se han actualizado para brindar soporte a la edición de Posts:

Se ha añadido un nuevo tipo de evento "tweet_edit" al Compliance Firehose.

```json
{
  "tweet_edit": {
    "id": <tweetId>,
    "initial_tweet_id": <tweetId>,
    "edit_tweet_ids": [<tweetId1>, <tweetId2>, <tweetId3> ...],
    "timestamp_ms": "<timestampMsStr>"
  }
}
```
