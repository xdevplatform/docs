## Descripción general

[Enterprise](https://developer.x.com/en/products/x-api/enterprise)

_Esta es una API enterprise disponible únicamente dentro de nuestros niveles de acceso gestionado. Para usar esta API, primero debes configurar una cuenta con nuestro equipo de ventas enterprise. [Más información](https://developer.x.com/en/products/x-api/enterprise)_

_Puedes ver todas las ofertas de filtered stream de la X API [AQUÍ](/x-api/posts/filtered-stream)._

La PowerTrack API brinda a los clientes la capacidad de filtrar el firehose completo de X y recibir únicamente los datos en los que ellos o sus clientes están interesados. Esto se logra aplicando el lenguaje de filtrado de PowerTrack — consulta [Reglas y filtrado](/x-api/enterprise-gnip-2.0/fundamentals/rules-filtering) \- para hacer coincidir Posts según una amplia variedad de atributos, incluyendo atributos de usuario, geolocalización, idioma y muchos otros. Usar reglas de PowerTrack para filtrar Posts asegura que los clientes reciban todos los datos, y _solo_ los datos que necesitan para tu app.


### Componentes principales

La PowerTrack API consta de dos endpoints:

#### Endpoint de reglas

Un endpoint separado gestionado independientemente por tu aplicación, el endpoint de reglas admite los métodos GET, POST, POST _method=delete y de validación de reglas con autenticación básica para gestionar tu conjunto de reglas. Puede admitir miles de reglas que te permiten filtrar el stream de datos en tiempo real por los temas y conversaciones que te interesan. Al endpoint de reglas se puede acceder, gestionarlo y persistirá independientemente de tu estado de conexión al stream — también puedes actualizar (añadir/eliminar) reglas mientras estás conectado al stream y los cambios surtirán efecto casi de inmediato.

#### Endpoint del stream

Conectarse al endpoint de streaming consiste en una simple solicitud [GET](/x-api/enterprise-gnip-2.0/powertrack-api#powertrack-api) usando autenticación básica. Una vez establecida la conexión, los datos se entregan en formato JSON (ver la carga útil de ejemplo a continuación) a través de una conexión HTTP Streaming persistente. Solo recibirás datos que coincidan con tus reglas mientras estés conectado al stream.

#### Tags de reglas

Un único stream de PowerTrack puede admitir miles de reglas, por lo que poder distinguir qué regla(s) coincidieron con un Post dado se vuelve importante. Esto se resuelve fácilmente usando tags de reglas. Al crear una regla, puedes asignar un valor de tag que se devolverá en el objeto matching_rules ([ver aquí](/x-api/enterprise-gnip-2.0/fundamentals/data-enrichments#matching-rules)) de la carga útil de respuesta.

Los tags de reglas pueden representar un caso de uso de cliente final, un tema o conversación, u otro identificador útil que puedes usar para enrutar los Posts entrantes en consecuencia.

Si, además de datos en tiempo real, tu producto también requiere acceso instantáneo a datos recientes, recomendamos usar nuestra [Search API](/x-api/enterprise-gnip-2.0/fundamentals/search-api).

## Guías
### Integración con PowerTrack

Para integrar PowerTrack en tu producto, necesitarás construir una aplicación que pueda hacer lo siguiente:

1.  Establecer una conexión de streaming a la stream API de PowerTrack.
2.  Enviar de forma asíncrona solicitudes POST a la rules API de PowerTrack para añadir y eliminar reglas del stream.
3.  Gestionar volúmenes bajos de datos — Mantener la conexión de streaming y asegurar que los buffers se vacíen regularmente.
4.  Gestionar volúmenes altos de datos — desacoplar la ingesta del stream del procesamiento adicional usando procesos asíncronos.
5.  Reconectarse al stream automáticamente cuando se desconecte por cualquier motivo.

Para detalles sobre los tipos de solicitudes necesarias para las tareas 1 y 2, y consideraciones importantes al implementarlas, consulta la [referencia de la API](/x-api/enterprise-gnip-2.0/powertrack-api#api-reference-index).

### Reglas y filtrado

PowerTrack mejora la capacidad de filtrar el firehose completo de X y recibir únicamente los datos en los que ellos o sus clientes están interesados. Esto se logra aplicando el lenguaje de filtrado de PowerTrack para hacer coincidir Posts según una amplia variedad de atributos, incluyendo atributos de usuario, geolocalización, idioma y muchos otros. Usar reglas de PowerTrack para filtrar una fuente de datos asegura que los clientes reciban todos los datos, y _solo_ los datos que necesitan para tu app.

Como se ha descrito, los clientes agregan reglas de filtrado al stream de PowerTrack para determinar qué actividades se enviarán a través de la conexión. El stream de PowerTrack puede admitir miles de estas reglas individuales, y entregar el conjunto combinado de actividades coincidentes a través de la única conexión del stream.

El conjunto de reglas de PowerTrack utilizadas para filtrar el stream de un cliente es altamente flexible. Si un cliente necesita agregar una nueva regla de filtrado para capturar un tipo diferente de contenido, o eliminar una regla existente, su app puede enviar una solicitud a la PowerTrack API para hacerlo. Cuando se envía esa solicitud, las reglas de filtrado se modifican automáticamente y los cambios simplemente surten efecto en el stream de datos sin necesidad de reconectarse. Esto permite a los clientes proporcionar datos a muchos clientes a escala, mientras admiten requisitos de filtrado distintos para cada uno de esos clientes.
