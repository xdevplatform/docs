## Standard v1.1 comparado con X API v2

Si has estado trabajando con los endpoints estándar v1.1 [POST statuses/update](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/post-statuses-update) y [POST statuses/destroy/:id](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/post-statuses-destroy-id), el objetivo de esta guía es ayudarte a entender las similitudes y diferencias entre los endpoints estándar y los de X API v2 manage Posts.

* **Similitudes**
    * Autenticación
* **Diferencias**
    * URLs de endpoint
    * Requisitos de App y Project

    * Parámetros de solicitud


### Similitudes

**Autenticación**

Tanto los endpoints estándar v1.1 como los de X API v2 manage Posts ([POST statuses/update](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/post-statuses-update) y [POST statuses/destroy/:id](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/post-statuses-destroy-id)) usan [OAuth 1.0a User Context](https://developer.x.com/content/developer-twitter/resources/fundamentals/authentication). Por lo tanto, si anteriormente utilizabas uno de los endpoints estándar v1.1, puedes continuar usando el mismo método de autenticación si migras a la versión X API v2. 

### Diferencias

**URLs de endpoint**

* Endpoints Standard v1.1:
    * https://api.x.com/1.1/statuses/update.json
        (Crea un Post)
    * `https://api.x.com/1.1/statuses/destroy/:id.json`
        (Elimina un Post)
* Endpoint X API v2:
    * https://api.x.com/2/tweets
        (Crea un Post)
    * https://api.x.com/2/tweets/:id
        (Elimina un Post especificado)

### Requisitos de App y Project

Los endpoints de X API v2 requieren que utilices credenciales de una [developer App](/resources/fundamentals/developer-apps) asociada a un [Project](/resources/fundamentals/developer-apps) al autenticar tus solicitudes.
