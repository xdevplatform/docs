### Enterprise comparado con X API v2

**Similitudes**

* Granularidad
* Paginación
* Zona horaria

**Diferencias**

* URLs de endpoint
* Requisito de App y Project
* Períodos de tiempo disponibles
* Formato de datos de respuesta
* Métodos HTTP
* Formatos de tiempo de la solicitud
* Parámetros de la solicitud
* Operadores de filtrado

#### Similitudes

**Granularidad**

Si bien el parámetro para seleccionar la granularidad de los datos devueltos es diferente (`bucket` para la versión enterprise, `granularity` para la versión v2), los valores que puedes pasar con ese parámetro son los mismos, así como el comportamiento predeterminado:

* `day`
* `hour` (predeterminado)
* `minute`

**Paginación**

Aunque v2 tiene funciones de paginación adicionales (nuevos parámetros de paginación que te permiten navegar utilizando IDs de Posts con `since_id` y `until_id`), tanto enterprise como v2 te permiten paginar usando tiempo (`fromDate` y `toDate` con enterprise, y `start_time` y `end_time` para v2).

Si estás utilizando la versión enterprise, usarás el parámetro `next` para paginar, el campo del next token se llamará `next` y estará ubicado en la raíz de la respuesta.

Si estás utilizando v2, puedes usar el parámetro `next_token` o `pagination_token` para paginar, y tu next token se ubicará en `meta.next_token` en la respuesta.
 

**Zona horaria**

Como se mencionó en la sección de paginación, puedes navegar por diferentes páginas de datos usando tiempo tanto para enterprise como para v2. En ambos casos, usarás UTC como zona horaria al usar estos parámetros.
