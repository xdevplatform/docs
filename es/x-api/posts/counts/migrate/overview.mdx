## Comparando los endpoints de Post counts de la X API

El endpoint de Post counts v2 eventualmente reemplazará al [endpoint de counts de la Search API enterprise](/x-api/enterprise-gnip-2.0/fundamentals/search-api#counts-requests-post-count). Si tienes código, apps o herramientas que utilizan una versión anterior de un endpoint de Post counts y estás considerando migrar a los endpoints más recientes de X API v2, entonces esta guía es para ti.

## Comparación de recent Post counts

La versión enterprise de los endpoints de Post counts te permite obtener recuentos de 30 días o del archivo completo. Por lo tanto, el endpoint v2 de recent Post counts, que analiza un período de 7 días, no es un reemplazo directo de ninguno de los endpoints antes mencionados.

Sin embargo, para ayudar con las comparaciones, veremos cómo se compara el endpoint v2 de recent Post counts con el endpoint enterprise de 30 días.

La siguiente tabla compara los diversos tipos de endpoints de recent Post counts:

| **Description** | **Enterprise** | **X API v2** |
| :--- | :--- | :--- |
| Host domain | https://gnip-api.x.com | https://api.x.com |
| Endpoint path | /search/30day/accounts/:account_name/:label/counts.json | /2/tweets/counts/recent |
| [Autenticación](/resources/fundamentals/authentication) | Basic authentication | OAuth 2.0 Bearer Token |
| Formato de timestamp | YYYYMMDDhhmm | YYYY-MM-DDTHH:mm:ssZ  <br/>[ISO 8601 / RFC 3339](https://tools.ietf.org/html/rfc3339#section-5.6) |
| Devuelve recuentos de Posts no más antiguos de | 31 días | 7 días |
| Métodos HTTP compatibles | GET | GET |
| Límites de tasa de solicitud predeterminados | 20 solicitudes por 1 seg, agregados en solicitudes de search data y counts  <br/>El límite por minuto variará según el partner como se especifica en tu contrato. | 180 solicitudes por 15 min por usuario  <br/>450 solicitudes por 15 min por App |
| Admite filtrado usando [annotations](/x-api/fundamentals/post-annotations) |     | ✔   |
| Admite filtrado usando [conversation_id](/x-api/fundamentals/conversation-id) |     | ✔   |
| Nombre de clave JSON para el array de datos de Post | results | data |
| Granularidad de tiempo | Día, hora o minuto | Día, hora o minuto |
| Zona horaria | UTC | UTC |
| Parámetros de solicitud para seleccionar el período de tiempo | fromDate  <br/>toDate | start_time  <br/>end_time |
| Parámetros de solicitud para navegar por ID de Post |     | since_id  <br/>until_id |
| Requiere el uso de credenciales de una [developer App](/resources/fundamentals/developer-apps) asociada a un [project](/resources/fundamentals/developer-apps) |     | ✔   |

### Comparación de operadores de filtrado

Las dos versiones diferentes (enterprise y v2) de Post counts difieren en qué operadores están disponibles, y también tienen distintos niveles de disponibilidad de operadores dentro de cada versión, que se explican a continuación.

Enterprise

* No hay sub-niveles de operadores enterprise. Todos los operadores enterprise están disponibles para todos los usuarios enterprise.



X API v2

* **Core:** estos operadores están disponibles para cualquier usuario v2.
* **Advanced:** estos operadores solo están disponibles para los usuarios que han sido aprobados para acceso Academic Research.



Puedes obtener más información sobre cada uno de estos conjuntos de operadores en sus respectivas guías:

* [Operadores enterprise](/x-api/enterprise-gnip-2.0/fundamentals/search-api#building-search-queries)
* [Operadores de X API v2](/x-api/posts/search/integrate/build-a-query)
