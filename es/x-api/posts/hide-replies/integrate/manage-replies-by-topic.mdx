### Gestionar respuestas por tema

A través del endpoint hide replies, puedes crear integraciones para ayudar a las personas y marcas a mantener su conversación en el tema. Esta página muestra cómo gestionar una conversación usando los endpoints hide replies y [recent search](/x-api/posts/recent-search).

Recent search tiene funcionalidad para una conversación y sus respuestas, y el payload del Post devuelve [Post annotations](/x-api/fundamentals/post-annotations) para ayudarte a entender el contexto y el tema de cada Post, independientemente del idioma.

El flujo de la app tendrá controles para mostrar y gestionar una conversación:

1.  Pide permiso al usuario para leer sus Posts y gestionar sus respuestas.
2.  Extrae una conversación reciente a partir de la URL de un Post y verifica que la conversación es del usuario autenticado.
3.  Llamará al endpoint de recent search para mostrar cada Post de la conversación. La solicitud incluirá una consulta de búsqueda por conversation ID y la expansion de annotations para determinar si el Post está relacionado con deportes o no, según la interpretación que X hace del Post.
4.  Llama a Hide replies para ocultar una respuesta cuando el usuario decide hacerlo. También proporcionará una forma de deshacer esta acción por si acaso, para que el usuario siempre esté en control. 

5.  Para conversaciones más largas, proporcionará controles para [paginar los resultados de búsqueda](/x-api/posts/search/integrate/paginate).
     

#### Optimizar para el usuario (y para el uso)

Puedes diseñar un flujo de manera que el usuario tenga el control de cualquier acción que pretenda realizar. Tener este principio en mente también te ayuda a construir una integración que puede optimizar el consumo de Posts.

1.  Debido a que el usuario autenticado solo puede gestionar conversaciones que él mismo inició, tu flujo debería terminar temprano cuando no sea el caso.
    * Realiza una solicitud inicial de Post lookup. Termina el flujo temprano si la URL del Post no es válida o si la conversación no fue iniciada por el usuario autenticado.
    * De esta manera, tu app no tiene que hacer una solicitud de recent search si la conversación no puede ser moderada por el usuario autenticado.
2.  Solicita los [campos de usuario y Post](/x-api/fundamentals/fields) en la misma solicitud para evitar hacer solicitudes por separado. Este enfoque también puede mejorar el rendimiento de tu app.
3.  Evita hacer solicitudes cuando sea necesario. Esta app almacena en caché el estado oculto de una respuesta en el navegador del usuario. Esto es útil para conversaciones más grandes, donde el usuario puede querer retomar sus esfuerzos de moderación más tarde, y ayuda a tu app a optimizar las solicitudes para ocultar o mostrar respuestas.
