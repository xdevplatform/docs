## Comparación de los endpoints de timelines de la X API

Los endpoints v2 reverse chronological timeline, user Posts timeline y user mention timeline reemplazan a los endpoints [v1.1 statuses/home_timeline,](https://developer.x.com/en/docs/twitter-api/v1/tweets/timelines/api-reference/get-statuses-home_timeline) [v1.1 statuses/user_timeline](https://developer.x.com/en/docs/twitter-api/v1/tweets/timelines/api-reference/get-statuses-user_timeline.html) y [v1.1 statuses/mentions_timeline](https://developer.x.com/en/docs/twitter-api/v1/tweets/timelines/api-reference/get-statuses-mentions_timeline.html) respectivamente. Si tienes código, apps o herramientas que utilizan una versión anterior de este endpoint y estás considerando migrar al endpoint más reciente de X API v2, entonces esta guía es para ti. Para obtener una guía de migración más detallada, consulta [Migración de Standard v1.1 a X API v2](/x-api/posts/timelines/migrate/standard-to-twitter-api-v2).

Esta página contiene tres tablas comparativas:

* Home timeline en cronología inversa
* Timeline de Posts de usuario
* Timeline de menciones de usuario

### Home timeline en cronología inversa

Las siguientes tablas comparan los endpoints estándar v1.1 y de X API v2 de home timeline:

|     |     |     |
| :--- | :--- | :--- |
| **Description** | **Standard v1.1** | **X API v2** |
| Documentación | [Referencia de la API](https://developer.x.com/en/docs/twitter-api/v1/tweets/timelines/api-reference/get-statuses-home_timeline) | [Referencia de la API](https://developer.x.com/x-api/posts/timelines#user-mention-timeline-3) |
| Métodos HTTP admitidos | `GET` | `GET` |
| Host domain | `https://api.x.com` | `https://api.x.com` |
| Endpoint paths | `/1.1/statuses/home_timeline.json` | `/2/users/:id/timelines/reverse_chronological` |
| Parámetros requeridos | `user_id` o `screen_name` | ID de usuario establecido como parámetro de ruta :id |
| Autenticación | OAuth 1.0a User Context | OAuth 1.0a User Context<br/><br/>[OAuth 2.0 Authorization Code Flow with PKCE](/fundamentals/authentication/oauth-2-0/authorization-code) |
| Límites de tasa de solicitud | 15 solicitudes por 15 minutos con OAuth 1.0a User Context<br/><br/>Límite de solicitudes: 100,000 en un período de 24 horas. | 180 solicitudes por ventana de 15 minutos |
| Posts predeterminados por respuesta | 15  | 100 |
| Posts máximos por respuesta | 800 | Este endpoint devuelve todos los Posts creados en un timeline durante los últimos 7 días, así como los 800 más recientes independientemente de la fecha de creación. |
| Proporciona historial de edición de Post | ✔   | ✔   |
| Posts históricos disponibles | Los 800 Posts más recientes, incluidos Retweets | Los 3,200 Posts más recientes, incluidos Retweets |
| Opciones de navegación del timeline | since_id (exclusivo) usado para sondeo de actualizaciones<br/><br/>`max_id` (inclusivo) | `start_time`<br/><br/>end_time<br/><br/>`since_id`(exclusivo) usado para sondeo de actualizaciones <br/><br/>`until_id` (exclusivo) |
| Parámetros opcionales para refinar resultados | `count`<br/><br/>`exclude_replies`<br/><br/>`include_rts`<br/><br/>`trim_user`<br/><br/>`tweet_mode`<br/><br/>`since_id`<br/><br/>`max_id` | `max_results`<br/><br/>`exclude`(retweets,replies)<br/><br/>`tweet.fields`<br/><br/>`user.fields`<br/><br/>`place.fields`<br/><br/>`media.fields`<br/><br/>`poll.fields`<br/><br/>`expansions`<br/><br/>`start_time`<br/><br/>`end_time`<br/><br/>`since_id`<br/><br/>`until_id` |
| Admite solicitar y recibir [annotations](/x-api/fundamentals/post-annotations) | N/A | Si se incluyen annotations en tweet.fields, los resultados se anotarán con datos de annotation inferidos basados en el texto del Post, como 'Music Genre' y 'Folk Music' o 'Musician' y 'Dolly Parton' |
| Admite solicitar y recibir [métricas](/x-api/fundamentals/metrics) específicas de Post | N/A | Si se incluyen annotations en `tweet.fields`, los resultados se anotarán con public_metrics por Post, incluidos `retweet_count`, `reply_count`, `quote_count`, `like_count`, `impression_count` y `bookmark_count`, `non_public_metrics` incluyendo `impression_count`, `user_profile_clicks`, `url_link_clicks` y `engagements`.<br/><br/>Métricas de media adicionales como view_count y métricas de reproducción de video.<br/><br/>organic\_metrics y promoted\_metrics adicionales disponibles con User Context para Posts promocionados. |
| Admite solicitar y recibir [conversation_id](/x-api/fundamentals/conversation-id) | N/A | Devuelve un campo conversation_id donde el valor representa el primer Post publicado en un hilo de respuestas para ayudarte a hacer seguimiento de las conversaciones. |
| Formato JSON de Post | [Formato de datos Standard v1.1](https://developer.x.com/en/docs/twitter-api/v1/data-dictionary/overview.html) | Formato [X API v2](/x-api/fundamentals/data-dictionary) (determinado por los parámetros de solicitud fields y expansions, no es retrocompatible con formatos v1.1)<br/><br/>Para obtener más información sobre cómo migrar del formato Standard v1.1 al formato X API v2, visita nuestra [guía de migración de formatos de datos](/x-api/migrate/data-format-migration). |
| Orden de resultados | Cronológico inverso | Cronológico inverso |
| Paginación de resultados | N/A debe usar navegación por ID de Post | Los resultados pueden revisarse avanzando o retrocediendo usando un pagination_token |
| Requiere el uso de credenciales de una [developer App](/resources/fundamentals/developer-apps) asociada a un [Project](/resources/fundamentals/developer-apps) |     | ✔   |
