### Migración de la API de PowerTrack a X API v2 filtered stream

Utiliza esta guía de migración para comprender las similitudes y diferencias entre la [API de PowerTrack](/x-api/enterprise-gnip-2.0/powertrack-api) y [filtered stream](/x-api/posts/filtered-stream) de X API v2, y para ayudarte a migrar una integración actual de la API de PowerTrack a filtered stream v2.

* **Similitudes**
    * Método de entrega streaming
    * Proceso de integración
    * Conexión de stream persistente con endpoints de gestión de reglas independientes
    * Sintaxis de reglas
    * Operadores de reglas (con excepciones)
    * Lógica de coincidencia de reglas
    * Soporte para historial y metadatos de edición de Post
* **Diferencias**
    * Longitud de las reglas
    * Volumen de reglas
    * URLs de endpoint
    * Requisito de App y Project para el acceso
    * Método de autenticación
    * Parámetros de solicitud
    * Seguimiento de uso
    * Múltiples streams, conexiones redundantes, backfill y recuperación de Replay
    * Parámetros de solicitud y formato de respuesta
    * Estructura de datos JSON de respuesta

#### Similitudes

**Método de entrega streaming**

Tanto PowerTrack como filtered stream de X API v2 utilizan la entrega de datos en streaming, que requieren que el cliente establezca una conexión abierta a un endpoint y mantenga una solicitud HTTP de larga duración, analizando la respuesta de forma incremental del servidor en tiempo real. Tanto PowerTrack como filtered stream de X API v2 filtran Posts públicamente disponibles que coinciden con reglas existentes en el stream en tiempo real y utilizan señales keep-alive como caracteres de nueva línea (\\r\\n) para indicar que la conexión sigue activa. Las conexiones de endpoint tanto de PowerTrack como de filtered stream de X API v2 entregan datos en tiempo real y deben ser leídas por el cliente conectado rápidamente.
