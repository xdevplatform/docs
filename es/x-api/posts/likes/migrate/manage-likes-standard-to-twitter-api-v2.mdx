### Manage Likes: Standard v1.1 comparado con X API v2

Si has estado trabajando con los endpoints estándar v1.1 [POST favorites/create](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/post-favorites-create) y [POST favorites/destroy](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/post-favorites-destroy), el objetivo de esta guía es ayudarte a entender las similitudes y diferencias entre los endpoints estándar v1.1 y X API v2 de manage Likes.

* **Similitudes**
    * OAuth 1.0a User Context
* **Diferencias**
    * URLs de endpoint y métodos HTTP
    * Requisitos de App y Project
    * Parámetros de solicitud

#### Similitudes

**Método de autenticación OAuth 1.0a User Context**

Ambas versiones del endpoint admiten [OAuth 1.0a User Context](/resources/fundamentals/authentication#oauth-1-0a-2). Por lo tanto, si anteriormente estabas usando uno de los endpoints estándar v1.1 de manage favorites, puedes continuar usando el mismo método de autenticación si migras a la versión X API v2.

#### Diferencias

**URLs de endpoint y métodos HTTP**

* Endpoints Standard v1.1:
    * POST https://api.x.com/1.1/favorites/create.json
        (dar like a un Post)
    * POST https://api.x.com/1.1/favorites/destroy.json
        (quitar like a un Post)
* Endpoint X API v2:
    * POST https://api.x.com/2/tweets/:id/likes
        (dar like a un Post)
    * DELETE https://api.x.com/2/tweets/:id/likes/:tweet_id
        (quitar like a un Post) 

**Requisitos de App y Project**

Los endpoints de X API v2 requieren que utilices credenciales de una [developer App](/resources/fundamentals/developer-apps) asociada a un [Project](/resources/fundamentals/developer-apps) al autenticar tus solicitudes. Todos los endpoints de X API v1.1 pueden usar credenciales de Apps o Apps asociadas
