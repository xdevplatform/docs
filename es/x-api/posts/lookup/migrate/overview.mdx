## Comparación de los endpoints de Posts lookup de la X API

Los endpoints v2 de Posts lookup reemplazan a los endpoints estándar v1.1 [GET statuses/lookup](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-lookup) y [GET statuses/show](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-show-id). Esta guía es para desarrolladores que migran desde estas versiones anteriores a X API v2.

## Tabla comparativa de endpoints

| Description | Standard v1.1 | X API v2 |
|:-------------|:---------------|:----------|
| **Métodos HTTP admitidos** | `GET` | `GET` |
| **Host domain** | `https://api.x.com` | `https://api.x.com` |
| **Endpoint path** | `/1.1/statuses/show.json`, `/1.1/statuses/lookup.json` | `/2/tweets` |
| **[Autenticación](resources/fundamentals/authentication)** | OAuth 1.0a User Context | OAuth 1.0a User Context, OAuth 2.0 App-Only, OAuth 2.0 Authorization Code with PKCE |
| **[Formato JSON](/x-api/fundamentals/data-dictionary) de Post** | Formato Standard v1.1 | [Formato X API v2](/x-api/fundamentals/data-dictionary), determinado por los parámetros `fields` y `expansions` (no es retrocompatible con v1.1) |
| **Admite la selección de [fields](/x-api/fundamentals/data-dictionary) específicos** |  | ✔ |
| **Admite los campos de [annotations](/x-api/fundamentals/post-annotations)** |  | ✔ |

## Standard v1.1 comparado con X API v2

Si has estado trabajando con los endpoints estándar v1.1 GET statuses/show y GET statuses/lookup, esta guía te ayudará a entender las similitudes y diferencias entre los endpoints estándar y los de X API v2 Posts lookup.

También te puede interesar nuestra [herramienta visual de migración de formato de datos](/x-api/migrate/data-format-migration) para ayudarte a ver rápidamente las diferencias entre el [formato de datos de X API v1.1](/x-api/fundamentals/data-dictionary) y el [formato de X API v2](/x-api/fundamentals/data-dictionary).

- **Similitudes**
  - OAuth 1.0a User Context
  - Límites de Posts por solicitud
  - Soporte para historial y metadatos de edición de Post

- **Diferencias**
  - URLs de endpoint
  - Requisitos de App y Project
  - Formato de datos de respuesta
  - Parámetros de solicitud

### Similitudes

#### Método de autenticación OAuth 1.0a User Context

El endpoint estándar admite [OAuth 1.0a User Context](/resources/fundamentals/authentication), mientras que el nuevo endpoint de Post lookup de X API v2 admite tanto OAuth 1.0a User Context como [OAuth 2.0 App-Only](/resources/fundamentals/authentication). Por lo tanto, si anteriormente utilizabas uno de los endpoints estándar v1.1 de Post lookup, puedes continuar usando el mismo método de autenticación si migras a la versión X API v2.

La autenticación App-Only es probablemente la forma más sencilla de comenzar. Para aprender cómo generar un App Access Token, consulta [esta guía de OAuth 2.0 App-only](/resources/fundamentals/authentication).

#### Límites de Posts por solicitud

El endpoint v1.1 [GET statuses/lookup](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-lookup) te permite especificar hasta 100 Posts por solicitud. Esto también aplica al endpoint GET /tweets. Para especificar 100 Posts completos, usa el parámetro `ids` como parámetro de consulta con una lista separada por comas de [IDs de Post](/resources/fundamentals/x-ids).

**Soporte para historial y metadatos de edición de Post**

Ambas versiones proporcionan metadatos que describen cualquier historial de edición. Consulta las referencias de la API de Post lookup y la [página de fundamentos de edición de Posts](/x-api/fundamentals/edit-posts) para obtener más detalles.

### Diferencias

#### URLs de endpoint

- **Endpoints Standard v1.1:**
  - `https://api.x.com/1.1/statuses/show`
  - `https://api.x.com/1.1/statuses/lookup`
  
- **Endpoint X API v2:**
  - `https://api.x.com/2/tweets`
  - `https://api.x.com/2/tweets/:id`

#### Requisitos de App y Project

Los endpoints de X API v2 requieren credenciales de una [developer App](/resources/fundamentals/developer-apps) asociada a un [Project](/resources/fundamentals/developer-apps) para la autenticación. Los endpoints de X API v1.1 pueden usar credenciales de Apps o Apps asociadas con una App.

#### Formato de datos de respuesta

Una diferencia significativa entre las versiones de endpoint estándar v1.1 y X API v2 es cómo se seleccionan los fields en el payload.

Para los endpoints estándar, muchos fields de respuesta se incluyen por defecto, con opciones para usar parámetros para especificar fields adicionales. 

Sin embargo, X API v2 solo entrega los fields `id` y `text` del Post por defecto. Los fields y objetos adicionales requieren el uso de los parámetros [fields](/x-api/fundamentals/fields) y [expansions](/x-api/fundamentals/expansions). Los fields expandidos se devuelven en un objeto `includes` dentro de la respuesta, que puede coincidir con el objeto Post principal haciendo coincidir los IDs.

Para obtener más información sobre el uso de fields y expansions, consulta la [guía sobre cómo usar fields y expansions](/x-api/fundamentals/data-dictionary). Una [guía de migración de formato de datos](/x-api/fundamentals/fields) también mapea los fields estándar v1.1 a los fields v2 más recientes.

Además, X API v2 introduce nuevos diseños JSON para los objetos, incluidos los objetos Post y [user](/x-api/fundamentals/fields):

- Los endpoints estándar devuelven objetos Post en un array `statuses`, mientras que X API v2 utiliza un array `data`.
- Retweeted y Quoted Tweets en X API v2 reemplazan la terminología "statuses".
- Nueva terminología como `like` reemplaza términos como `favorites` y `favourites`.
- Los atributos sin valores (por ejemplo, `null`) no se incluyen en los payloads de X API v2.

El objeto Post en X API v2 incluye nuevos fields como:
- `conversation_id`
- Dos nuevos campos de [annotations](/x-api/fundamentals/post-annotations) (`context` y `entities`)
- Nuevos campos de [métricas](/x-api/fundamentals/metrics)
- Campo `reply_setting` que muestra quién puede responder a un Post determinado

#### Parámetros de solicitud

Los siguientes parámetros de solicitud estándar v1.1 tienen equivalentes en X API v2:

| Standard | X API v2 |
|:----------|:----------|
| `id`     | `ids`    |

Ciertos parámetros estándar v1.1 **no** son compatibles con X API v2:

| Standard            | Comment                                                                                                                      |
|:---------------------|:------------------------------------------------------------------------------------------------------------------------------|
| `tweet_mode`        | Reemplazado por la funcionalidad de fields y expansions.                                                                             |
| `trim_user`         | Reemplazado por fields y expansions. Utiliza la expansion `author_id` y `user.fields` para los datos de usuario.                               |
| `include_my_retweet`| Proporciona el ID del Post fuente para los Posts Retweeteados por el usuario autenticado.                                          |
| `include_entities`  | Utiliza fields y expansions para controlar las entities en el payload.                                                               |
| `include_ext_alt_text` | Añade el campo `ext_alt_text` en la entidad media si hay texto alternativo presente.                                                         |
| `include_card_uri`  | Añade `card_uri` cuando se adjunta una ads card.                                                                               |
| `map`               | Devuelve el ID del Post y el mensaje de error para los Posts no disponibles en X API v2, en lugar de fields anulados en v1.1.            |

### Solicitudes cURL

Las siguientes solicitudes cURL muestran endpoints estándar v1.1 y sus equivalentes v2. Reemplaza `ACCESS_TOKEN` en el encabezado con tu app access token. Para los endpoints v2, el token debe pertenecer a una [developer App](/fundamentals/developer-apps) dentro de un Project.

Los payloads de respuesta de v1.1 diferirán de v2. Con v2, puedes solicitar diferentes fields con los parámetros [fields](/x-api/fundamentals/fields) y [expansions](/x-api/fundamentals/expansions).

**Endpoints Standard v1.1 `GET statuses/lookup` y v2 `GET /tweets`**

```bash
curl --request GET \
  --url 'https://api.x.com/1.1/statuses/lookup.json?id=1460323737035677698%2C1460323743339741184' \
  --header 'Authorization: Bearer $ACCESS_TOKEN'
```

```bash
curl --request GET \
  --url 'https://api.x.com/2/tweets?ids=1460323737035677698%2C1460323743339741184&tweet.fields=created_at&expansions=author_id&user.fields=created_at' \
  --header 'Authorization: Bearer $ACCESS_TOKEN'
```


**Endpoints Standard v1.1 `GET statuses/show/:id` y v2 `GET /tweets/:id`**
```bash
curl --request GET \
  --url 'https://api.x.com/1.1/statuses/show.json?id=1460323737035677698' \
  --header 'Authorization: Bearer $ACCESS_TOKEN'
```

```bash
curl --request GET \
  --url 'https://api.x.com/2/tweets/1460323737035677698?tweet.fields=created_at&expansions=author_id&user.fields=created_at' \
  --header 'Authorization: Bearer $ACCESS_TOKEN'
```
