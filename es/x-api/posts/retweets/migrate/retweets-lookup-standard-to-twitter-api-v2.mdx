### Retweets lookup: Standard v1.1 comparado con X API v2

Si has estado trabajando con los endpoints estándar v1.1 [v1.1 GET statuses/retweets/:id](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-retweets-id) y [v1.1 GET statuses/retweets/:ids](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-retweeters-ids), el objetivo de esta guía es ayudarte a entender las similitudes y diferencias entre los endpoints estándar v1.1 y de X API v2 de Retweets lookup.

* **Similitudes**
    * Autenticación
    * Límites de usuarios por solicitud
* **Diferencias**
    * URLs de endpoint

    * Limitaciones de la solicitud
    * Requisitos de App y Project

    * Formato de datos de respuesta
    * Parámetros de solicitud

#### Similitudes

**Autenticación**

Tanto los endpoints estándar v1.1 como los de X API v2 Retweets lookup ([v1.1 GET statuses/retweets/:id](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-retweets-id) y [v1.1 GET statuses/retweeters/:ids](https://developer.x.com/en/docs/twitter-api/v1/tweets/post-and-engage/api-reference/get-statuses-retweeters-ids)) usan [OAuth 1.0a User Context](https://developer.x.com/content/developer-twitter/resources/fundamentals/authentication) u OAuth 2.0 Bearer Token.

**Límites de usuarios por solicitud**

Tanto para los endpoints GET v1.1 como v2, el número máximo de usuarios que devolverá el endpoint de Retweets lookup es de 100 usuarios. Para el endpoint v2 de Retweets lookup, no se pasa ningún token de paginación, por defecto entregamos 100 usuarios y ese es el máximo que se devuelve.
