Los endpoints de Batch Compliance te permiten subir conjuntos de datos de Post IDs o user IDs y recibir su estado actual de cumplimiento. Úsalos para identificar Posts eliminados, cuentas suspendidas y otros eventos de compliance.

## Cómo funciona

1. **Crea un job** — Especifica el tipo (Posts o usuarios) y la URL de subida
2. **Sube los IDs** — Sube tu conjunto de datos a la URL proporcionada
3. **Espera el procesamiento** — El job se procesa de forma asincrónica
4. **Descarga los resultados** — Obtén el estado de compliance para cada ID

## Endpoints

| Método | Endpoint | Descripción |
|:-------|:---------|:------------|
| POST | [`/2/compliance/jobs`](/x-api/compliance/create-compliance-job) | Crear un nuevo compliance job |
| GET | [`/2/compliance/jobs/:id`](/x-api/compliance/get-compliance-job-by-id) | Obtener el estado del job |
| GET | [`/2/compliance/jobs`](/x-api/compliance/get-compliance-jobs) | Listar todos los jobs |

---

## Tipos de job

| Tipo | Descripción |
|:-----|:------------|
| `tweets` | Verificar el estado de compliance de Posts |
| `users` | Verificar el estado de compliance de usuarios |

---

## Eventos de compliance

### Eventos de Post

| Evento | Descripción |
|:------|:------------|
| `deleted` | El Post fue eliminado por el usuario |
| `bounced` | El Post falló la verificación de compliance |
| `protected` | La cuenta se volvió protegida |
| `suspended` | La cuenta fue suspendida |
| `scrub_geo` | Se eliminaron los datos de geolocalización |

### Eventos de usuario

| Evento | Descripción |
|:------|:------------|
| `deleted` | La cuenta fue eliminada |
| `suspended` | La cuenta fue suspendida |
| `protected` | La cuenta se volvió protegida |
| `deactivated` | La cuenta fue desactivada |

---

## Ejemplo: Crear un job

```bash
curl -X POST "https://api.x.com/2/compliance/jobs" \
  -H "Authorization: Bearer $BEARER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "tweets",
    "name": "my-compliance-job"
  }'
```
