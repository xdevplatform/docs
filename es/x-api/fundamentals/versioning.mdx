La X API usa números de versión en las rutas de los endpoints para brindar estabilidad al mismo tiempo que permite la evolución. Comprender nuestra estrategia de versionado te ayuda a planificar integraciones y mantenerte al día.

---

## Versiones actuales

| Versión | Estado | Descripción |
|:--------|:-------|:------------|
| **v2** | Actual | Endpoints modernos, precios flexibles, todas las nuevas funciones |
| **v1.1** | Legado | Soporte limitado, actualizaciones mínimas |
| **Enterprise** | Disponible | Acceso de alto volumen con soporte dedicado |

<Tip>
Usa **X API v2** para todos los proyectos nuevos. Aquí es donde se lanzan todas las nuevas funciones.
</Tip>

## Versión en las URLs

El número de versión aparece en la ruta del endpoint:

```
https://api.x.com/2/tweets
                   ^
                   versión
```

## Cambios rompedores vs. no rompedores

### Cambios rompedores (requieren actualizaciones de código)

Estos cambios solo ocurren en aumentos de versión mayor:

- Eliminar un endpoint
- Eliminar un campo de respuesta
- Eliminar un parámetro de consulta
- Añadir un nuevo parámetro requerido
- Cambiar el tipo de dato de un campo
- Renombrar un campo o recurso
- Cambiar los códigos de respuesta o tipos de error
- Modificar los scopes de autorización

### Cambios no rompedores (aditivos)

Estos pueden ocurrir en cualquier momento sin cambios de versión:

- Añadir un nuevo endpoint
- Añadir un nuevo parámetro opcional
- Añadir un nuevo campo de respuesta
- Añadir nuevos scopes de OAuth
- Cambiar el texto de mensajes de error
- Anular campos por razones de privacidad/seguridad

## Calendario de lanzamientos

| Tipo | Frecuencia | Aviso |
|:-----|:----------|:-------|
| **Versiones mayores** | No más de una vez al año | Se proporcionan guías de migración |
| **Cambios no rompedores** | Continuos | Actualizaciones del changelog |
| **Parches de seguridad** | Según sea necesario | Pueden aplicarse a la versión actual |

---

## Política de deprecación

Cuando lanzamos una nueva versión mayor:

1. **Deprecación**: La versión anterior se marca como deprecada
2. **Período de soporte**: La versión deprecada sigue funcionando durante un período definido
3. **Retirada**: La versión deprecada se elimina

### Definiciones

| Estado | Significado |
|:-------|:--------|
| **Activo** | Totalmente compatible con nuevas funciones y correcciones |
| **Deprecado** | Sin nuevas funciones; solo bugs críticos; se desaconseja su uso |
| **Retirado** | Ya no es accesible |
