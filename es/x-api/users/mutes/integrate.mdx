## Autenticación

Los endpoints de mutes requieren autenticación de usuario para acceder a las listas privadas de silencios:

| Método | Descripción |
|:-------|:------------|
| [OAuth 2.0 Authorization Code with PKCE](/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2) | Recomendado para nuevas aplicaciones |
| [OAuth 1.0a User Context](/resources/fundamentals/authentication) | Soporte heredado |

<Warning>
La autenticación App-Only no es compatible. Debes autenticarte en nombre de un usuario.
</Warning>

### Scopes requeridos (OAuth 2.0)

| Scope | Requerido para |
|:------|:---------------|
| `mute.read` | Obtener cuentas silenciadas |
| `mute.write` | Silenciar y dejar de silenciar cuentas |
| `users.read` | Requerido con scopes de mute |

---

## Resumen de endpoints

| Método | Endpoint | Descripción |
|:-------|:---------|:------------|
| GET | `/2/users/:id/muting` | Obtiene la lista de cuentas silenciadas |
| POST | `/2/users/:id/muting` | Silencia una cuenta |
| DELETE | `/2/users/:source_user_id/muting/:target_user_id` | Deja de silenciar una cuenta |

## Fields y expansions

### Respuesta predeterminada

```json
{
  "data": [
    {
      "id": "1234567890",
      "name": "Example User",
      "username": "example"
    }
  ]
}
```

### Fields disponibles

<Accordion title="user.fields">
| Field | Descripción |
|:------|:------------|
| `created_at` | Fecha de creación de la cuenta |
| `description` | Bio del usuario |
| `profile_image_url` | URL del avatar |
| `public_metrics` | Recuentos de seguidores/seguidos |
| `verified` | Estado de verificación |
</Accordion>

<Accordion title="expansions">
| Expansion | Descripción |
|:----------|:------------|
| `pinned_tweet_id` | Post fijado del usuario |
</Accordion>

### Ejemplo con fields

<CodeGroup dropdown>

```bash cURL
curl "https://api.x.com/2/users/123456789/muting?\
user.fields=username,verified,created_at&\
max_results=100" \
  -H "Authorization: Bearer $USER_ACCESS_TOKEN"
```

```python title="Python SDK" lines wrap icon="python"
from xdk import Client

client = Client(bearer_token="YOUR_USER_ACCESS_TOKEN")

# Obtener usuarios silenciados con fields adicionales
for page in client.users.get_muting(
    user_id="123456789",
    user_fields=["username", "verified", "created_at"],
    max_results=100
):
    for user in page.data:
        print(f"{user.username} - Verified: {user.verified}")
```

```javascript title="JavaScript SDK" lines wrap icon="square-js"
import { Client } from "@xdevplatform/xdk";

const client = new Client({ accessToken: "YOUR_USER_ACCESS_TOKEN" });

const paginator = client.users.getMuting("123456789", {
  userFields: ["username", "verified", "created_at"],
  maxResults: 100,
});

for await (const page of paginator) {
  page.data?.forEach((user) => {
    console.log(`${user.username} - Verified: ${user.verified}`);
  });
}
```

## Paginación

Para usuarios con listas de silencios grandes, los resultados están paginados:

<CodeGroup dropdown>

```bash cURL
# Primera solicitud
curl "https://api.x.com/2/users/123/muting?max_results=100" \
  -H "Authorization: Bearer $USER_ACCESS_TOKEN"

# Solicitud posterior con token de paginación
curl "https://api.x.com/2/users/123/muting?max_results=100&pagination_token=NEXT_TOKEN" \
  -H "Authorization: Bearer $USER_ACCESS_TOKEN"
```

```python title="Python SDK" lines wrap icon="python"
from xdk import Client

client = Client(bearer_token="YOUR_USER_ACCESS_TOKEN")

# El SDK gestiona la paginación automáticamente
all_muted = []

for page in client.users.get_muting(user_id="123", max_results=100):
    if page.data:
        all_muted.extend(page.data)

print(f"Muted {len(all_muted)} users")
```

```javascript title="JavaScript SDK" lines wrap icon="square-js"
import { Client } from "@xdevplatform/xdk";

const client = new Client({ accessToken: "YOUR_USER_ACCESS_TOKEN" });

async function getAllMutedUsers(userId) {
  const allMuted = [];

  // El SDK gestiona la paginación automáticamente
  const paginator = client.users.getMuting(userId, { maxResults: 100 });

  for await (const page of paginator) {
    if (page.data) {
      allMuted.push(...page.data);
    }
  }

  return allMuted;
}

// Uso
const muted = await getAllMutedUsers("123");
console.log(`Muted ${muted.length} users`);
```

## Diferencias de comportamiento

### Silenciar vs Bloquear

| Característica | Silenciar | Bloquear |
|:--------|:-----|:------|
| Ver sus Posts | No (ocultos) | No |
| Ellos ven tus Posts | Sí | No |
| Ellos te siguen | Sí (pueden seguir) | No (eliminados) |
| Ellos pueden enviarte DMs | Sí | No |
| Notificación enviada | No | No |

<Tip>
Silenciar es privado — el usuario silenciado no recibe notificación y no puede saber que ha sido silenciado.
</Tip>

## Gestión de errores

| Estado | Error | Solución |
|:-------|:------|:---------|
| 400 | Invalid request | Verifica el formato del user ID |
| 401 | Unauthorized | Verifica el access token |
| 403 | Forbidden | Verifica scopes y permisos |
| 404 | Not Found | El usuario no existe |
| 429 | Too Many Requests | Espera y reintenta |
