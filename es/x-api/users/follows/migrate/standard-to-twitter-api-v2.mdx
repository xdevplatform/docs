#### Gestionar seguimientos: Standard v1.1 comparado con X API v2

Si has estado trabajando con los endpoints estándar v1.1 [POST friendships/create](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/follow-search-get-users/api-reference/post-friendships-create) y [POST friendships/destroy](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/follow-search-get-users/api-reference/post-friendships-destroy), el objetivo de esta guía es ayudarte a entender las similitudes y diferencias entre los endpoints estándar y los de X API v2 para gestionar seguimientos.

* **Similitudes**
    * OAuth 1.0a User Context
* **Diferencias**
    * URLs de endpoints
    * Requisitos de App y Project
    * Métodos HTTP
    * Parámetros de solicitud



#### Similitudes

**Método de autenticación OAuth 1.0a User Context**

Ambas versiones del endpoint admiten [OAuth 1.0a User Context](/resources/fundamentals/authentication#oauth-1-0a-2). Por lo tanto, si anteriormente usabas uno de los endpoints estándar v1.1 de gestionar seguimientos, puedes seguir utilizando el mismo método de autenticación si migras a la versión de X API v2.

#### Diferencias

**URLs de endpoints**

* Endpoints estándar v1.1:
    * POST https://api.x.com/1.1/friendships/create.json
        (seguir a un usuario)
    * POST https://api.x.com/1.1/friendships/destroy.json
        (dejar de seguir a un usuario)
* Endpoint X API v2:
    * POST https://api.x.com/2/users/:id/following
        (seguir a un usuario)
    * DELETE https://api.x.com/2/users/:source\_user\_id/following/:target\_user\_id
        (dejar de seguir a un usuario)

**Requisitos de App y Project**

Los endpoints de X API v2 requieren que uses credenciales de una [App de desarrollador](/resources/fundamentals/developer-apps) asociada a un [Project](/resources/fundamentals/developer-apps) al autenticar tus solicitudes.
