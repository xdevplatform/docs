## Autenticación

Los endpoints de DM requieren autenticación de usuario para acceder a conversaciones privadas:

| Método | Descripción |
|:-------|:------------|
| [OAuth 2.0 Authorization Code with PKCE](/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2) | Recomendado |
| [OAuth 1.0a User Context](/resources/fundamentals/authentication) | Soporte legacy |

<Warning>
La autenticación App-Only no es compatible. Todos los Mensajes Directos son privados.
</Warning>

### Scopes requeridos (OAuth 2.0)

| Scope | Requerido para |
|:------|:-------------|
| `dm.read` | Leer eventos de DM |
| `tweet.read` | Requerido con dm.read |
| `users.read` | Requerido con dm.read |

## Tipos de eventos

| Evento | Descripción | Campos clave |
|:------|:------------|:-----------|
| `MessageCreate` | Se envió un mensaje | `text`, `sender_id` |
| `ParticipantsJoin` | Un usuario se unió al grupo | `participant_ids`, `sender_id` |
| `ParticipantsLeave` | Un usuario abandonó el grupo | `participant_ids` |

## Fields y expansions

### Fields por defecto

| Tipo de evento | Fields por defecto |
|:-----------|:---------------|
| MessageCreate | `id`, `event_type`, `text` |
| ParticipantsJoin/Leave | `id`, `event_type`, `participant_ids` |

### Fields disponibles

| Field | Descripción | Eventos |
|:------|:------------|:-------|
| `dm_conversation_id` | ID de conversación | Todos |
| `created_at` | Timestamp del evento | Todos |
| `sender_id` | Quién envió/invitó | MessageCreate, Join |
| `attachments` | Adjuntos de medios | MessageCreate |
| `referenced_tweets` | Posts compartidos | MessageCreate |

### Expansions disponibles

| Expansion | Devuelve |
|:----------|:--------|
| `sender_id` | Objeto User del remitente |
| `participant_ids` | Objetos User de los participantes |
| `attachments.media_keys` | Objetos Media |
| `referenced_tweets.id` | Objetos Post |

### Ejemplo con expansions

<CodeGroup dropdown>

```bash cURL
curl "https://api.x.com/2/dm_events?\
dm_event.fields=created_at,sender_id,attachments&\
expansions=sender_id,attachments.media_keys&\
user.fields=username,profile_image_url&\
media.fields=url,type" \
  -H "Authorization: Bearer $USER_ACCESS_TOKEN"
```

```python title="SDK de Python" lines wrap icon="python"
from xdk import Client

client = Client(bearer_token="YOUR_USER_ACCESS_TOKEN")

# Get DM events with expansions
for page in client.dm_events.list(
    dm_event_fields=["created_at", "sender_id", "attachments"],
    expansions=["sender_id", "attachments.media_keys"],
    user_fields=["username", "profile_image_url"],
    media_fields=["url", "type"],
    max_results=100
):
    for event in page.data:
        print(f"Event: {event.event_type} - {event.text}")
```

```javascript title="SDK de JavaScript" lines wrap icon="square-js"
import { Client } from "@xdevplatform/xdk";

const client = new Client({ accessToken: "YOUR_USER_ACCESS_TOKEN" });

const paginator = client.dmEvents.list({
  dmEventFields: ["created_at", "sender_id", "attachments"],
  expansions: ["sender_id", "attachments.media_keys"],
  userFields: ["username", "profile_image_url"],
  mediaFields: ["url", "type"],
  maxResults: 100,
});

for await (const page of paginator) {
  page.data?.forEach((event) => {
    console.log(`Event: ${event.event_type} - ${event.text}`);
  });
}
```

## Paginación

Los eventos de DM se devuelven en orden cronológico inverso (los más nuevos primero):

<CodeGroup dropdown>

```bash cURL
# First request
curl "https://api.x.com/2/dm_events?max_results=100" \
  -H "Authorization: Bearer $USER_ACCESS_TOKEN"

# Subsequent request with pagination token
curl "https://api.x.com/2/dm_events?max_results=100&pagination_token=NEXT_TOKEN" \
  -H "Authorization: Bearer $USER_ACCESS_TOKEN"
```

```python title="SDK de Python" lines wrap icon="python"
from xdk import Client

client = Client(bearer_token="YOUR_USER_ACCESS_TOKEN")

# The SDK handles pagination automatically
all_events = []

for page in client.dm_events.list(max_results=100):
    if page.data:
        all_events.extend(page.data)

print(f"Found {len(all_events)} DM events")
```

```javascript title="SDK de JavaScript" lines wrap icon="square-js"
import { Client } from "@xdevplatform/xdk";

const client = new Client({ accessToken: "YOUR_USER_ACCESS_TOKEN" });

async function getAllDMEvents() {
  const allEvents = [];

  // The SDK handles pagination automatically
  const paginator = client.dmEvents.list({ maxResults: 100 });

  for await (const page of paginator) {
    if (page.data) {
      allEvents.push(...page.data);
    }
  }

  return allEvents;
}

// Usage
const events = await getAllDMEvents();
console.log(`Found ${events.length} DM events`);
```

</CodeGroup>

<Note>
Los eventos de hasta hace **30 días** están disponibles.
</Note>

## Compatibilidad de IDs con v1.1

Los IDs de conversación y de evento se comparten entre los endpoints v1.1 y v2. Esto significa que puedes:

- Usar v2 para recuperar eventos, luego usar v1.1 para eliminar mensajes específicos
- Referenciar los IDs de conversación de las URLs de x.com en las solicitudes de la API
