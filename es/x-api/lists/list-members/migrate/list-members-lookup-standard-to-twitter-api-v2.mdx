### List members lookup: Standard v1.1 comparado con X API v2


Si has estado trabajando con los endpoints estándar v1.1 [GET lists/members](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/get-lists-members) y [GET lists/memberships](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/get-lists-memberships), el objetivo de esta guía es ayudarte a entender las similitudes y diferencias entre los endpoints de List member estándar v1.1 y de X API v2.

* **Similitudes**
    * Métodos de autenticación
* **Diferencias**
    * URLs de endpoints
    * Rate limits
    * Requisitos de App y Project
    * Límites de objetos de datos por solicitud
    * Formatos de datos de respuesta
    * Parámetros de solicitud

#### Similitudes

**Autenticación**

Ambas versiones del endpoint admiten tanto [OAuth 1.0a User Context](/resources/fundamentals/authentication#oauth-1-0a-2) como [App only](/resources/fundamentals/authentication#oauth-2-0). Por lo tanto, si anteriormente usabas uno de los endpoints estándar v1.1 de List members, puedes seguir utilizando el mismo método de autenticación si migras a la versión de X API v2.

Dependiendo de tu biblioteca/paquete de autenticación preferido, la autenticación App only probablemente sea la forma más sencilla de empezar y se puede establecer con un encabezado de solicitud simple. Para aprender cómo generar un Access Token App only, consulta [esta guía de App only](/resources/fundamentals/authentication#bearer-token-also-known-as-app-only).

#### Diferencias

**URLs de endpoints**

* Endpoints estándar v1.1:
    * GET https://api.x.com/1.1/lists/members.json
        (Consulta los miembros de una List especificada)
    * GET https://api.x.com/1.1/lists/mem
