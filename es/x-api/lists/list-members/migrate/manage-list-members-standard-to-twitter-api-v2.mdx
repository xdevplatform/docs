### Gestionar List members: Standard v1.1 comparado con X API v2

Si has estado trabajando con los endpoints estándar v1.1 [POST lists/members/create](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/post-lists-members-create) y [POST lists/members/destroy](https://developer.x.com/en/docs/twitter-api/v1/accounts-and-users/create-manage-lists/api-reference/post-lists-members-destroy), el objetivo de esta guía es ayudarte a entender las similitudes y diferencias entre los endpoints estándar v1.1 y de X API v2 para gestionar List members.

* **Similitudes**
    * Autenticación
* **Diferencias**
    * URLs de endpoints
    * Requisitos de App y Project
    * Métodos HTTP
    * Rate limits
    * Parámetros de solicitud

#### Similitudes

**Autenticación**

Ambas versiones del endpoint admiten [OAuth 1.0a User Context](https://developer.x.com/content/developer-twitter/resources/fundamentals/authentication). Por lo tanto, si anteriormente usabas uno de los endpoints estándar v1.1 de gestionar List members, puedes seguir utilizando el mismo método de autenticación si migras a la versión de X API v2.

#### Diferencias

**URLs de endpoints**

* Endpoints estándar v1.1:
    * POST https://api.x.com/1.1/lists/members/create.json
        (Añade un miembro a una List especificada)
    * POST https://api.x.com/1.1/lists/members/destroy.json
        (Elimina un miembro de una List especificada)
* Endpoint X API v2:
    * POST https://api.x.com/2/lists/:id/members
        (Añade un miembro a una List especificada)

    * DELETE https://api.x.com/2/lists/:id/members/:user_id
        (Elimina un miembro de una List especificada)

**Rate limits**

| **Standard v1.1** | **X API v2** |
| :--- | :--- |
| /1.1/lists/members/create.json<br/><br/>ninguno | /2/lists/:id/members<br/><br/>300 solicitudes por ventana de 15 minutos con OAuth 1.0a User Context<br/><br/>300 solicitudes por ventana de 15 minutos con OAuth 2.0 Authorization Code with PKCE |
| /1.1/lists/members/destroy.json<br/><br/>ninguno | /2/lists/:id/members/:user_id<br/><br/>300 solicitudes por ventana de 15 minutos con OAuth 1.0a User Context<br/><br/>300 solicitudes por ventana de 15 minutos con OAuth 2.0 Authorization Code with PKCE |

**Requisitos de App y Project**

Los endpoints de X API v2 requieren que uses credenciales de una [App de desarrollador](/resources/fundamentals/developer-apps) asociada a un [Project](/resources/fundamentals/developer-apps) al autenticar tus solicitudes. Todos los endpoints de X API v1.1 pueden usar credenciales de Apps o Apps relacionadas con un project.

**Parámetros de solicitud**

Los siguientes parámetros de solicitud estándar v1.1 tienen equivalentes en X API v2:

| **Standard v1.1** | **X API v2** |
| :--- | :--- |
| list_id | id  |
| slug | Sin equivalente |
| screen_name | Sin equivalente |
| owner\_screen\_name | Sin equivalente |
| owner_id | Sin equivalente |
