## Herramientas útiles

Antes de sumergirnos en algunos conceptos clave que te ayudarán a integrar este endpoint, te recomendamos familiarizarte con:

### Postman

Postman es una excelente herramienta que puedes usar para probar un endpoint. Cada solicitud de Postman incluye todos los parámetros de ruta y de cuerpo para ayudarte a entender rápidamente lo que está disponible. Para saber más sobre nuestras colecciones de Postman, visita nuestra página ["Usando Postman"](/tutorials/postman-getting-started).

### Ejemplos de código

¿Te interesa comenzar con este endpoint usando código en tu lenguaje de programación preferido? Tenemos varios ejemplos de código diferentes que puedes usar como punto de partida en nuestra [página de Github](https://github.com/xdevplatform/Twitter-API-v2-sample-code).

### Bibliotecas de terceros

Aprovecha alguna de las [bibliotecas de terceros](/tools-and-libraries) de nuestra comunidad para ayudarte a comenzar. Puedes encontrar una biblioteca que funcione con los endpoints v2 buscando la etiqueta de versión adecuada.

## Conceptos clave

### Autenticación

Todos los endpoints de X API v2 requieren que autentiques tus solicitudes con un conjunto de credenciales, también conocidas como claves y tokens. Puedes usar OAuth 1.0a User Context, App only o OAuth 2.0 Authorization Code with PKCE para autenticar tus solicitudes a este endpoint.

[OAuth 1.0a User Context](/resources/fundamentals/authentication#oauth-1-0a-2) significa que debes usar un conjunto de API Keys y Access Tokens de usuario para realizar una solicitud exitosa. Los access tokens deben estar asociados al usuario en cuyo nombre estás realizando la solicitud. Si deseas generar un conjunto de Access Tokens para otro usuario, este debe autorizar tu App mediante el [flujo OAuth de 3 pasos](/resources/fundamentals/authentication#obtaining-access-tokens-using-3-legged-oauth-flow).

Ten en cuenta que OAuth 1.0a puede ser difícil de usar. Si no estás familiarizado con este método de autenticación, te recomendamos usar una [biblioteca](/tools-and-libraries), una herramienta como Postman, o usar OAuth 2.0 o App only para autenticar tus solicitudes.

[OAuth 2.0 Authorization Code with PKCE](/resources/fundamentals/authentication#oauth-2-0-authorization-code-flow-with-pkce-2) permite un mayor control sobre el scope de una aplicación y los flujos de autorización entre múltiples dispositivos. OAuth 2.0 te permite elegir scopes específicos y detallados que te otorgan permisos específicos en nombre de un usuario.

Para habilitar OAuth 2.0 en tu App, debes activarlo en la configuración de autenticación de tu App, que se encuentra en la sección de configuración de la App en la Developer Console.

[App only](/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token) solo requiere que pases un [Access Token App only](/resources/fundamentals/authentication#app-only-authentication-and-oauth-2-0-bearer-token) con tu solicitud. Puedes generar un Access Token App only directamente dentro de una App de desarrollador, o generar uno usando el endpoint [POST oauth2/token](/resources/fundamentals/authentication#post-oauth2-token).

### Developer Console, Projects y Apps de desarrollador

Para obtener un conjunto de credenciales de autenticación que funcionen con los endpoints de X API v2, debes [registrarte para una cuenta de desarrollador](https://developer.x.com/en/portal/petition/essential/basic-info), configurar un [Project](/resources/fundamentals/developer-apps) dentro de esa cuenta y crear una [App de desarrollador](/resources/fundamentals/developer-apps) dentro de ese Project. Luego podrás encontrar tus claves y tokens dentro de tu App de desarrollador.

### Rate limits

Cada día, miles de desarrolladores realizan solicitudes a la X API. Para ayudar a gestionar el enorme volumen de estas solicitudes, se aplican [rate limits](https://developer.x.com/x-api/fundamentals/rate-limits) en cada endpoint que limitan el número de solicitudes que puedes realizar en nombre de tu app o de un usuario autenticado.

Este endpoint está limitado tanto a nivel de App como a nivel de usuario. El rate limit de la app significa que tú, el desarrollador, solo puedes realizar un número determinado de solicitudes a este endpoint durante un período determinado desde cualquier App dada (se asume mediante el uso de la API Key y la API Secret Key, o del Bearer Token). El rate limit de usuario significa que el usuario autenticado en cuyo nombre realizas la solicitud solo puede realizar una búsqueda de List Post un número determinado de veces en cualquier App de desarrollador.

La siguiente tabla muestra los rate limits de cada endpoint.

| Endpoint | Método HTTP | Rate limit |
| :--- | :--- | :--- |
| /2/lists/:id/tweets | GET | 900 solicitudes por 15 minutos |

### Fields y expansions

El endpoint GET de X API v2 permite a los usuarios seleccionar exactamente qué datos desean recibir de la API mediante un conjunto de herramientas llamadas `fields` y `expansions`. El parámetro `expansions` te permite expandir objetos referenciados en el payload. Por ejemplo, la búsqueda de List Posts te permite obtener los siguientes [expansions](/x-api/fundamentals/expansions):

* `author_id`

El parámetro `fields` te permite seleccionar exactamente qué [fields](/x-api/fundamentals/fields) dentro de los diferentes objetos de datos deseas recibir. Este endpoint entrega principalmente objetos Post. Por defecto, el objeto Post devuelve los fields `id` y `text`. Para recibir fields adicionales como `tweet.created_at` o `tweet.lang`, deberás solicitarlos específicamente mediante un parámetro fields.

Hemos añadido una guía sobre el uso conjunto de [fields y expansions](/x-api/fundamentals/data-dictionary/reference#how-to-use-fields-and-expansions) en nuestro [diccionario de datos de X API v2](/x-api/fundamentals/data-dictionary).

La siguiente tabla muestra los fields y expansions disponibles para el endpoint de lookup:

| Endpoint | Fields | Expansions |
| :--- | :--- | :--- |
| /2/lists/:id/tweets | `tweet.fields`, `user.fields` | `author_id` |

### Paginación

La búsqueda de List Posts puede devolver muchos datos. Para asegurarnos de devolver resultados consistentes y de alto rendimiento en cualquier momento, usamos paginación. La paginación es una característica en los endpoints de X API v2 que devuelven más resultados de los que se pueden devolver en una sola respuesta. Cuando eso sucede, los datos se devuelven en una serie de 'páginas'. Aprende más sobre cómo [paginar los resultados.](/x-api/fundamentals/pagination)
