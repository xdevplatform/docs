Postman es una excelente herramienta que puedes usar para probar un endpoint. Para saber más sobre nuestras colecciones de Postman, visita nuestra página ["Usando Postman"](/tutorials/postman-getting-started).

## Conceptos clave

### Autenticación

Todos los endpoints de X API v2 requieren que autentiques tus solicitudes con un conjunto de credenciales, también conocidas como claves y tokens. Puedes usar OAuth 1.0a User Context para autenticar tus solicitudes a este endpoint.

[OAuth 1.0a User Context](/resources/fundamentals/authentication), lo que significa que debes usar un conjunto de API Keys y Access Tokens de usuario para realizar una solicitud exitosa. Los access tokens deben estar asociados al usuario en cuyo nombre estás realizando la solicitud. Si deseas generar un conjunto de Access Tokens para otro usuario, este debe autorizar tu App mediante el [flujo OAuth de 3 pasos](https://developer.x.com/resources/fundamentals/authentication/obtaining-user-access-tokens).

Ten en cuenta que OAuth 1.0a puede ser difícil de usar. Si no estás familiarizado con este método de autenticación, te recomendamos usar una [biblioteca](/tools-and-libraries) o una herramienta como Postman.

### Developer Console, Projects y Apps de desarrollador

Para obtener un conjunto de credenciales de autenticación que funcionen con los endpoints de X API v2, debes [registrarte para una cuenta de desarrollador](https://developer.x.com/en/portal/petition/essential/basic-info), configurar un [Project](/resources/fundamentals/developer-apps) dentro de esa cuenta y crear una [App de desarrollador](/resources/fundamentals/developer-apps) dentro de ese Project. Luego podrás encontrar tus claves y tokens dentro de tu App de desarrollador.

### Rate limits

Cada día, miles de desarrolladores realizan solicitudes a la X API. Para ayudar a gestionar el enorme volumen de estas solicitudes, se aplican [rate limits](/x-api/fundamentals/rate-limits) en cada endpoint que limitan el número de solicitudes que puedes realizar en nombre de tu app o de un usuario autenticado.

Estos endpoints están limitados a nivel de usuario, lo que significa que el usuario autenticado en cuyo nombre realizas la solicitud solo puede llamar al endpoint un número determinado de veces en cualquier App de desarrollador.

La siguiente tabla muestra los rate limits de cada endpoint.

| Endpoint | Método HTTP | Rate limit |
| :--- | :--- | :--- |
| /2/users/:id/pinned_lists | POST | 50 solicitudes por 15 minutos |
| /2/users/:id/pinned_lists/:list_id | DELETE | 50 solicitudes por 15 minutos |
| /2/users/:id/pinned_lists | GET | 15 solicitudes por 15 minutos |

### Fields y expansions

El endpoint GET de X API v2 permite a los usuarios seleccionar exactamente qué datos desean recibir de la API mediante un conjunto de herramientas llamadas `fields` y `expansions`. El parámetro `expansions` te permite expandir objetos referenciados en el payload. Por ejemplo, la búsqueda de pinned Lists te permite obtener los siguientes [expansions](/x-api/fundamentals/expansions):

* `owner_id`

El parámetro `fields` te permite seleccionar exactamente qué [fields](/x-api/fundamentals/fields) dentro de los diferentes objetos de datos deseas recibir. Este endpoint entrega principalmente objetos de usuario. Por defecto, el objeto List devuelve los fields `id` y `name`. Para recibir fields adicionales como `list.created_at` o `list.description`, deberás solicitarlos específicamente mediante un parámetro fields.

Hemos añadido una guía sobre el uso conjunto de [fields y expansions](/x-api/fundamentals/data-dictionary/reference#how-to-use-fields-and-expansions) en nuestro [diccionario de datos de X API v2](/x-api/fundamentals/data-dictionary).

La siguiente tabla muestra los fields y expansions disponibles para el endpoint de lookup:

| Endpoint | Fields | Expansions |
| :--- | :--- | :--- |
| /2/users/:id/pinned_lists | `list.fields`, `user.fields` | `owner_id` |
