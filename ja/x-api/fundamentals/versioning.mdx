X API はエンドポイントパスにバージョン番号を使用し、安定性を確保しつつ進化を可能にします。バージョン管理戦略を理解することで、統合の計画を立て、最新の状態を保てます。

---

## 現在のバージョン

| Version | Status | Description |
|:--------|:-------|:------------|
| **v2** | 現行 | モダンなエンドポイント、柔軟な料金、すべての新機能 |
| **v1.1** | Legacy | 限定的なサポート、最小限の更新 |
| **Enterprise** | 利用可能 | 専任サポート付きの大容量アクセス |

<Tip>
すべての新規プロジェクトには **X API v2** を使用してください。ここに新機能がすべて追加されます。
</Tip>

## URL 内のバージョン

バージョン番号はエンドポイントパスに現れます。

```
https://api.x.com/2/tweets
                   ^
                   version
```

## 破壊的変更と非破壊的変更

### 破壊的変更（コードの更新が必要）

これらの変更はメジャーバージョンアップ時のみ発生します。

- エンドポイントの削除
- レスポンスフィールドの削除
- クエリパラメータの削除
- 新しい必須パラメータの追加
- フィールドのデータ型の変更
- フィールドやリソースの名称変更
- レスポンスコードやエラータイプの変更
- 認可スコープの変更

### 非破壊的変更（追加）

これらはバージョン変更なしにいつでも発生し得ます。

- 新しいエンドポイントの追加
- 新しいオプションパラメータの追加
- 新しいレスポンスフィールドの追加
- 新しい OAuth スコープの追加
- エラーメッセージテキストの変更
- プライバシー/セキュリティ上の理由でフィールドを null にする

## リリーススケジュール

| Type | Frequency | Notice |
|:-----|:----------|:-------|
| **メジャーバージョン** | 年 1 回以下 | 移行ガイドを提供 |
| **非破壊的変更** | 継続的 | changelog を更新 |
| **セキュリティパッチ** | 必要に応じて | 現行バージョンに適用される場合あり |

---

## 廃止ポリシー

新しいメジャーバージョンをリリースする際:

1. **廃止（Deprecation）**: 以前のバージョンが廃止予定としてマークされる
2. **サポート期間**: 廃止予定のバージョンは定められた期間動作を継続
3. **廃止（Retirement）**: 廃止予定のバージョンが削除される

### 定義

| Status | Meaning |
|:-------|:--------|
| **Active** | 新機能と修正で完全にサポート |
| **Deprecated** | 新機能なし、重大なバグのみ対応、使用を推奨しない |
| **Retired** | アクセス不可 |
