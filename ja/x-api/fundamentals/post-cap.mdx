X API v2 は **pay-per-usage**（従量課金制）の料金体系を採用しています。実際の API 消費量に基づいて課金され、アプリレベルで追跡されます。

---

## 請求の仕組み

| Concept | Description |
|:--------|:------------|
| **クレジット制** | クレジットを事前に購入し、API 使用に応じて減算 |
| **リクエスト単位の料金** | エンドポイントごとに異なるコスト |
| **リアルタイム追跡** | Developer Console で使用状況を監視 |

<Note>
Pay-per-usage プランは、月間 200 万 Post の読み取り上限が適用されます。より多くのボリュームが必要な場合は、[Enterprise プラン](/forms/enterprise-api-interest) を検討してください。
</Note>

## 重複排除

<Note>
**日次重複排除**: 同じ post が 1 日以内に複数のクエリから返された場合、請求では 1 回のみカウントされます。
</Note>

つまり、

- 同じ post を 1 日に複数回取得 = 1 回の課金
- 翌日に同じ post を再度取得 = 追加で 1 回の課金
- 同じリクエストで異なる post = それぞれ個別にカウント

## 使用状況のモニタリング

[Developer Console](https://console.x.com) で使用状況を追跡できます。

| Metric | Description |
|:-------|:------------|
| **合計使用量** | 請求期間中に取得された Post 数 |
| **エンドポイント別** | エンドポイントタイプ別の内訳 |
| **アプリ別** | 開発者アプリごとの使用量 |
| **コスト追跡** | リアルタイムのコスト計算 |
| **クレジット残高** | 前払いクレジットの残高 |

## 料金の詳細

エンドポイントや操作ごとの現在の料金については [Developer Console](https://console.x.com) を確認してください。

料金は以下によって変わることがあります。

- エンドポイントタイプ（search vs. lookup vs. stream）
- 操作（read vs. write）
- データの範囲（recent vs. full-archive）

## FAQ

<Accordion title="クレジットがなくなったらどうなりますか？">
クレジットを追加購入するまで、API リクエストは失敗します。中断を避けるため残高アラートを設定してください。
</Accordion>

<Accordion title="月額の最低料金はありますか？">
ありません。使った分だけ支払います。使用量ゼロで料金ゼロの月もあり得ます。
</Accordion>

<Accordion title="ストリーミングはどのように課金されますか？">
Filtered stream で配信されたユニークな post ごとに使用量にカウントされ、日次重複排除の対象になります。
</Accordion>

<Accordion title="失敗したリクエストもカウントされますか？">
いいえ。データを返して成功したレスポンスのみが課金対象です。
</Accordion>
