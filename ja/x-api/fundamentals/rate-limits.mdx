Rate limits は各エンドポイントに対して行えるリクエスト数を制御します。上限を超えると、ウィンドウがリセットされるまで 429 エラーが返されます。

---

## Rate limit の仕組み

| Concept | Description |
|:--------|:------------|
| **タイムウィンドウ** | 通常 15 分または 24 時間 |
| **Per-user limits** | OAuth 1.0a または OAuth 2.0 user token で適用 |
| **Per-app limits** | Bearer Token（app-only）で適用 |
| **Per-endpoint** | 各エンドポイントに独自の上限 |

---

## 上限の確認

レスポンスヘッダーで現在の rate limit ステータスを確認できます。

```
x-rate-limit-limit: 900
x-rate-limit-remaining: 847
x-rate-limit-reset: 1705420800
```

| Header | Description |
|:-------|:------------|
| `x-rate-limit-limit` | 許可される最大リクエスト数 |
| `x-rate-limit-remaining` | ウィンドウ内での残りリクエスト数 |
| `x-rate-limit-reset` | ウィンドウがリセットされる Unix タイムスタンプ |

## Rate limit の処理

rate limit に達すると、429 レスポンスが返されます。

```json
{
  "errors": [{
    "code": 88,
    "message": "Rate limit exceeded"
  }]
}
```

### 復旧戦略

1. `x-rate-limit-reset` でウィンドウがリセットされる時刻を確認
2. その時刻まで待機してから再試行
3. 必要に応じて指数バックオフを使用

```python title="Example" lines wrap icon="python"
import time

def make_request_with_backoff(url, headers):
    response = requests.get(url, headers=headers)
    
    if response.status_code == 429:
        reset_time = int(response.headers.get('x-rate-limit-reset', 0))
        wait_time = max(reset_time - time.time(), 60)
        time.sleep(wait_time)
        return make_request_with_backoff(url, headers)
    
    return response
```

## Rate limit と請求

Rate limit と請求は別物です。

| Concept | Purpose |
|:--------|:--------|
| **Rate limits** | システム安定性のためリクエスト頻度を制御 |
| **Usage billing** | 取得したデータに対して課金（従量課金） |

Rate limit の範囲内でも使用料が発生する場合があり、逆に追加コストなしで rate limit に達する場合もあります。
