Batch Compliance エンドポイントを使用すると、Post ID またはユーザー ID のデータセットをアップロードし、それらの現在のコンプライアンス状態を受け取れます。これを利用して、削除された Post、凍結されたアカウント、その他のコンプライアンスイベントを特定できます。

## 仕組み

1. **ジョブを作成** — タイプ (Post またはユーザー) とアップロード URL を指定
2. **ID をアップロード** — 提供された URL にデータセットをアップロード
3. **処理を待つ** — ジョブは非同期で処理されます
4. **結果をダウンロード** — 各 ID のコンプライアンス状態を取得

---

## エンドポイント

| Method | Endpoint | 説明 |
|:-------|:---------|:------------|
| POST | [`/2/compliance/jobs`](/x-api/compliance/create-compliance-job) | 新規コンプライアンスジョブを作成 |
| GET | [`/2/compliance/jobs/:id`](/x-api/compliance/get-compliance-job-by-id) | ジョブのステータスを取得 |
| GET | [`/2/compliance/jobs`](/x-api/compliance/get-compliance-jobs) | すべてのジョブを一覧表示 |

---

## ジョブタイプ

| Type | 説明 |
|:-----|:------------|
| `tweets` | Post のコンプライアンス状態を確認 |
| `users` | ユーザーのコンプライアンス状態を確認 |

---

## コンプライアンスイベント

### Post イベント

| Event | 説明 |
|:------|:------------|
| `deleted` | ユーザーによって Post が削除された |
| `bounced` | Post がコンプライアンスチェックに失敗した |
| `protected` | アカウントが非公開になった |
| `suspended` | アカウントが凍結された |
| `scrub_geo` | 位置情報データが削除された |

### ユーザーイベント

| Event | 説明 |
|:------|:------------|
| `deleted` | アカウントが削除された |
| `suspended` | アカウントが凍結された |
| `protected` | アカウントが非公開になった |
| `deactivated` | アカウントが無効化された |

---

## 例: ジョブの作成

```bash
curl -X POST "https://api.x.com/2/compliance/jobs" \
  -H "Authorization: Bearer $BEARER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "tweets",
    "name": "my-compliance-job"
  }'
```
