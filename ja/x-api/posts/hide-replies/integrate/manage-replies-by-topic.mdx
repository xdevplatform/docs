### トピック別に返信を管理する

hide replies エンドポイントを通じて、人やブランドが会話をトピック上に保てるように支援する統合を構築できます。このページでは、hide replies と [recent search](/x-api/posts/recent-search) エンドポイントを使って会話を管理する方法を示します。

Recent search には会話とその返信を取得する機能があり、Post ペイロードには言語を問わず各投稿の文脈とトピックを理解するための [Post annotations](/x-api/fundamentals/post-annotations) が返されます。

アプリのフローには、会話を表示および管理するコントロールを備えます:

1.  ユーザーの投稿を読み、返信を管理する許可をユーザーにリクエストします。
2.  投稿 URL から最近の会話を取得し、その会話が認証ユーザーによって開始されたものであることを確認します。
3.  recent search エンドポイントを呼び出して、会話内の各投稿を表示します。リクエストには conversation ID の検索クエリと annotation expansion を含め、X の投稿解釈に基づいて投稿がスポーツ関連かどうかを判定します。
4.  ユーザーが選択したときに Hide replies を呼び出して返信を非表示にします。ユーザーが常に主導権を持てるよう、このアクションを取り消す方法も提供します。

5.  長い会話には、[検索結果のページネーション](/x-api/posts/search/integrate/paginate)コントロールを提供します。


#### ユーザー(と利用状況)向けに最適化する

ユーザーが実行しようとする任意のアクションを主導できる方法でフローを設計できます。この原則を念頭に置くことで、投稿の消費を最適化する統合も構築できます。

1.  認証ユーザーは自分が開始した会話のみ管理できるため、そうでない場合はフローを早期に終了する必要があります。
    * 最初に Post lookup リクエストを行います。投稿 URL が無効か、認証ユーザーが会話を開始していない場合は早期にフローを終了します。
    * こうすることで、認証ユーザーが会話をモデレートできない場合、アプリは recent search リクエストを行わずに済みます。
2.  同じリクエストで [user と Post フィールド](/x-api/fundamentals/fields)をリクエストして、リクエストを分けずに済むようにします。このアプローチはアプリのパフォーマンス向上にも役立ちます。
3.  必要なとき以外はリクエストを行わないようにします。このアプリは、返信の非表示ステータスをユーザーのブラウザにキャッシュします。これは大きな会話で、ユーザーがモデレーションを後で再開したい場合に役立ち、返信の非表示・再表示のリクエスト最適化にも寄与します。
