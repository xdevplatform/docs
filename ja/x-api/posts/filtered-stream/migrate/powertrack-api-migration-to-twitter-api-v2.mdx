### PowerTrack API から X API v2 filtered stream への移行

この移行ガイドを使用して、[PowerTrack API](/x-api/enterprise-gnip-2.0/powertrack-api) と X API v2 [filtered stream](/x-api/posts/filtered-stream) の類似点と相違点を理解し、既存の PowerTrack API 連携を v2 filtered stream に移行しやすくします。

* **類似点**
    * ストリーミング配信方式
    * 統合プロセス
    * ルール管理エンドポイントを別に持つ永続ストリーム接続
    * ルール構文
    * ルール演算子(例外あり)
    * ルールマッチングロジック
    * 投稿の編集履歴とメタデータのサポート
* **相違点**
    * ルール長
    * ルール数
    * エンドポイント URL
    * アクセスに関する App と Project の要件
    * 認証方式
    * リクエストパラメーター
    * 使用量トラッキング
    * 複数ストリーム、冗長接続、backfill および Replay リカバリ
    * リクエストパラメーターとレスポンス形式
    * レスポンス JSON データ構造

#### 類似点

**ストリーミング配信方式**

PowerTrack と X API v2 filtered stream はどちらもストリーミングデータ配信を使用します。クライアントはエンドポイントへのオープン接続を確立し、非常に長寿命の HTTP リクエストを維持し、サーバーからのレスポンスをリアルタイムで逐次パースする必要があります。PowerTrack と X API v2 filtered stream はどちらも、ストリーム上に存在するルールに一致する公開投稿をリアルタイムでフィルタリングし、接続が有効であることを示すために改行文字 (\\r\\n) を keep-alive シグナルとして使用します。PowerTrack と X API v2 filtered stream のエンドポイント接続はどちらもリアルタイムでデータを配信するため、接続クライアントは迅速に読み取る必要があります。
