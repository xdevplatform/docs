### 返された投稿と関連ルールを対応付ける

Filtered stream エンドポイントでは、単一の接続に複数のルールを設定できます。ストリームで投稿を受信し始める前に、興味のある投稿の種類を指定するルールを作成する必要があります。

ユーザー属性、位置情報、言語などさまざまな属性で投稿にマッチするようにルールを指定する際、そのルールを高いレベルで区別するタグを付けることができます。特に多くのルールを設定する場合、タグはルールに文脈を与える良い方法です。フィルタリングルールが、どの投稿アクティビティが接続を通じて送信されるかを決定します。

異なる種類の投稿を捉えるために新しいフィルタリングルールを追加したり、既存のルールを削除したりする必要がある場合、アプリは [POST tweets/search/stream/rules](/x-api/stream/update-stream-rules) エンドポイントにリクエストを送信できます。そのリクエストが送信されると、フィルタリングルールは自動的に変更され、再接続することなくデータストリームに反映されます。ほとんどのルール追加は約 20 秒以内に反映されます。可能性は低いですが、外的要因(例: ネットワーク接続性)によっては、一致する投稿の受信が始まるまでにさらに時間がかかる場合があります。ルール一覧エンドポイントでルールが見つからない場合、ルール作成リクエストが成功したかどうかを、ログでエラーメッセージを確認して検証してください。


#### Matching rules

アクティビティが Filtered stream 接続を通じて配信されるとき、`matching_rules` 配列には、配信された投稿に一致したフィルターのリストが含まれます。

投稿ペイロードには、その投稿の配信を引き起こしたルールの ID とタグを含む追加の文字列メタデータがあります。単一の投稿に複数のルールが一致する場合、そのアクティビティは 1 回だけ配信され、一致した各ルールがこのメタデータに含まれます。matching rules は、特定の投稿を特定のルールに簡単に関連付けられる仕組みを提供し、これは多数の異なるルールを持っている場合に特に役立ちます。この方式でデータが単一のストリームを通じて配信されるため、一意の ID とタグを持たせておくことがマッチングにおいて不可欠です。

**投稿ペイロードでの "matching_rules" 配列の例:**


```json
"matching_rules": [
    {
      "id": "1166916266197536768",
      "tag": "test-rule-tag-00000"
    },
    {
      "id": "1166916266197536769",
      "tag": "test-rule-tag-12345"
    }
  ]
```

#### エンベディングルールの一致

投稿が `embedding:` 演算子を含むルールに一致した場合、そのルールの `matching_rules` エントリには 2 つの追加フィールドが含まれます(エンベディングベースの一致でのみ存在します):

| Field | Description |
|:------|:------------|
| `embedding_similarity` | ルールのクエリと一致した投稿とのコサイン類似度スコア (0.0–1.0)。 |
| `embedding_threshold` | 適用されたしきい値(指定した値、またはデフォルトの `0.3`)。 |

エンベディング一致のペイロード抜粋の例:

```json title="レスポンス例" lines wrap icon="/icons/xds/icon-brackets.svg"
{
  "data": {
    "id": "1784600000000000001",
    "text": "The new carbon tax proposal could reshape how industries approach emissions..."
  },
  "matching_rules": [
    {
      "id": "1784567890123456789",
      "tag": "climate-semantic",
      "embedding_similarity": 0.4523,
      "embedding_threshold": 0.4
    }
  ]
}
```

キーワード、`from:`、`has:` などのエンベディング以外のルールでは、`matching_rules` エントリは `id` と `tag` のみを含みます。

#### ルールタグ

作成時に、各フィルタリングルールにはタグを付けることができます。ルールタグは特別な意味を持たず、ルールと共に持ち回される不透明な文字列として扱われます。返されるアクティビティの `matching_rules` メタデータに含まれ、高いレベルでルールを識別しやすくすることを目的としています。

タグはフィルタリングルールを論理的にグループ化する簡単な方法を提供します。たとえば、特定のルールに対して一意の ID をタグとして生成し、アプリが処理するアクティビティ内でその ID を参照して、結果を特定の顧客・キャンペーン・カテゴリ・関連グループと関連付けられます。

既存のルールでタグは更新できず、ルール作成時にのみ含められる点に注意してください。タグを「更新」または「リネーム」するには、まずそのルールを削除し、目的のタグで再作成する必要があります。最善の解決策は、システム側で自身のアプリ内のさまざまなデータポイントと関連付けられる一意の識別子をタグとして使用することです。これによりルールセットを何も変更する必要がなくなります。
